# max-txt2img

## Codex 실행 환경

- 이 스킬은 이미지 생성 모델로 완성된 래스터 인포그래픽을 만드는 방식입니다.
  `flat vector`는 시각적 스타일을 뜻하며 SVG 파일 출력을 뜻하지 않습니다.
- 이미지를 생성하거나 수정할 때는 설치된 `imagegen` 스킬을 읽고, 현재 도구
  목록에 있는 내장 이미지 생성 도구를 사용합니다. Codex에서는
  `image_gen.imagegen`으로 제공되며 도구 이름은 실행 환경에 따라 달라질 수 있습니다.
  화면비, 스타일, 정확한 라벨은 프롬프트로 전달합니다. 도구 스키마에 없는
  모델명, 해상도, 품질 또는 저장 경로 인수를 만들어 넣지 않습니다.
- 로컬 이미지를 수정할 때는 먼저 `view_image`로 확인하고 현재 도구 스키마가
  지원하는 참조 이미지 방식으로 전달합니다. 유지할 구조와 변경할 부분을
  명시합니다. 재생성 시 프롬프트가 같아도 픽셀까지 같은 결과는 보장하지 않습니다.
- 생성 도구가 반환한 이미지를 표시하고 실제 결과를 검토합니다. 프로젝트에서
  사용하는 이미지는 반환된 실제 파일을 프로젝트의 지정 위치에 복사합니다.
  저장 위치나 생성 성공 여부를 추측하지 않습니다.
- 명백한 오류를 고치기 위한 재생성은 기본적으로 1회까지 수행합니다. 기존에
  승인된 도구 사용 범위 안에서는 다시 확인하지 않습니다. 별도 유료 API나
  CLI로 전환해야 하는 경우에는 자동으로 전환하지 않고, 검증된 프롬프트와
  현재 제약을 제공합니다. 해당 전환을 사용자가 요청한 경우에만 진행합니다.
- `dev-log-rich-post-workspace-v2`에서 호출되면 제작 전에
  [v2 인포그래픽 연결 규칙](../dev-log-rich-post-workspace-v2/references/infographic-v2.md)을
  읽습니다. 해당 문서는 블로그의 배치, 저장, 검수 규칙을 정합니다.
  일반 문서 도식화에서는 블로그 워크플로를 실행하지 않습니다.


문서나 특정 단락의 핵심 내용을 분석하고, 이를 직관적인 다이어그램 또는 인포그래픽 이미지로 변환한다.

다음 파이프라인을 따른다.

`문서 읽기 → 핵심 구조화 → 시각화 방식 선택 → 이미지 프롬프트 작성 → 검증 → 이미지 생성 → 결과 검토`

## 목표

사용자가 원문을 다시 읽지 않아도 생성된 이미지를 보고 약 10초 안에 다음을 파악할 수 있게 한다.

- 문서의 핵심 메시지
- 주요 단계 또는 구성요소
- 구성요소 사이의 순서·계층·인과·순환 관계
- 가장 중요하게 강조해야 할 내용

예쁜 장식 이미지보다 정확하고 이해하기 쉬운 정보 구조를 우선한다.

## 입력

다음 입력을 처리한다.

- 사용자가 붙여넣은 텍스트
- 업로드한 문서 또는 파일
- 접근 가능한 웹페이지
- 현재 대화에서 언급된 문서
- 기존에 작성한 이미지 생성 프롬프트
- 기존 생성 이미지에 대한 수정 요청

사용자가 선택적으로 지정할 수 있는 항목:

- 분석 범위: 전체 문서 또는 특정 섹션
- 화면비: 기본값 `16:9`
- 라벨 언어: 기본값은 사용자 요청 언어
- 시각적 분위기와 색상
- 강조할 개념
- 원하는 도식 유형
- 기존 이미지에서 유지하거나 변경할 부분

필수 정보가 없을 때만 짧게 질문한다. 합리적인 기본값을 적용할 수 있다면 질문하지 말고 진행한다.

## 작업 분기

### 새 이미지 요청

사용자가 문서나 텍스트를 도식화해 달라고 하면 전체 파이프라인을 수행한다.

### 프롬프트만 요청

사용자가 이미지 생성용 프롬프트만 요청하면 문서를 분석하고 검증된 영문 프롬프트까지 작성한다. 이미지는 생성하지 않는다.

### 이미지만 다시 생성

사용자가 “같은 프롬프트로 이미지만 다시 만들어줘”라고 하면 기존 프롬프트를 그대로 재사용하여 이미지를 생성한다.

단, 명백한 오탈자나 이미지 생성 도구에서 처리할 수 없는 표현이 있으면 의미를 바꾸지 않는 범위에서 최소한으로 수정하고 수정 사실을 알린다.

### 기존 이미지 수정

사용자가 기존 이미지의 특정 부분을 바꾸라고 하면 전체 프롬프트를 처음부터 새로 설계하지 않는다. 유지할 요소와 변경할 요소를 구분한 뒤 최소한의 프롬프트 수정으로 재생성한다.

## 실행 절차

### 1. 대상 읽기

대상 문서나 텍스트를 실제로 읽는다.

문서 전체가 아니라 특정 섹션이 지정되었다면 해당 범위를 우선하되, 해석에 꼭 필요한 주변 문맥만 추가로 확인한다.

문서를 읽지 않은 상태에서 제목이나 일반 지식만으로 이미지를 만들지 않는다.

### 2. 핵심 구조화

내부적으로 다음 항목을 정리한다.

- 핵심 메시지 1개
- 주요 단계 또는 구성요소
- 각 요소의 짧은 명칭
- 각 요소를 설명하는 핵심 키워드 2~3개
- 요소 사이의 관계
- 시작점과 종료점
- 강조할 전환점, 조건 또는 체크포인트
- 이미지에서 생략해도 되는 세부 내용

사용자에게 장황한 사고 과정이나 비공개 추론을 노출하지 않는다. 필요한 경우 최종 구조 요약만 간결하게 제공한다.

### 3. 시각화 방식 선택

내용의 관계에 따라 가장 적합한 도식 유형을 선택한다.

- 시간 순서 또는 업무 절차: 좌→우 프로세스 플로우
- 성장·성숙도·발전 단계: 상승 계단 또는 로드맵
- 반복·개선·피드백: 순환 루프
- 상위·하위 개념: 계층 트리 또는 피라미드
- 중심 개념과 주변 요소: 허브 앤드 스포크
- 두 대상의 차이: 좌우 비교
- 원인에서 결과로 이어지는 구조: 인과관계 플로우
- 시스템 구성요소와 연결: 아키텍처 다이어그램

문서 구조에 맞지 않는 도식 유형을 억지로 사용하지 않는다.

### 4. 이미지 생성 프롬프트 작성

이미지 생성 도구가 잘 이해할 수 있도록 상세한 영문 프롬프트를 작성한다.

프롬프트에는 다음 내용을 포함한다.

1. 이미지의 목적과 주제
2. 선택한 도식 유형과 전체 배치
3. 단계 또는 구성요소의 정확한 개수
4. 각 요소의 라벨
5. 각 요소를 상징하는 아이콘 모티프
6. 요소 사이의 연결 방식
7. 강조 요소와 시각적 내러티브
8. 색상 흐름
9. 스타일
10. 화면비
11. 금지 요소
12. 이미지에 표시해도 되는 텍스트 목록

기본 스타일:

- minimal
- professional
- corporate-friendly
- flat vector infographic
- soft gradients
- generous white space
- balanced composition
- high readability
- clean typography

기본 금지 요소:

- no clutter
- no photorealism
- no unnecessary 3D effects
- no brand logos
- no decorative text
- no extra labels
- no illegible small text
- no invented facts
- no misspelled labels

### 5. 프롬프트 검증

이미지를 생성하기 전에 프롬프트를 점검한다.

- 원문의 핵심 메시지가 반영되었는가?
- 단계와 구성요소의 수가 정확한가?
- 구성요소 사이의 관계가 정확한가?
- 원문에 없는 정보를 만들어내지 않았는가?
- 라벨이 지나치게 많지 않은가?
- 각 단계의 키워드가 2~3개 이내인가?
- 도식 유형이 내용에 적합한가?
- 사용자가 약 10초 안에 흐름을 파악할 수 있는가?
- 화면비와 라벨 언어가 요청에 맞는가?

기준을 충족하지 못하면 프롬프트를 보정한 뒤 이미지를 생성한다.

### 6. 이미지 생성

현재 환경에서 사용할 수 있는 내장 이미지 생성 기능으로 이미지를 생성한다.

이미지 생성 기능을 직접 사용할 수 없는 환경이라면 다음을 제공한다.

- 완성된 영문 이미지 프롬프트
- 권장 화면비
- 권장 이미지 생성 설정
- 사용자가 이미지 생성 기능이 있는 대화에서 그대로 사용할 수 있는 실행 문장

이미지를 생성할 수 없는데 생성했다고 말하지 않는다.

### 7. 결과 검토

생성된 이미지를 확인할 수 있다면 다음 기준으로 점검한다.

- 핵심 단계와 구성요소가 빠지지 않았는가?
- 라벨의 철자와 내용이 정확한가?
- 단계의 순서와 연결 방향이 정확한가?
- 텍스트가 잘리거나 깨지지 않았는가?
- 이미지가 과밀하지 않은가?
- 문서의 핵심을 한눈에 이해할 수 있는가?
- 요청한 화면비와 스타일을 따르는가?
- 불필요한 로고, 장식, 실사 또는 3D 요소가 없는가?

명백한 오류가 있으면 프롬프트를 수정하여 1회 재생성한다.

이미 승인된 사용 범위를 넘는 별도 비용이나 새로운 권한이 필요한 경우에만 재생성 전에 확인한다.

## 텍스트와 라벨 규칙

- 이미지 라벨은 기본적으로 사용자의 언어를 따른다.
- 이미지 생성 도구가 비영어 라벨을 안정적으로 표현하지 못하면 사용자에게 다음 중 적합한 방식을 제안한다.
  - 영문 라벨로 생성
  - 번호만 이미지에 표시하고 설명을 별도로 제공
  - 짧은 핵심 명사만 이미지에 표시
- 사용자가 지정한 언어나 필수 라벨을 임의로 영문·번호로 바꾸지 않습니다.
  단순화할 때도 핵심 의미와 의사결정에 필요한 조건을 보존합니다.
- 라벨은 짧고 명확하게 작성한다.
- 문장 전체를 이미지에 넣지 않는다.
- 단계당 핵심 키워드는 최대 3개로 제한한다.
- 원문에 있는 고유명사, 수치, 단계명은 임의로 바꾸지 않는다.
- 이미지에 표시하도록 지정한 텍스트 외의 문구를 추가하지 않도록 프롬프트에 명시한다.

## 기본 출력 형식

결과를 다음 순서로 제공한다.

1. 생성된 이미지
2. 핵심 구조 요약 1~3줄
3. 사용한 최종 영문 프롬프트
4. 검토 결과 또는 재생성 여부

최종 프롬프트는 사용자가 쉽게 복사하고 수정할 수 있도록 코드 블록에 넣는다.

예시:

- **핵심 구조:** 5단계 성숙도 모델을 상승 계단으로 표현했습니다. 개인에서 팀, 제품과 사용자로 확장되는 범위를 색상 변화와 화살표로 강조했습니다.
- **이미지:** 생성된 이미지
- **사용한 프롬프트:** 영문 프롬프트 코드 블록
- **검토:** 단계 수, 순서, 라벨 및 화면비 확인 완료

## 품질 기준

다음 기준을 만족하는 결과를 목표로 한다.

- 핵심 반영: 주요 단계·구성요소·관계가 정확하게 표현됨
- 사실 정확성: 원문에 없는 정보가 추가되지 않음
- 라벨 정확도: 오탈자와 왜곡 없음
- 가독성: 한눈에 흐름을 파악할 수 있음
- 정보 밀도: 텍스트와 장식이 과도하지 않음
- 스타일 적합성: 요청한 스타일과 화면비 준수
- 재사용성: 최종 프롬프트를 사용자가 다시 실행하거나 수정할 수 있음

## 흔한 실패와 대응

### 문서를 읽지 않고 일반적인 이미지를 생성함

반드시 대상 내용을 먼저 읽고 핵심 구조를 추출한다.

### 이미지에 너무 많은 텍스트를 넣음

문장을 제거하고 짧은 라벨과 단계당 2~3개의 키워드만 남긴다.

### 라벨이 깨지거나 오타가 발생함

이미지 생성 후 라벨을 확인한다. 오류가 있으면 의미를 보존하면서 불필요한 라벨을 줄이고 재생성한다. 영문·번호 기반 표현으로 전환할 때는 사용자가 해당 변경을 허용했는지 확인한다.

### 예쁘지만 의미가 불분명함

장식보다 단계, 관계, 방향, 계층을 명확하게 표현한다.

### 원문에 없는 요소를 추가함

시각적 장치는 추가할 수 있지만 새로운 사실, 단계, 수치, 주장은 추가하지 않는다.

### 첫 번째 결과를 무조건 확정함

명백한 오류가 있거나 품질 기준을 충족하지 못하면 프롬프트를 보정하여 재생성한다.

## 호출 예시

- “이 문서를 핵심 위주로 도식화 이미지로 만들어줘.”
- “이 단락을 좌에서 우로 흐르는 프로세스 다이어그램으로 만들어줘.”
- “이 성숙도 모델을 상승 계단형 인포그래픽으로 그려줘.”
- “이 시스템 설명을 아키텍처 다이어그램으로 만들어줘.”
- “이미지는 만들지 말고 이미지 생성용 영문 프롬프트만 작성해줘.”
- “방금 사용한 프롬프트로 이미지만 다시 생성해줘.”
- “구조는 유지하고 색상을 파란색 계열로 바꿔서 다시 만들어줘.”

## 동작 원칙

- 사실의 정확성을 시각적 화려함보다 우선한다.
- 사용자가 지정하지 않은 세부 스타일은 합리적인 기본값을 적용한다.
- 불필요한 확인 질문을 줄이고 실행 가능한 경우 바로 진행한다.
- 사용 가능한 도구와 기능을 실제로 확인한 뒤 사용한다.
- 접근할 수 없는 문서나 URL의 내용을 읽었다고 가정하지 않는다.
- 이미지 생성이 불가능한 환경에서는 검증된 프롬프트를 제공한다.
- 사용자가 요청하지 않은 파일 업로드, 외부 게시 또는 공유를 수행하지 않는다.
- 최종 이미지와 함께 사용한 프롬프트를 항상 제공한다.
