지난 글에서 Sonnet 5와 Opus 4.8을 비교했습니다. 이번에는 그 위 체급입니다. Anthropic이 2026년 6월 9일 출시한 Claude Fable 5는 Opus 위에 새로 생긴 'Mythos 클래스'의 첫 일반 공개 모델입니다. 출시 3일 만에 미국 정부 수출통제로 전면 중단됐다가 7월 1일 복구되는 소동까지 겪었습니다. 

 

1. Fable 5는 무엇인가

정의. Fable 5는 Anthropic의 새 최상위 티어 'Mythos 클래스'를 일반 사용자가 쓸 수 있게 만든 모델입니다. 기존 Haiku → Sonnet → Opus 3단 사다리 위에 네 번째 단이 생겼습니다.

구조. Fable 5와 Mythos 5는 동일한 가중치를 공유합니다. 차이는 추론 시점에 붙는 안전 계층 하나입니다.

  • Fable 5: 사이버보안, 생물·화학, 모델 증류(distillation) 영역에 안전 분류기를 적용한 일반 공개 버전입니다.
  • Mythos 5: 해당 안전장치를 일부 해제한 버전입니다. Project Glasswing을 통해 승인된 방어 보안 조직에만 제공합니다.

작동 원리. Fable 5의 분류기가 요청을 차단하면 모델이 거부로 끝나지 않고 Opus 4.8로 폴백해 답을 생성합니다. Anthropic은 이 전환이 전체 세션의 5% 미만에서 발생하고, 사용자에게 통지되며, 폴백 응답에는 Fable 요율이 아닌 Opus 요율이 청구된다고 밝혔습니다. API에서는 거부가 에러가 아니라 HTTP 200에 stop_reason: "refusal"로 돌아오고, fallbacks 파라미터(베타)로 서버 측 자동 재시도를 설정할 수 있습니다.

이 구조가 이번 비교의 핵심 전제입니다. Fable 5를 쓴다는 것은 사실상 "Fable 5 + Opus 4.8 폴백" 조합을 쓴다는 뜻입니다. 두 모델은 양자택일이 아니라 한 쌍입니다.

3. 벤치마크: 격차는 난이도에 비례

Anthropic 공식 발표와 독립 평가를 종합한 수치입니다.

해석 시 유의점은 세 가지입니다.

첫째, 격차는 균일하지 않습니다. 코딩, 특히 장기 에이전틱 작업에서 가장 크고, 지식노동(GDPval-AA)에서는 42 Elo 수준으로 좁습니다. Anthropic 스스로 "작업이 길고 복잡할수록 Fable 5의 우위가 커진다"고 프레이밍했습니다.

둘째, 하네스 변경이 수치에 섞여 있습니다. Opus 4.8의 Terminal-Bench 점수는 하네스를 Terminus-2에서 mini-SWE-agent로 바꾸면서 74.6에서 82.7로 올랐습니다. 과거 기사와 단순 비교하면 오독하게 됩니다.

셋째, 안전 분류기가 벤치마크 점수를 깎습니다. Terminal-Bench에서 Fable 5는 시행의 20.9%에서 안전 거부에 걸려 84.3을 기록했습니다. 동일 가중치인 Mythos 5는 88.0입니다. 즉 Fable 5의 순수 능력은 측정치보다 높고, 그 차이는 안전 계층의 비용입니다.

대부분의 수치가 Anthropic 자체 발표 기반이라는 점도 남습니다. 방향성 지표로 취급하고, 자기 워크로드에서 검증한 뒤 전환하는 것이 맞습니다.

4. 실전 테스트

단일 프롬프트 앱 빌드 대결: 동일 프롬프트, 동일 디자인 요구사항으로 헬스 대시보드 앱을 빌드시켰습니다. API 실시간 연동, 건강 추적, 문서 편집, 캘린더까지 포함한 과제입니다.

토큰 사용량 약 50,000 약 2배
안정성 조용히 실행, 완주 에러 발생, 크래시 반복
디자인 시스템 브랜딩·타이포·컬러·UI 컴포넌트를 일관되게 생성 장황한 중간 피드백, 결과물 응집력 부족

주목할 지점은 속도의 역전입니다. Fable 5는 응답 하나하나는 느린 모델인데, 전체 작업은 절반 시간에 절반 토큰으로 끝냈습니다. 에러와 재시도가 없으면 총비용이 내려간다는 실증 사례입니다.

 

반대 증거: 격차가 사라지는 경우

The New Stack은 pandas 실제 이슈(#32265) 기반 추론 테스트와 코딩 테스트를 동일 프롬프트로 돌렸는데, 두 모델의 결과가 사실상 수렴했습니다. 청구서만 달랐습니다. 필자의 추정은 두 모델이 같은 회사, 같은 훈련 철학, 겹치는 데이터로 만들어진 형제 모델이라 잘 정의된 과제에서는 같은 패턴에 도달한다는 것입니다.

같은 테스트에서 또 하나 중요한 관찰이 나왔습니다. Claude Code에서 Fable 5로 작업하던 중 안전 분류기에 걸려 세션이 Opus 4.8로 자동 전환됐고, 최종 결과물의 어느 부분을 어느 모델이 작성했는지 구분할 수 없었습니다. Fable 5 도입 시 실제로 마주하게 될 운영 특성입니다.

종합. 잘 스코프된 단일 과제에서는 두 모델이 수렴합니다. 격차는 과제가 길어지고, 파일이 많아지고, 모델이 스스로 계획-실행-검증을 반복해야 할 때 벌어집니다. 벤치마크 패턴과 실전 테스트 패턴이 일치합니다.

실효 비용은 두 방향으로 갈립니다.

비싸지는 경우. Fable 5는 복잡한 문제에서 사고 토큰을 더 쓰는 경향이 있습니다. 실제 과제 기준 실효 비용이 단가 차이(2배)를 넘어 3~5배가 된다는 관측이 있습니다. 단일 함수 리팩토링이나 짧은 질의처럼 Opus로 충분한 작업을 Fable에 주면 순수 낭비입니다.

싸지는 경우. AI Foundations 테스트처럼 Opus가 에러-재시도 루프에 빠지는 작업에서는 Fable 5가 절반 토큰으로 완주했습니다. 재시도 비용까지 합산하면 총비용이 역전됩니다.

결론은 단가표가 아니라 완주율이 비용을 결정한다는 것입니다. 판단 기준을 이렇게 잡을 수 있습니다: Opus 4.8이 한 번에 완료하는 작업이면 Opus가 쌉니다. Opus가 두 번 이상 실패하는 작업이면 Fable이 쌉니다.

 

6. 속도: 지연시간과 처리량을 분리해서 봐야 한다

  • 응답 지연(latency): Opus 4.8이 코딩 과제에서 3~15초 수준일 때, Fable 5는 60초에서 수 분이 걸립니다. 멀티스텝 비동기 실행은 30분에서 수 시간까지 갑니다.
  • 총 처리 시간(throughput): 위 4-1 테스트처럼 복잡한 과제 전체로 보면 Fable 5가 절반 시간에 끝낼 수 있습니다.

이것은 버그가 아니라 설계 의도입니다. Fable 5는 확장된 사고, 도구 실행, 자체 검증, 반복 수정을 거친 뒤 응답하는 위임형 모델입니다. 대화형으로 쓰면 스피너만 보게 되고, 통째로 맡기는 방식으로 쓰면 설계 의도대로 작동합니다. 실무 팁 하나를 덧붙이면, Fable 5 작업은 서로 다른 문제 3~4개를 병렬로 걸어두고 첫 결과를 리뷰하는 동안 나머지가 완료되게 운용하면 대기 시간이 사라집니다.

 

7. 도입 전 확인할 제약

데이터 보존. Fable 5는 안전 분류기 운영을 위해 프롬프트·출력의 30일 보존이 의무입니다(학습에는 사용하지 않음). ZDR(Zero Data Retention)이 불가능합니다. 소스코드나 개인정보에 ZDR을 요구하는 계약·규제 환경이라면 벤치마크와 무관하게 Fable 5가 막힙니다. Opus 4.8은 ZDR을 지원합니다.

분류기 오탐. 보안 연구, 생물·화학, 취약점 분석에 가까운 워크로드는 일부 응답이 Opus 4.8 폴백으로 처리됩니다. 안티치트 업무처럼 리버싱·탐지 우회 분석이 섞이는 도메인이라면 이 전환 빈도를 사전에 측정해볼 필요가 있습니다. 출시 직후 분류기가 과민하다는 평가(Karpathy 포함)가 있었고, 7월 복구판에는 개선 분류기가 추가됐습니다.

통합 변경. API 통합 시 세 가지가 바뀝니다: stop_reason: "refusal" 처리, 다른 모델로의 재시도(서버 측 fallbacks 파라미터 또는 SDK 미들웨어), 폴백 시 과금 규칙입니다.

 

8. 실행 가이드: 라우팅 전략

기본 규칙. 검토 프로세스 하에서 작업을 안정적으로 완료하는 가장 싼 모델에서 시작합니다. Opus 4.8이 기본값입니다.

Fable 5로 승격하는 조건:

  • 멀티파일 리팩토링, 대규모 마이그레이션 등 코드베이스 전체를 작업 기억에 유지해야 하는 과제 (Stripe는 5,000만 라인 Ruby 코드베이스 마이그레이션을 하루에 완료했다고 보고했습니다. 수작업 추정 2개월 이상 분량입니다)
  • 모듈 경계를 넘는 디버깅 — 증상과 원인이 멀리 떨어진 경우
  • 계획-실행-자체검증-반복을 무감독으로 돌리는 장시간 비동기 실행
  • Opus 4.8이 반복적으로 실패하거나 계획을 잃는 것이 확인된 과제

Opus 4.8에 고정하는 조건:

  • 잘 스코프된 일상 작업 (격차가 수렴하는 구간)
  • 지연시간이 중요한 대화형·고빈도 트래픽 (2배 단가가 볼륨으로 복리 증가)
  • ZDR이 계약 요건인 워크로드
  • 분류기 오탐이 잦은 민감 도메인

조건이 바뀌면 결론도 바뀝니다. Fable 5 단가가 인하되거나 ZDR이 열리면 승격 임계값이 내려갑니다. 반대로 워크로드가 짧은 과제 위주라면 상위 티어의 존재 자체가 무의미합니다. 이 판단은 벤치마크가 아니라 자기 작업 로그로 해야 합니다.
