Grok 4.7은 어떤 모델인가

Grok 4.7은 SpaceXAI가 코딩과 지식 노동을 위해 내놓은 AI 모델입니다. 질문에 답하는 데서 그치지 않고, 개발 도구와 연결해 코드를 수정하거나 자료를 읽고 문서·발표 자료를 만드는 작업을 겨냥합니다. 이런 도구를 사용하며 여러 단계를 수행하는 AI를 에이전트라고 부릅니다.

출시 발표에 따르면 이전 Grok 4.6보다 큰 기반 모델을 사용하고, 오래 걸리는 과제를 더 많이 학습했습니다. 작업 결과를 스스로 점검하고 긴 자료를 다루는 능력도 개선했다는 설명입니다. 출시 시점에는 Cursor, Grok Build, Grok API 등에서 사용할 수 있습니다.

코딩과 문서 작업에서는 어느 쪽이 나을까?

코딩 평가만 보아도 결과가 엇갈립니다. xAI가 공개한 표에서 Grok은 소프트웨어 개발 평가인 DeepSWE에서 근소하게 앞섰지만, 장시간 코딩을 평가하는 CursorBench와 터미널 작업을 평가하는 Terminal-Bench에서는 Fable이 높았습니다.

아래는 xAI 공식표에서 두 모델의 값이 모두 있는 7개 평가를 옮긴 것입니다. 벤치마크는 정해진 과제를 수행하게 하고 결과를 채점하는 시험입니다. 모든 행에서 높은 값이 좋은 결과를 뜻하지만, 평가마다 과제와 단위가 달라 점수를 합산할 수는 없습니다.

표의 AA Briefcase는 문서·표·슬라이드 같은 사무 업무를 평가합니다. 이 항목은 백분율 대신 상대 평가 점수인 Elo를 사용합니다. 평가기관의 설명에 따르면, 결과물의 분석 품질·표현 품질·채점 기준 충족도를 합친 값입니다.

API 비용은 얼마나 차이 날까?

여기서 비교하는 가격은 앱의 월 구독료가 아니라, 프로그램에서 모델을 호출할 때 사용량에 따라 내는 API 요금입니다. 입력은 모델에 보내는 질문과 자료, 출력은 모델이 생성하는 내용입니다. 같은 자료를 다시 사용할 때에는 캐시 읽기 요금이 적용될 수 있습니다.

xAI 가격표와 Anthropic 가격표의 일반 API 단가는 다음과 같습니다. 단위는 모두 토큰 100만 개당 미국 달러입니다.

요금 항목 Grok 4.7 Fable 5.1
일반 입력 $2 $10
일반 출력 $6 $50
캐시 읽기 $0.50 $0.25

Grok의 위 요금은 입력 프롬프트가 20만 토큰 미만인 요청 기준입니다. 20만 토큰을 초과하면 초과분만이 아니라 요청 전체에 입력 $4·캐시 읽기 $1·출력 $12가 적용됩니다. Fable은 100만 토큰 문맥까지 표준 단가를 유지합니다. Cursor나 다른 중개 서비스의 요금은 이 직접 API 가격과 다를 수 있습니다.

단가 차이를 실제 금액으로 보기 위해, Codex가 같은 토큰 사용량 세 가지를 대입해 계산했습니다. 첫 번째 예시에서는 여러 요청에 걸쳐 입력 100만 토큰과 출력 20만 토큰을 사용합니다. Grok은 입력 $2에 출력 $1.20을 더해 $3.20, Fable은 각각 $10씩 더해 $20입니다.

첫째와 둘째 행은 각 요청의 프롬프트가 20만 토큰보다 짧다고 가정했습니다. 셋째 행에는 Grok의 장문 요금을 적용했습니다. 캐시 쓰기, 서버 도구, 세금, 중개 수수료는 제외했으며, 실제 모델을 실행한 청구액이 아닌 단가 계산입니다.

Fable이 더 저렴해질 여지도 있습니다. 같은 긴 자료를 반복해서 읽고 출력은 적은 작업이라면 낮은 캐시 읽기 단가가 유리합니다. 즉시 응답이 필요하지 않을 때 요청을 모아 나중에 처리하는 Batch API를 쓰면 입출력 요금도 50% 할인됩니다. Grok 4.7은 Batch API를 지원하지 않습니다.

실제 비용은 같은 일을 끝낼 때까지 계산해야 합니다. Grok에서 재시도하거나 사람이 수정하는 일이 늘어나면 표의 절감률이 그대로 남지는 않습니다. 반대로 결과 차이가 작은 반복 작업이라면 낮은 단가가 누적 비용을 줄여 줄 수 있습니다.

Fable 5.1 공식 사양에는 입력·출력·캐시 가격, Batch API 할인, 1M 문맥과 128K 출력이 함께 표시됩니다. 모바일에서는 화면을 좌우로 밀어 각 값을 확인하세요.

50만 토큰을 넘는 자료와 답변을 한 문맥에 유지해야 한다면 두 모델 가운데 Fable이 맞습니다. Grok의 출력에 별도 상한이 없다는 설명도 문맥 창의 제한까지 없다는 뜻은 아닙니다. 자료를 나누거나 필요한 부분을 검색해 넣을 수 있다면 Grok도 비교 대상에 남습니다. 문맥 창의 크기는 담을 수 있는 양을 뜻하므로, 자료 속 조건을 얼마나 정확하게 찾아 쓰는지는 결과물로 확인해야 합니다.

업무용 API를 연결하기 전 확인할 조건

회사 자료를 넣는다면 보존 정책부터 확인해야 합니다. xAI 보안 문서는 기본 보존 기간을 30일로 안내하며, 요청·응답을 보존하지 않는 Zero Data Retention(ZDR)을 신청할 수 있다고 설명합니다. 대신 ZDR에서는 서버에 대화 상태를 저장하거나 Files·Collections·Batch를 사용하는 기능이 제한됩니다. Anthropic 정책에서 Fable 5.1은 별도 승인이 없는 한 30일 보존이 필요한 모델입니다. 회사가 ZDR을 요구한다면 성능과 별개로 적용 가능 여부와 계약 조건을 먼저 확인해야 합니다.

자동화에서는 요청 거절도 완료 응답과 구분해야 합니다. Fable의 거부 응답은 HTTP 200이어도 stop_reason: "refusal"을 포함할 수 있습니다. 다른 모델로 재시도하는 서버측 fallback은 beta 기능이며, Batch API와 일부 클라우드에서는 직접 재시도를 구현해야 합니다. 성공률을 비교할 때에도 재시도 횟수와 실제 답변한 모델을 함께 기록해야 공정합니다.

Fable 사용자가 Grok으로 바꿔 볼 만한 작업

공개 평가와 비용을 함께 고려하면, 지금 Fable에 맡기는 작업 가운데 무엇을 유지하고 무엇을 Grok으로 시험할지 다음처럼 나눌 수 있습니다.

지금 맡기는 작업 권하는 시작점 확인할 부분
사람이 검토할 초안·분류를 반복 생성 Grok 4.7 시험 줄어든 요금과 늘어난 수정 시간
여러 도구를 쓰며 오래 진행하는 개발 작업 기존 Fable 5.1 유지 Grok에서도 같은 완료 조건을 충족하는지

비용을 우선해 새 API 자동화를 구성 Grok 4.7부터 시험 자체 과제의 성공률이 요구 수준에 이르는지

Grok을 처음 시험할 때에는 기본 추론 설정인 high에서 시작할 수 있습니다. 결과가 부족하면 xhigh로 높여 보고, 현재 쓰는 Fable과 같은 입력·도구·완료 조건을 맞춰 비교하세요. 앞의 최고 강도 평가 점수가 기본 설정에서도 그대로 나온다고 가정해서는 안 됩니다.

이전 Astra·Fable 비교글과 함께 모델을 고르는 중이라면, 평소 맡기는 업무에서 대표 사례를 골라 두는 것이 좋습니다. 예를 들어 20개 안팎의 사례에 같은 완료 조건을 적용하고, 성공 여부·수정 횟수·실제 요금·완료 시간을 기록할 수 있습니다. 이는 통계적으로 충분한 표본이라는 뜻이 아니라, 전환 전에 차이를 확인하기 위한 출발점입니다.

Grok 4.7을 도입할지는 실제로 줄어든 요금과 추가로 드는 수정 시간을 함께 보고 결정하는 편이 낫습니다. 먼저 비용이 많이 드는 반복 작업 하나를 옮겨 보고, 결과가 유지될 때 사용 범위를 넓히는 것을 권합니다.
