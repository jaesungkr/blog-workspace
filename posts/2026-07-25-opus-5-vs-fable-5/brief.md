# 기획: Opus 5 vs Fable 5 - 클로드 모델 비교

## 분류와 독자

- 상위 카테고리: `Log`
- 하위 카테고리: `AI 모델 · 비교`
- 한 명의 독자: Claude Code 또는 Claude API에서 기본 모델을 정해야 하는
  개발자와 자동화 담당자
- 검색 의도: `Opus 5 vs Fable 5`, `Claude Opus 5 가격`,
  `Fable 5 비교`, `Claude Code 모델 추천`
- 독자가 이미 아는 것: Fable 5가 Claude 최상위 모델이고 Opus가 그 아래
  모델이었다는 기존 라인업

## 글의 중심

- 독자가 기억할 한 문장: 대부분의 작업은 Opus 5로 시작하고, 실제 작업 로그로
  필요성이 확인된 최고 난도 과제만 Fable 5로 올립니다.
- 낯선 주제를 붙잡아 줄 익숙한 장면: 같은 일을 더 싼 도구로 처리해도 사용량이
  두 배가 되면 실제 비용은 같아지는 계산
- 이 글이 답하지 않는 범위: 모든 조직의 비공개 워크로드, 장기간 반복한 자체
  블라인드 벤치마크, Claude 구독 플랜별 사용량 제한
- 가장 정직한 한계 또는 반론: dev.log가 두 모델 API를 같은 하네스에서 직접
  재실행한 비교가 아니라 공개 테스트의 원시 수치를 정규화한 분석입니다.

## 중앙 방법의 계산 또는 판단 사슬

`영상에 공개된 전체 출력 토큰과 실행 횟수 -> 모델별 실행당 출력 토큰 ->
공식 출력 단가 적용 -> 실행당 출력 비용 비교 -> 시간·성공 결과와 함께 판단 ->
Opus 기본, 로그로 증명된 예외만 Fable이라는 라우팅 기준`

단순화한 손익분기식은 다음과 같습니다.

`Opus 작업비 / Fable 작업비 = Opus 토큰 사용량 배수 / 2`

입력·출력 비율과 부대비용이 같다는 가정에서 Opus가 Fable보다 토큰을 두 배
사용하면 두 모델의 작업비가 같아집니다.
