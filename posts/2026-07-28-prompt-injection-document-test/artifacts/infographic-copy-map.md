# 인포그래픽 문구·근거 맵

## 독자 질문

문서 속 공격 문장이 모델 문맥에 들어온 뒤, 실제 도구 행동으로 곧바로
이어지지 않게 하려면 어디에 경계를 둬야 하나요?

## 배치

`문장보다 권한이 더 중요한 이유` 절의
`사용자 요청 -> 외부 문서 -> 판단 -> 도구 행동` 인용문 바로 뒤

## 문구와 근거

| 이미지 문구 | 역할 | 본문·근거 |
|---|---|---|
| 문서의 한 줄이 행동이 되기 전 | 제목 | 공격 문장이 모델 판단을 거쳐 도구 행동으로 이어지는 중앙 사슬 |
| 외부 데이터와 도구 사이에 세 경계를 둡니다 | 요지 | OWASP·Microsoft·OpenAI의 다층 방어 원칙 |
| 사용자 요청 / 신뢰할 지시 | 입력 1 | 사용자가 요청한 회의 사실 요약 |
| 외부 문서 / 비신뢰 데이터 | 입력 2 | OWASP의 간접 프롬프트 인젝션 정의 |
| 에이전트 판단 | 처리 | 데이터와 명령의 신뢰 수준 판단 |
| 중단 · 기록 | 방어 결과 | 허용 범위를 벗어난 도구 행동 차단·감시 |
| 1 작업 범위 / 요약만 | 경계 1 | 구체적인 작업·출력 범위 지정 |
| 2 최소 권한 / 읽기만 | 경계 2 | 요약 작업에 불필요한 쓰기·전송 권한 제거 |
| 3 사람 승인 / 전송·삭제 전 확인 | 경계 3 | 되돌리기 어려운 행동의 human-in-the-loop |
| 허용된 결과 / 회의 사실 요약 | 정상 결과 | 본 실험의 정상 작업 목표 |
| 한 모델의 판단만으로 안전을 보장할 수 없습니다 | 한계 | 공격 성공 0/6은 보편적 안전 증명이 아니라는 실험 한계 |

## 조판 수치

- 캔버스: 1200×1500, 4:5
- 헤더: 230px, 캔버스 높이의 15.3%
- 제목: 68px -> 360px 표시에서 20.4px
- 주요·경계 라벨: 50px -> 15.0px
- 설명: 40px -> 12.0px
- 부제: 38px -> 11.4px
- 보조 라벨·한계: 37px -> 11.1px
- 모바일 축소 래스터는 만들지 않으며 같은 원본을 브라우저에서
  `width:360px`로 표시해 검수합니다.
