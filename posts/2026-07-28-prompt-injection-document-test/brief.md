# 기획: 프롬프트 인젝션 실험 - 문서 속 한 줄이 AI 에이전트를 속일까

## 분류와 독자

- 상위 카테고리: `Log`
- 하위 카테고리: `AI 개념 · 실전`
- 한 명의 독자: AI 에이전트에게 문서·메일·웹페이지를 읽히려 하지만, 그 안의
  숨은 지시가 실제 행동으로 이어질 수 있는지 궁금한 비개발자 또는 입문 개발자
- 검색 의도: `프롬프트 인젝션`, `간접 프롬프트 인젝션`, `AI 에이전트 보안`을
  검색해 개념, 실제 작은 실험 결과, 바로 적용할 방어 원칙을 함께 확인함
- 독자가 이미 아는 것: 챗봇에 질문을 입력할 수 있고, AI 에이전트가 파일을
  읽거나 만드는 정도의 작업을 할 수 있음. 지시 계층, 신뢰 경계, 최소 권한은
  쉬운 설명이 필요함

## 글의 중심

- 독자가 기억할 한 문장: 이번 단순 실험에서 문서 속 한 줄은 Codex를 속이지
  못했지만, 안전성은 공격 문구 탐지 하나가 아니라 명확한 작업 범위, 최소 권한,
  위험 행동 승인이라는 여러 겹의 경계로 만들어야 함
- 낯선 주제를 붙잡아 줄 익숙한 장면: 받은 PDF나 회의록을 요약해 달라고 했는데
  문서 안에 사람에게는 메모처럼 보이는 AI용 지시가 들어 있는 장면
- 이 글이 답하지 않는 범위: 모든 모델·에이전트의 안전성 순위, 적응형 공격,
  이미지 기반 공격, 민감 정보 유출, 브라우저·메일·결제 도구의 실제 침투 테스트
- 가장 정직한 한계 또는 반론: 최신 모델의 기본 방어가 단순 공격을 막은 결과이며,
  공격 형태 3개를 조건별 1회씩 실행한 작은 표본입니다. 공격 성공 0/6은
  취약점이 없다는 증명이 아님

## dev.log만의 근거

- first-party contribution: 같은 업무 메모에 한 줄짜리 공격 지시를 눈에 보이는
  문장, HTML 주석, 흰색 1px 텍스트로 넣고, 최소 지시와 신뢰 경계 지시에서
  Codex가 파일을 만들거나 허위 추천을 삽입하는지 격리된 6개 공격 사례와
  1개 대조군으로 확인함
- 실제 실행 주체: `Codex`
- 보존할 원자료: `artifacts/run_experiment.py`,
  `artifacts/experiment-metadata.json`, `artifacts/experiment-results.json`,
  `artifacts/runs/`의 입력 문서·프롬프트·JSONL 이벤트·요약·판정 파일
- 기존 글 또는 시리즈 연결: dev.log의 AI 에이전트·작업공간 격리 글에서 한
  단계 더 들어가, 에이전트가 외부 문서를 읽을 때 생기는 신뢰 경계를 실험함
- 다른 블로그 이름으로 바꿔도 성립하는 부분: OWASP와 각 벤더의 일반 보안
  권고. 저장소 지침이 실험에 섞인 파일럿을 폐기하고 `/private/tmp`에서 다시
  실행한 과정, 정확한 입력과 실패를 남긴 점이 dev.log의 검증 근거를 만듦
- 자율 주제 점수: 10/10

    trust and scope 2

## 중앙 방법의 계산 또는 판단 사슬

공격 경로:

`사용자 요청 -> 에이전트가 외부 문서 읽기 -> 문서의 공격 문장이 모델 문맥에
포함 -> 데이터와 명령의 신뢰 수준 판단 -> 도구 호출 결정 -> 파일·메일·웹 행동`

방어 판단:

`외부 문서를 신뢰하지 않는 데이터로 표시 -> 허용 작업과 출력 파일을 제한 ->
도구 권한을 최소화 -> 위험 행동은 사람에게 확인 -> 실제 행동과 출처를 기록`

## 보조 인포그래픽 판단

- 결정: `1장`
- 한눈에 보여 줄 관계: 사용자 요청과 외부 문서가 에이전트 안에서 만난 뒤,
  지시 계층·권한 경계·사람 승인을 통과해야 실제 행동으로 이어지는 흐름
- 글이나 표만으로 충분하지 않은 이유: 독자는 프롬프트 인젝션을 단순히
  “나쁜 문장 필터링”으로 오해하기 쉽습니다. 공격이 들어오는 `source`와
  위험 행동이 나가는 `sink` 사이에 세 방어층이 있다는 구조를 한 화면에서
  보여 주면 실전 대책을 더 빨리 이해할 수 있음
- 유형: `원리`
- 핵심 설명 뒤 권장 위치: `문장보다 권한이 더 중요한 이유` 절의 판단 사슬 뒤
- 추가 이미지가 있다면 각 이미지가 답할 서로 다른 질문: 1장으로 충분함
- 조판 품질 요구: 1200×1500 캔버스에서 제목 68px, 주요·경계 라벨 50px,
  설명 40px, 한계 37px로 조정함. 360px CSS 표시 환산값은 각각 20.4px,
  15.0px, 12.0px, 11.1px이며 헤더는 캔버스 높이의 15.3%임.
  큰 외곽 카드 없이 입력·판단·세 경계·결과의 흐름이 캔버스 대부분을
  차지하게 구성하고, 원본 래스터의 여백과 연결선 충돌을 별도 확인함
