## 분류와 독자

- 하위 카테고리: `AI 개념 · 실전`
- 한 명의 독자: Codex나 Claude Code용 `SKILL.md`를 직접 관리하지만, 실패가
  생길 때마다 규칙을 덧붙이는 방식이 실제 성능을 높이는지 판단하기 어려운 개발자
- 검색 의도: `SkillOpt`, `SkillOpt 사용법`, `에이전트 스킬 최적화`를 검색해
  도구의 원리, 공식 성능 수치, 설치 경로, 현실적인 적용 조건을 한 번에 확인함

## 글의 중심

- 독자가 기억할 한 문장: SkillOpt의 핵심은 스킬을 자주 다시 쓰는 데 있지 않고,
  실행 결과를 근거로 작은 수정을 제안한 뒤 별도 검증 점수가 실제로 오른 수정만
  남기는 데 있음
- 낯선 주제를 붙잡아 줄 익숙한 장면: 한 작업의 실패를 고치려고 스킬에 예외
  규칙을 추가했더니 이전에 잘 되던 작업이 오히려 흔들리는 장면
- 이 글이 답하지 않는 범위: 논문의 전체 유료 모델 실험 재현, SkillOpt-Sleep의
  실제 개인 세션 수집, 주관적 글쓰기·디자인 작업의 자동 채점기 설계
- 가장 정직한 한계 또는 반론: 자동 검증기와 분리된 검증 데이터가 약하면
  SkillOpt도 잘못된 점수를 최적화할 뿐임. 전체 학습에는 적지 않은 모델 호출과
  토큰이 들며, 한 번만 수행할 작업에는 비용을 회수하기 어려움

## 중앙 방법의 계산 또는 판단 사슬

`훈련 작업 + 현재 skill.md -> 동결된 대상 모델의 실행 궤적·점수 -> 별도
옵티마이저 모델의 add/delete/replace 제안 -> 중복 병합·순위화·편집 예산만큼
선택 -> 후보 skill.md -> 분리한 selection 세트 점수 비교 -> 향상 시 채택,
동점·하락 시 거절 -> best_skill.md`
