# 기획: SkillOpt 사용법: 에이전트의 반복 실수를 스킬로 고치는 방법

## 분류와 독자

- 상위 카테고리: `Log`
- 하위 카테고리: `AI 개념 · 실전`
- 한 명의 독자: Codex나 Claude Code용 `SKILL.md`를 처음 접했거나 직접
  관리하면서도 SkillOpt가 어떤 문제에 필요한지 감을 잡기 어려운 개발자
- 검색 의도: `SkillOpt`, `SkillOpt 사용법`, `에이전트 스킬 최적화`를 검색해
  도구의 원리, 공식 성능 수치, 설치 경로, 현실적인 적용 조건을 한 번에 확인함
- 독자가 이미 아는 것: 에이전트가 지침 파일을 읽을 수 있다는 정도. 학습률,
  실행 궤적, 검증 세트는 구체적인 업무 예시 뒤에 설명해야 함

## 글의 중심

- 독자가 기억할 한 문장: SkillOpt의 핵심은 스킬을 자주 다시 쓰는 데 있지 않고,
  실행 결과를 근거로 작은 수정을 제안한 뒤 별도 검증 점수가 실제로 오른 수정만
  남기는 데 있음
- 낯선 주제를 붙잡아 줄 익숙한 장면: 버그 수정용 스킬을 쓰는 코딩 에이전트가
  코드는 고치지만 관련 테스트를 반복해서 빼먹는 장면
- 설명용 구조 예시: 훈련 기록에서 `코드 수정 뒤 관련 테스트 실행` 규칙을
  제안하고, 별도 선택용 작업 10개에서 현재 6개 성공보다 후보가 8개 성공하면
  채택하며 6개 동점 후보는 거절함. 실제 측정값이 아닌 가상 예시라고 명시함
- 이 글이 답하지 않는 범위: 논문의 전체 유료 모델 실험 재현, SkillOpt-Sleep의
  실제 개인 세션 수집, 주관적 글쓰기·디자인 작업의 자동 채점기 설계
- 가장 정직한 한계 또는 반론: 자동 검증기와 분리된 검증 데이터가 약하면
  SkillOpt도 잘못된 점수를 최적화할 뿐임. 전체 학습에는 적지 않은 모델 호출과
  토큰이 들며, 한 번만 수행할 작업에는 비용을 회수하기 어려움

## 설명 순서

| 순서 | 독자가 먼저 알아야 할 것 | 다음 내용과의 연결 |
|---|---|---|
| 1 | 반복 업무에서 같은 실수를 하는 에이전트가 SkillOpt의 대상임 | 무엇에 필요한 도구인지 먼저 이해함 |
| 2 | 테스트를 빼먹는 가상 사례에서 규칙 제안과 6→8 채택을 봄 | 별도 선택용 작업과 동점 거절을 숫자로 이해함 |
| 3 | SkillOpt는 모델 가중치가 아니라 외부 스킬 문서를 최적화함 | 파인튜닝·일회성 프롬프트와 다른 대상을 구분함 |
| 4 | 작업 기록에서 작은 편집 후보를 만들고 별도 검증 세트가 채택을 결정함 | 학습률·게이트·거절 기록의 역할을 이해함 |
| 5 | 현재 소스에서 게이트 경계와 전체 테스트를 직접 재현함 | 가상 예시와 실제 검증 범위를 분리함 |
| 6 | 공식 성능의 학습 비용과 두 워크플로를 구분함 | 설치 전에 자신의 목적과 검증 가능성을 판단함 |

## 중앙 방법의 계산 또는 판단 사슬

`훈련 작업 + 현재 skill.md -> 동결된 대상 모델의 실행 궤적·점수 -> 별도
옵티마이저 모델의 add/delete/replace 제안 -> 중복 병합·순위화·편집 예산만큼
선택 -> 후보 skill.md -> 분리한 selection 세트 점수 비교 -> 향상 시 채택,
동점·하락 시 거절 -> best_skill.md`

## 보조 인포그래픽 판단

- 결정: `1장`
- 한눈에 보여 줄 관계: 같은 스킬 문서가 훈련 작업에서는 편집 근거를 만들고,
  분리된 selection 작업에서는 채택 여부를 결정하며, 통과본만 배포되는 순환 구조
- 글이나 표만으로 충분하지 않은 이유: 롤아웃·옵티마이저·편집 예산·검증 게이트가
  순차 단계이면서 거절 버퍼를 통해 다음 단계로 되돌아가는 관계라 문장만으로는
  데이터 분리와 피드백 방향을 한눈에 잡기 어려움
- 유형: `과정`
- 핵심 설명 뒤 권장 위치: `예시를 실제 학습으로 바꾸는 여섯 단계` 판단 사슬 뒤
- 추가 이미지가 있다면 각 이미지가 답할 서로 다른 질문: 한 장만 제작함
