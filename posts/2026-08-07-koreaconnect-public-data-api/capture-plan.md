# 캡처 계획: 공공데이터 API 활용기, 전국 화재 현황 29만 건을 받아보니

## 독자 과업

- 주요 독자와 이 독자가 모른다고 가정할 내용: 공공데이터로 작은 프로젝트를
  해보고 싶지만 마켓 탐색, 키 위치, 날짜 필드와 갱신 지연을 모르는 개발자
- 낯선 주제를 설명할 익숙한 기준: 뉴스와 기관 자료를 수작업으로 모으는 대신
  전국 사건 기록을 JSON 한 번으로 받기
- 글을 읽은 뒤 완료할 작업: 마켓에서 한 API를 고르고 1~5건을 호출한 뒤
  사건일과 등록일을 비교해 용도를 판단
- 시작 상태와 전제 조건: 디지털융합플랫폼 계정, 승인된 API 이용자 키, curl
- 비개발자가 시작할 가장 쉬운 경로: 로그인 없이 마켓의 분야·설명을 둘러보고
  사용할 데이터의 상세 명세와 갱신일을 확인
- 개발자·API로 확장할 경로: 승인 뒤 `api_user_key_id` 헤더로 POST하고 JSON 저장
- 가장 짧은 성공 경로: 상세 페이지 -> 사용신청 -> 승인 -> `size=1` 호출 ->
  `total`과 `items[0]` 확인
- 이 글이 시험하지 않는 범위: 다른 API 인증 호출, 전수 품질, 고정 갱신 SLA

## 비교와 사용법

- 비교 대상과 개수: 같은 화재 API의 `rcptDt`, `dsptDt`, `gtrRegDt` 정렬 3개
- 판정 규칙: 실제 사건 최신성은 접수일, 수집 최신성은 등록일로 구분
- 공식 자료와 독립 검증의 경계: 요청·응답 명세는 공식, 200 응답·건수·날짜
  비교는 Codex 직접 호출
- 실제 시작 URL: `https://portal.koreaconnect.kr/market/mk/getMkDigitStore`
- 계정·API Key 조건: 검색은 공개, 호출은 사용신청 승인과 이용자 키 필요
- 정확한 헤더: `api_user_key_id`
- 대표 첫 과제: `page=1&size=5&sort=rcptDt,desc`
- 공식 문서 링크: 전국 화재 현황 상세 URL
- 가장 흔한 실패: 키를 쿼리에 넣거나 헤더를 빼면 401. 등록일만 정렬하면 같은
  배치 안에서 실제 최신 접수를 놓칠 수 있음

## 실행 환경

- 실행 주체: 사용자 승인·키 입력, Codex 호출·검산
- 확인일: 2026-08-07
- OS·도구: macOS, curl, Codex in-app browser
- 계정·네트워크 조건: 승인된 키 사용, 키는 파일에 저장하지 않음
- 테스트 데이터와 개인정보 준비: 공개 화재 데이터만 저장. 조사서번호는 원시
  증거에 남지만 본문 예시에서는 노출하지 않음
