## 현재 편집 방향

- 한 명의 독자: ChatGPT 같은 AI 채팅은 써 봤지만 로컬 AI, 파인튜닝, GPU 같은 말은 낯선 비개발자
- 중심 문장: Unsloth Desktop은 공개 AI 모델을 내 컴퓨터에 내려받아 대화하고, 질문·답변 예시로 원하는 응답 방식을 학습하는 화면형 앱입니다.
- 가장 쉬운 시작: 작은 GGUF 모델로 로컬 채팅을 확인한 뒤 학습 자료와 Train 설정으로 이동합니다.
- 글의 척추: 반복해서 원하는 답변 형식을 요청하던 독자가 파인튜닝의 뜻을 이해하고, 작은 모델 실행과 정답 예시 준비를 거쳐 짧은 학습의 시작 상태까지 확인합니다.
- 근거 경계: 공개 본문은 제작 과정이나 미실행 사실을 변명처럼 고지하지 않습니다. 공식 주장에는 링크를 붙이고, 직접 측정하지 않은 성능·VRAM·품질 수치를 쓰지 않습니다.

## 제목과 소제목 스트립

이전 제목:

- `Unsloth Desktop 사용법, 첫 학습 전에 볼 화면 3곳`

선택 제목:

- `Unsloth Desktop이란? 코딩 없이 내 PC에서 AI를 학습하는 앱`

| 소제목 | 독자에게 맡은 일 | 통과 이유 |
|---|---|---|
| `Unsloth Desktop은 무엇을 하는 앱일까` | identify | 일반 AI 채팅과 로컬 파인튜닝 앱의 차이를 제품명과 함께 설명함 |
| `내 컴퓨터로 어디까지 할 수 있을까` | verify | 운영체제와 CPU·GPU 범위, 작은 모델로 시작할 이유를 연결함 |
| `처음에는 작은 모델로 채팅해 보기` | act | 학습보다 먼저 확인할 첫 행동을 평이하게 제시함 |
| `학습 자료는 정답 예시처럼 준비하기` | act | 문서 투입이 아니라 입력·출력 예시를 준비한다는 핵심을 설명함 |
| `Train 화면에서 고를 세 가지` | choose | Model·Method·Dataset이라는 실제 선택 범위를 이름 붙임 |
| `99% 뒤에는 학습 스텝 확인하기` | verify | 다운로드 진행률과 실제 학습 시작을 구분함 |
| `Desktop 대신 Studio·Core를 고를 때` | decide | 다른 Unsloth 방식과 Colab으로 바꿀 조건을 한 표에서 보여 줌 |

제목과 소제목만 읽으면 `제품 이해 -> 사용 환경 확인 -> 첫 실행 -> 자료 준비 -> 학습 설정 -> 진행 확인 -> 대안 선택` 순서가 보입니다. 모든 소제목을 질문형으로 맞추지 않고, 독자의 일이 바뀌는 지점에만 문장 형태를 사용했습니다.

## 문단별 새 정보와 주장 소유권

| 절 | 새 정보 | 소유한 주장·행동 |
|---|---|---|
| opening | 파인튜닝의 평이한 뜻, Desktop의 제품 정체, 작은 채팅이라는 첫 행동 | 제품의 한 문장 정의와 가장 쉬운 시작 |
| Unsloth Desktop은 무엇을 하는 앱일까 | 일반 AI 채팅과 로컬 모델의 차이, 파인튜닝 범위, 공식 오프라인 안내 | 제품이 필요한 이유 |
| 내 컴퓨터로 어디까지 할 수 있을까 | OS, CPU·GPU의 쉬운 뜻, 모델·백엔드별 범위 | 설치 전 기대치와 작은 모델 선택 |

- 반복 소유권: 파인튜닝 정의는 opening이 소유하고 이후에는 데이터와 학습 방식에 필요한 만큼만 이어 갑니다.
- 반복 소유권: 작은 모델 채팅은 세 번째 절이 절차를 소유하고 opening과 closing은 한 문장 행동만 남깁니다.
- 반복 소유권: 미측정 성능 고지는 공개 본문에서 소유 절을 만들지 않습니다. 근거 한계는 evidence.md가 보존합니다.
- 빈 문단 검사: 글의 구성을 예고하거나 앞 표를 그대로 되풀이하는 문단을 두지 않았습니다.

## AI 템플릿 문장 정리

- `2026년 8월 14일 기준 공식 UI에서 확인되는 것은...` 같은 제작 과정 중심 문장을 삭제하고 독자가 바로 행동할 수 있는 제품 정의와 첫 시작을 남겼습니다.
- `설치 가능 여부와 학습 가능 여부는 다릅니다`라는 압축 대비만 두지 않고 모델 크기와 메모리 요구가 왜 다른지 바로 설명했습니다.
- 기술 용어를 먼저 나열하지 않고 `스마트폰에 앱을 설치하듯 모델 파일을 내려받는다`, `이런 질문에는 이렇게 답한다는 예시 모음`처럼 결과를 먼저 이해하게 했습니다.
- 절마다 굵은 요약을 두지 않았고 `이번 글에서는`, `차근차근`, `알아보겠습니다`를 사용하지 않았습니다.
- closing에서 본문 전체를 반복하지 않고 `작은 모델 채팅 -> 작은 정답 예시 묶음 -> Run preview`라는 다음 행동만 남겼습니다.

## 보존한 사실과 경계

- v0.1.701-beta 공개 날짜, Windows·macOS·Linux 설치 파일 제공
- Desktop의 CPU Chat·Data Recipes 범위와 폭넓은 하드웨어 범주, 모델·백엔드별 차이
- QLoRA를 4비트 기본 모델과 LoRA 어댑터의 결합으로 설명한 기술 의미
- 공식 FAQ의 오프라인 실행·텔레메트리 미수집 안내를 벤더 주장 범위로 표현
- 공식 화면의 Dataset·Model weights 99%, `Training in progress`, `waiting for first step (0)` 문구와 스텝 카운터 해석
- 직접 측정하지 않은 속도, VRAM 사용량, 학습 품질을 수치나 체험으로 쓰지 않음

- 채팅 확인용 GGUF와 Train의 학습 모델을 같은 모델로 단정하지 않음
