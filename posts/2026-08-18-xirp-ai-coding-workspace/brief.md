# 기획: Xirp, 스포티파이가 만든 AI 코딩 세션 관리 앱

## 분류와 독자

- 상위 카테고리: `Log`
- 하위 카테고리: `AI 개념 · 실전`
- 한 명의 독자: Claude Code, Codex, Gemini 가운데 둘 이상을 쓰거나 여러 프로젝트의 AI 코딩 세션을 동시에 관리하는 macOS 개발자
- 검색 의도: Xirp가 무엇인지, Orca와 어떤 문제가 다른지, Spotify Portal이 무엇이며 언제 필요한지, Portal 없이 첫 세션을 어떻게 시작하는지 알고 싶음
- 독자가 이미 아는 것: 터미널과 Git 저장소의 의미, AI 코딩 에이전트 하나를 설치하고 로그인하는 방법. Xirp와 Spotify Portal은 모르며 Orca는 이름이나 worktree 기능만 들어봤을 수 있음

## 글의 중심

- 독자가 기억할 한 문장: Xirp는 흩어진 CLI 세션을 모아 보는 도구이고, Orca는 worktree별 구현을 비교해 PR로 제출하는 IDE이며, Portal은 회사의 서비스·담당 팀·문서를 Xirp 세션에 연결하는 내부 개발자 포털입니다.
- 낯선 주제를 붙잡아 줄 익숙한 장면: 여러 터미널과 브랜치를 오가다 어느 에이전트가 어떤 저장소에서 무엇을 기다리는지 놓치는 장면
- 가장 쉬운 시작: Portal 연결 없이 기존 코딩 에이전트 CLI를 그대로 둔 채 로컬 Git 프로젝트 하나와 새 worktree 세션 하나로 시작함
- 첫 화면의 답: 단일 세션은 터미널, 여러 로컬 세션의 상태 관리는 Xirp, 구현 비교·변경 검토·PR은 Orca, 조직 맥락은 Xirp+Portal이라는 선택 기준을 lead visual 전에 제시함
- 이 글이 답하지 않는 범위: 실제 응답 속도·토큰 비용·코드 품질 벤치마크, Spotify Portal의 계약 가격과 엔터프라이즈 도입 절차, 직접 사용 후기
- 가장 정직한 한계 또는 반론: Xirp는 macOS 전용 비공개 소프트웨어의 베타이며 Windows·Linux·서버·SSH 세션은 지원하지 않음. 단일 세션 사용자에게는 기존 터미널보다 관리 층만 늘어날 수 있음

## dev.log만의 근거

- first-party contribution: Xirp·Portal·Orca 공식 문서의 기능을 `세션 상태 관리 / worktree 중심 구현 비교·PR / 조직 맥락 / 실행 위치`로 다시 분류해 `터미널 / Xirp 단독 / Orca / Xirp+Portal` 선택표를 만듦
- 실제 실행 주체: `Codex`
- 실제 확인 범위: Xirp·Spotify Portal·Orca의 공식 사이트와 문서, FAQ, 공개 화면을 교차 확인. Xirp 앱과 Portal 계정은 직접 실행하지 않음
- 보존할 원자료: 공식 URL, 주장별 근거 지도, 공식 문서가 제공한 원본 JPEG 3장, 무손실 변환한 게시용 PNG 3장과 각 SHA-256
- 기존 글 또는 시리즈 연결: 기존 `orca-agent-ide-guide`의 worktree·diff 검토 흐름을 현재 Orca 공식 문서로 다시 확인하고 Xirp와의 선택 기준으로 연결함
- 다른 블로그 이름으로 바꿔도 성립하는 부분: 제품 기능 요약에 그치지 않고, 세션 관리와 구현 비교를 서로 다른 문제로 나눈 dev.log 선택표를 제시함
