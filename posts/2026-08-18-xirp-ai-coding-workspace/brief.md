# 기획: Xirp, 여러 AI 코딩 에이전트를 한곳에서 관리하는 스포티파이 개발 도구

## 분류와 독자

- 상위 카테고리: `Log`
- 하위 카테고리: `AI 개념 · 실전`
- 한 명의 독자: Claude Code, Codex, Gemini 가운데 둘 이상을 쓰거나 여러 프로젝트의 AI 코딩 세션을 동시에 관리하는 macOS 개발자
- 검색 의도: Xirp가 무엇인지, 기존 터미널 기반 AI 코딩과 무엇이 다른지, Portal 없이도 쓸 수 있는지, 첫 세션을 어떻게 시작하는지 알고 싶음
- 독자가 이미 아는 것: 터미널과 Git 저장소의 의미, AI 코딩 에이전트 하나를 설치하고 로그인하는 방법. Xirp, Spotify Portal, Workspace는 모름

## 글의 중심

- 독자가 기억할 한 문장: Xirp는 새 AI 모델이 아니라 Claude Code·Codex·Gemini 세션과 Git worktree를 한곳에서 관리하고, 필요하면 Spotify Portal의 조직 맥락까지 연결하는 macOS 앱입니다.
- 낯선 주제를 붙잡아 줄 익숙한 장면: 여러 터미널과 브랜치를 오가다 어느 에이전트가 어떤 저장소에서 무엇을 기다리는지 놓치는 장면
- 가장 쉬운 시작: Portal 연결 없이 기존 코딩 에이전트 CLI를 그대로 둔 채 로컬 Git 프로젝트 하나와 새 worktree 세션 하나로 시작함
- 첫 화면의 답: macOS에서 한 에이전트와 한 세션만 쓴다면 터미널로 충분하지만, 여러 세션을 병렬로 돌린다면 Xirp 로컬 베타를 시험할 이유가 생김
- 이 글이 답하지 않는 범위: 실제 응답 속도·토큰 비용·코드 품질 벤치마크, Spotify Portal의 계약 가격과 엔터프라이즈 도입 절차, 직접 사용 후기
- 가장 정직한 한계 또는 반론: Xirp는 macOS 전용 비공개 소프트웨어의 베타이며 Windows·Linux·서버·SSH 세션은 지원하지 않음. 단일 세션 사용자에게는 기존 터미널보다 관리 층만 늘어날 수 있음

## dev.log만의 근거

- first-party contribution: 공식 기능 목록을 `에이전트 수·동시 세션 수·조직 맥락 필요 여부·운영체제` 네 조건으로 다시 판정해 `터미널 유지 / Xirp 단독 / Xirp+Portal / 도입 보류` 결정표를 만듦
- 실제 실행 주체: `Codex`
- 실제 확인 범위: 공개 공식 사이트, 공식 문서, FAQ, 변경 기록, 제품 발표문과 공식 화면의 교차 확인. Xirp 앱과 Portal 계정은 직접 실행하지 않음
- 보존할 원자료: 공식 URL, 주장별 근거 지도, 공식 문서가 제공한 원본 JPEG 3장, 무손실 변환한 게시용 PNG 3장과 각 SHA-256
- 기존 글 또는 시리즈 연결: Xirp 자체 사용 경험이나 직접 연결되는 기존 글이 없어 억지 내부 링크를 넣지 않음
- 다른 블로그 이름으로 바꿔도 성립하는 부분: 기능 요약만으로 끝내지 않고, 단일 세션 사용자에게는 불필요할 수 있다는 반론과 네 갈래 도입 결정표를 제시함
