# 기획: 어셈블리어란 무엇인가, ARM64 코드로 읽는 사용처와 장단점

## 분류와 독자

- 상위 카테고리: `Log`
- 하위 카테고리: `개발 · 디지털`
- 한 명의 독자: Python·JavaScript·C 같은 고급 언어 코드는 작성해 봤지만 어셈블리어와 CPU 명령의 관계는 처음 보는 개발 입문자
- 검색 의도: 어셈블리어가 무엇이고 어디에 쓰이는지, 장단점은 무엇인지, 코드를 어떻게 읽는지, 지금도 배울 가치가 있는지 한 번에 파악
- 독자가 이미 아는 것: 변수, 덧셈, 조건문, 함수처럼 고급 언어에서 쓰는 기본 개념

## 글의 중심

- 독자가 기억할 한 문장: 어셈블리어는 CPU가 실행하는 명령을 사람이 읽을 수 있는 기호로 옮긴 언어이며, 오늘날에는 앱 전체를 작성하기보다 하드웨어 제어·부팅·컴파일러·성능 분석·보안처럼 낮은 층을 직접 봐야 할 때 사용합니다.
- 낯선 주제를 붙잡아 줄 익숙한 장면: C의 `return a + b;` 한 줄이 컴파일 뒤 몇 개의 CPU 명령과 바이트로 바뀌는 장면
- 가장 쉬운 시작: 레지스터, 명령어, 메모리 주소라는 세 단어를 익힌 뒤 덧셈 함수의 네 줄짜리 ARM64 코드를 따라 읽기
- 첫 화면의 답: 어셈블리어는 기계어와 고급 언어 사이의 얇은 번역층이며, 특정 CPU에 밀착된 제어와 분석이 필요할 때 여전히 쓰입니다.
- 이 글이 답하지 않는 범위: 특정 CPU 명령 집합 전체, 운영체제별 완전한 호출 규약, SIMD 최적화, 셸코드 제작, 악성코드 작성, x86·ARM 문법의 모든 차이
- 가장 정직한 한계 또는 반론: 예시는 Apple Silicon macOS 26.5.2의 ARM64와 Apple Clang 21.0.0에서 확인한 작은 함수입니다. 다른 아키텍처·컴파일러·최적화 단계에서는 명령과 레지스터가 달라질 수 있습니다.

## dev.log만의 근거

- first-party contribution: 동일한 C 코드에서 Clang이 만든 ARM64 어셈블리와 `objdump`의 기계어 바이트를 직접 보존하고, 최적화 수준 `-O0`과 `-O2`가 같은 의미를 얼마나 다른 명령으로 표현하는지 비교
- 실제 실행 주체: `Codex`
- 보존할 원자료: `artifacts/experiment/`의 환경 정보, C 입력, 직접 작성한 ARM64 예제, 컴파일 명령, 어셈블리 출력, 오브젝트 디스어셈블 결과, 실행 결과, 실패 기록
- 기존 글 또는 시리즈 연결: 개발 · 디지털 카테고리의 프로그래밍 원리 설명 글로 독립 게시
- 다른 블로그 이름으로 바꿔도 성립하는 부분: 어셈블리어의 정의와 일반적인 사용처
- dev.log에서만 남는 부분: 현재 저장소 환경에서 재현한 C -> ARM64 어셈블리 -> 기계어 바이트 대응과 최적화 전후 비교 원자료

## 설명 순서

| 순서 | 독자가 먼저 알아야 할 것 | 다음 내용과의 연결 |
|---|---|---|
| 1 | 어셈블리어가 기계어 그 자체가 아니라 CPU 명령을 나타내는 사람이 읽을 기호라는 점 | 고급 언어·어셈블리·기계어의 위치를 구분 |
| 2 | 레지스터·명령어·메모리 주소의 역할 | 덧셈과 조건문 예제를 줄 단위로 읽음 |
| 3 | 명령 집합과 호출 규약이 CPU·운영체제에 따라 달라진다는 점 | ARM64 예시를 x86 전체에 일반화하지 않음 |
| 4 | 직접 제어와 예측 가능성의 이점에는 이식성·생산성 비용이 따름 | 실제 사용처와 장단점을 함께 판단 |
| 5 | 컴파일러가 대부분의 앱 코드를 더 잘 생성해 주는 현대적 현실 | 배울 이유와 직접 작성할 범위를 구분 |

## 중앙 방법의 계산 또는 판단 사슬

`C 소스 입력 -> Clang이 ARM64 어셈블리 생성 -> assembler가 기계어 바이트로 인코딩 -> CPU가 레지스터와 메모리 상태를 바꾸며 결과 출력`

## 보조 인포그래픽 판단

- 결정: `1장`
- 한눈에 보여 줄 관계: `C 한 줄 -> ARM64 니모닉 -> 32비트 기계어 -> CPU 상태 변화`
- 글이나 표만으로 충분하지 않은 이유: 독자가 흔히 어셈블리어와 기계어를 같은 것으로 오해하므로, 두 표현과 실행 주체의 경계를 한 화면에서 연결해야 합니다.
- 유형: `과정`
- 핵심 설명 뒤 권장 위치: `어셈블리어가 놓인 층` 절의 변환 설명 직후
- 추가 이미지가 있다면 각 이미지가 답할 서로 다른 질문: 대표 이미지는 주제 인지를 담당하고, 인포그래픽은 코드가 CPU 명령으로 내려가는 변환 단계를 설명합니다.
