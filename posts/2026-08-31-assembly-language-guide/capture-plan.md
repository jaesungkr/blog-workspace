# 조건부 캡처 계획

`workflow-v2.json`에서 `direct_capture` 또는 `gif`가 참일 때만 이 파일을 사용합니다.

## 독자 행동과 증거

| ID | 시작 상태 | 행동 | 기대 결과 | 필요한 캡처 |
|---|---|---|---|---|
| T01 | Apple Silicon macOS의 빈 실험 디렉터리 | `clang -S`로 C 함수를 ARM64 어셈블리로 변환 | 컴파일러가 만든 `.s` 원문 | 화면 캡처 대신 원문 `.s`와 명령 로그 |
| T02 | 동일한 C 입력 | `clang -c`와 `objdump -d`로 오브젝트를 디스어셈블 | 니모닉 옆에 기계어 바이트가 표시됨 | `objdump` 텍스트 출력 |
| T03 | 직접 작성한 ARM64 `.s` | Clang으로 링크한 뒤 세 입력으로 실행 | 호출 결과와 종료 상태가 예상값과 일치 | 소스·빌드 로그·실행 출력 |
| T04 | 같은 C 입력 | `-O0`과 `-O2` 결과 비교 | 최적화 단계에 따라 명령 수와 형태가 달라짐 | 두 `.s` 원문과 정규화 비교표 |

## 실행 경계

- 실행자: Codex
- 제품·앱 버전: Apple Clang과 Apple `otool`/LLVM `objdump` 중 현재 환경에서 확인되는 도구
- 운영체제·브라우저: Apple Silicon macOS, 브라우저 미사용
- 실행 날짜: 2026-08-31
- 직접 확인하지 못한 범위: x86-64·RISC-V 실행, 다른 운영체제의 호출 규약, 대규모 애플리케이션의 성능 개선 폭

## 개인정보 준비

- 테스트 계정 또는 공개 데이터만 사용합니다.
- 비밀번호·토큰·QR·이메일·개인 경로가 보이면 저장하지 않고 상태를 정리한 뒤 다시 캡처합니다.
- 원본은 `artifacts/captures/` 또는 `artifacts/recordings/`에 둡니다.

## 실패와 재캡처

| 문제 | 처리 | 최종 결과 |
|---|---|---|
| 컴파일러가 플랫폼별 심볼에 밑줄을 붙일 수 있음 | 공개 예제와 실제 macOS 심볼 표기를 구분해 기록 | 실제 출력은 그대로 보존하고 본문은 호출 규약 차이로 설명 |
| 최적화가 예제 함수를 상수 접기 또는 인라인할 수 있음 | 함수를 별도 번역 단위로 컴파일하고 오브젝트 코드를 함께 확인 | 함수 자체의 생성 명령만 비교 |
