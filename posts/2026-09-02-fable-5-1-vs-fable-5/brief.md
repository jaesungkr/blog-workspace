# 기획: Fable 5.1 vs Fable 5 - 클로드 모델 비교

## 분류와 독자

- 상위 카테고리: `Log`
- 하위 카테고리: `AI 모델 · 비교`
- 한 명의 독자: Claude Code 또는 Claude API에서 Fable 5를 사용하고 있으며 Fable 5.1로 바로 옮길지 판단하려는 비전문 개발자
- 검색 의도: Fable 5.1과 Fable 5의 성능·가격·호환성 차이를 확인하고 업그레이드 여부를 결정
- 독자가 이미 아는 것: Fable 5가 Claude의 최고 난도 장시간 작업용 모델이라는 사실
- 독자가 아직 모르는 것: Fable 5.1의 개선 폭, 캐시 가격 인하가 실제 청구액에 미치는 조건, `max`에서 오히려 늘어난 외부 평가 과제당 비용, 마이그레이션의 세 가지 호환성 변화

## 독자 효용 계약

- 독자가 알아보는 상황: 기존 Fable 5 세션이나 에이전트를 그대로 Fable 5.1 모델 ID로 바꿔도 되는지 확인하는 순간
- 한 명의 독자: Fable 5를 실제 개발 작업에 연결한 비전문 개발자
- 한 가지 기본 추천: 기존 Fable 5 작업은 호환성 점검 뒤 Fable 5.1로 옮기되, 일상 작업의 기본 모델까지 Fable 5.1로 올리지는 않고 Opus 5에서 부족한 장시간 과제에 사용
- 유용한 결과: 공식 벤치마크의 상승과 실제 비용의 상승 가능성을 함께 보고 모델·effort·캐시 구조를 따로 결정
- 지원할 실제 선택: 즉시 이전, 단계적 이전, Opus 5 유지 가운데 하나를 고름
- 제외할 세부 사항: Mythos 5.1의 제한 접근 절차, 시스템 카드의 전체 안전 평가, 모든 벤치마크, 구독 플랜별 세부 크레딧 계산, 직접 API 품질 테스트

## 글의 중심

- 독자가 기억할 한 문장: Fable 5.1은 같은 기본 단가에서 공식 비교표의 7개 평가군·9개 결과 행을 모두 앞섰고 캐시 읽기 가격도 4분의 1로 낮췄지만, `max` 외부 평가에서는 출력 토큰이 늘어 과제당 비용이 Fable 5보다 20% 높았습니다.
- 낯선 주제를 붙잡아 줄 익숙한 장면: 모델 선택기에서 이름 뒤에 `.1`이 붙은 새 모델을 보고 단순한 교체인지 비용 구조까지 달라진 업데이트인지 판단하는 상황
- 가장 쉬운 시작: 기존 대표 과제를 `xhigh`와 `max`로 나눠 성공률·출력 토큰·캐시 읽기·완료 시간을 기록
- 첫 화면의 답: 기존 Fable 5 사용자는 호환성만 확인되면 5.1로 옮길 이유가 충분하지만, 더 싸다는 이유로 `max`를 기본값으로 두면 안 됩니다.
- 이 글이 답하지 않는 범위: 한국어 창작 품질, 장시간 Claude Code 세션의 직접 재현, 모든 공급자 지연시간, 안전 분류기의 분야별 정확도
- 가장 정직한 한계 또는 반론: Anthropic 표는 제조사 평가이며, Artificial Analysis도 Anthropic의 출시 전 평가를 지원했고 기본 폴백으로 약 4%의 출력 토큰을 Opus 모델에서 받았습니다. dev.log는 두 API 모델을 같은 과제로 직접 실행하지 않았습니다.

## 독자 마찰 스크린샷 판단

- 진입점: UI 절차를 안내하지 않으므로 화면 진입점 캡처가 필요하지 않습니다.
- 선택: Claude Code 최소 버전과 API 모델 ID는 본문 텍스트가 더 정확합니다.
- 검증: 성능과 비용은 HTML 표와 보조 인포그래픽이 작은 화면에서 더 잘 읽힙니다.
- 결정: 설명용 UI 스크린샷 `0장`
- 제외 이유: 모델 선택기와 가격표 화면은 본문 표를 반복하며 플랜 상태에 따라 더 빨리 낡습니다.

## 보조 인포그래픽 판단

- 결정: `1장`
- 한눈에 보여 줄 관계: Fable 5.1의 성능 상승, 캐시 읽기 인하, `max` 과제당 비용 증가를 하나의 이전 판단으로 연결
- 글이나 표만으로 충분하지 않은 이유: 서로 다른 표에 흩어진 세 신호가 같은 방향을 가리키지 않으므로, 독자가 `더 좋은 모델 = 항상 더 싼 작업`으로 오해하기 쉽습니다.
- 유형: `비교`
- 핵심 설명 뒤 권장 위치: `외부 평가의 66점과 20% 높은 과제당 비용` 절 뒤
- 추가 이미지가 있다면 각 이미지가 답할 서로 다른 질문: 대표 이미지는 두 모델의 동등한 비교를 알리고, 인포그래픽은 이전 판단에서 성능과 비용이 갈리는 이유를 설명합니다.
