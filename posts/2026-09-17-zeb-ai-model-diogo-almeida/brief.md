# 기획: 제브(Jev) AI, 고객 문의 예시로 이해하는 판단 전용 모델

## 분류와 독자

- 상위 카테고리: `Trends`
- 하위 카테고리: `AI 뉴스 · 테크 · 산업`
- 한 명의 독자: 챗GPT는 알지만 제브(Jev)는 처음 접한 비전문가
- 검색 의도: 디오고 알메이다가 공개한 제브가 무엇이며 기존 챗봇형 AI와 무엇이 다른지 알고 싶음
- 독자가 이미 아는 것: 챗GPT 같은 AI는 질문을 받으면 문장으로 답한다는 점
- 독자가 아직 모르는 것: 제브는 자유로운 문장을 생성하지 않고, 미리 정한 선택지·점수·참일 확률을 소프트웨어에 돌려주는 판단 전용 모델이라는 점

## 글의 중심

- 독자가 기억할 한 문장: 제브는 문의를 읽어 담당 팀의 선택과 확률을 돌려주고, 프로그램은 그 값을 이용해 문의를 배정합니다.
- 낯선 주제를 붙잡아 줄 익숙한 장면: 고객 문의가 스팸인지, 어느 상담팀으로 보내야 하는지, 사람이 다시 봐야 하는지를 애플리케이션이 매번 판단하는 상황
- 가장 쉬운 시작: 제브를 `문장을 쓰는 AI`가 아니라 `선택지마다 확률을 매기는 AI`로 이해하기
- 첫 화면 답: 배송 문의를 분류하는 장면에서 제브를 프로그램의 다음 행동에 필요한 선택과 확률을 반환하는 모델로 소개함. 접근 경로는 마지막 절에서 설명함
- 이 글이 답하지 않는 범위: 제브 API 전체 사용법, 미공개 모델 구조와 학습 데이터 추정, 제브를 직접 호출한 독립 성능 비교, 범용 AGI 전망
- 가장 정직한 한계 또는 반론: 홈페이지의 속도·비용·지능 수치는 TypeSafe가 설계하고 수행한 워크플로 평가에서 나온 벤더 주장이고, 공개 표준 벤치마크나 독립 재현 결과로 확인된 보편적 성능이 아님
- 테스트 경계: 계정과 초기 접근 권한이 없어 제브를 직접 호출하지 않음. 공식 홈페이지·발표문·문서·평가 페이지를 서로 대조해 주장별 보장 범위와 미검증 범위를 나눔

## dev.log만의 근거

- first-party contribution: 홈페이지의 강한 문구를 `출력 형식으로 보장되는 것`, `회사가 측정한 것`, `아직 독립 검증되지 않은 것`으로 분류한 주장 감사표와 제브를 붙일 업무 판단 기준
- 실제 실행 주체: `Codex`
- 보존할 원자료: TypeSafe 공식 홈페이지 화면, 공식 발표문·문서·평가 페이지 URL, InstructGPT와 GPT-4 논문, 제공받은 Instagram 게시물의 공개 캡션, 주장별 근거와 한계를 기록한 `evidence.md`
- 기존 글 또는 시리즈 연결: 특정 기존 글의 후속편은 아니며, `Trends > AI 뉴스 · 테크 · 산업`에서 새 AI 제품의 발표 문구를 검증하는 글로 연결함
- 다른 블로그 이름으로 바꿔도 성립하는 부분: 공개 기능 설명은 성립함. `환각 0%`를 오답 0%와 분리하고, 벤더 평가의 참조값과 편향 고백까지 함께 읽는 판단이 dev.log의 검증 중심 기여임

## 설명 순서

| 순서 | 독자가 먼저 알아야 할 것 | 다음 내용과의 연결 |
|---|---|---|
| 1 | 배송 문의 한 건을 입력하고 팀·긴급도·수령 기한을 질문함 | 입력과 출력의 관계를 구체적으로 이해 |
| 2 | Choice·Score·Noul의 가상 응답을 보고 프로그램이 다음 행동을 정함 | 판단값과 실행, 모델 확률과 실측 정확도를 구분 |
| 3 | 알메이다는 InstructGPT와 GPT-4 논문에 이름을 올린 연구자임 | 챗GPT와의 연결을 과장 없이 정리 |
| 4 | 홈페이지 수치는 회사 자체 워크플로 평가이며 회사도 유리한 조건과 편향 가능성을 밝힘 | `환각 0%`와 정확도 보장의 차이를 검토 |
| 5 | 제브는 분류·라우팅·검증에, 챗봇형 LLM은 글·코드·설명 생성에 맞음 | 두 모델을 함께 쓰는 현실적인 위치를 결정 |

## 중앙 방법의 판단 사슬

`애플리케이션 상태 입력 -> 미리 정의한 Choice·Score·Noul 질문 -> 제브가 질문별 확률을 병렬 계산 -> 코드가 임계값과 정책을 적용 -> 자동 처리·사람 검토·생성형 LLM 호출 중 하나를 선택`

## 예시 보강 개정

- 사용자 요청: 문장을 전반적으로 매끄럽게 다듬고 제브가 무엇인지 바로 이해할 예시를 추가함
- 가상 입력: 사흘째 도착하지 않은 물건을 내일 선물해야 한다는 배송 문의
- 가상 출력: 배송 92%·결제 5%·계정 3%, 긴급도 0~2 중 1.7, 수령 기한 요구 확률 0.85. 실제 측정값이나 공식 API 원문이 아님을 표 앞에서 표시함
- 예시의 역할: 문의 입력, 질문 정의, 모델 판단값, 프로그램의 배정이라는 네 단계를 연결함
- Score 정확성: 공식 문서에 맞춰 0부터 시작하는 단계와 확률 가중 평균의 소수 점수를 사용함
- 첫 절이 입출력·확률 해석을 소유하고, 환각 절은 같은 문의를 오분류하는 반례로 형식 보장과 정답 보장을 구분함
- 성능 절의 최종 소제목: `193.6배 빠르고 444.6배 저렴하다는 주장`. 비용 증가로 오독될 수 있는 압축 표현을 풀고 회사 주장의 평가 조건을 설명함
- 이미지와 CDN URL은 기존 자산을 재사용하며 추가 업로드는 필요하지 않음
