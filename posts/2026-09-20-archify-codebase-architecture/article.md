안녕하세요. dev.log입니다.

처음 보는 프로젝트를 열면 파일은 많고, 어디서부터 읽어야 할지 막막할 때가 있습니다. AI에게 설명을 부탁해도 긴 답변을 읽다 보면 “그래서 이 요청은 어디를 거쳐 처리되는 거지?”라는 질문이 남습니다. 이럴 때 구성 요소와 연결 관계를 그림으로 펼쳐 놓으면 전체 흐름을 따라가기 쉽습니다.

**Archify는 AI가 읽은 코드나 사용자가 적은 설명을, 클릭하며 살펴볼 수 있는 다이어그램으로 만드는 스킬입니다.** Claude Code나 Codex 같은 코딩 도구에 추가해 사용합니다. 새 프로젝트의 구조를 파악하거나, 팀원에게 기능의 처리 과정을 설명할 때 어울립니다. [공식 프로젝트](https://github.com/tt-a1i/archify)는 코드 외에도 계획이나 아이디어를 시각화하는 예제를 제공합니다.

### 복잡한 처리 과정을 한눈에

웹사이트에서 상품을 조회하는 상황을 떠올려 보겠습니다. 브라우저가 서버에 요청을 보내면, 서버는 잠시 보관한 데이터인 캐시부터 확인합니다. 원하는 데이터가 없으면 데이터베이스에서 가져와 응답합니다. 문장으로는 짧지만, 인증이나 기록 저장까지 끼어들면 어떤 작업이 먼저인지 헷갈리기 쉽습니다.

아래는 Archify가 공개한 [캐시 미스 공식 예제](https://archify.si/gallery/artifacts/cache-miss.sequence)입니다. 캐시 미스는 필요한 데이터가 캐시에 없는 상황을 뜻합니다. 이 예제에는 인증과 추적 기록도 포함되어 있습니다.

{{media:archify-cache-miss}}

이런 그림은 상자 수보다 **화살표가 어떤 일을 뜻하는지** 읽는 편이 유용합니다. 요청이 들어오는 쪽에서 시작해 캐시 조회, 데이터베이스 접근, 응답으로 이어지는 순서를 따라가면 됩니다. 실제 서비스와 비교할 때도 “캐시에 없을 때 어디로 가는가”, “조회 결과가 어디로 돌아오는가”처럼 질문 하나를 정해 두면 확인할 범위가 줄어듭니다.

공식 예제에서 API 상자를 선택하면 상세 패널이 열립니다. 아래 화면에는 인증 확인, 캐시 조회, 데이터베이스 조회처럼 API가 다른 구성 요소에 보내는 요청이 모여 있습니다. 전체 그림에서 선을 하나씩 찾기 어려울 때, 담당 구성 요소를 눌러 관련 연결만 읽을 수 있습니다.

### 어디에 설치하고 어떻게 쓸까?

Archify를 쓰려면 파일을 읽고 명령을 실행할 수 있는 코딩 에이전트와 Node.js 환경이 필요합니다. 여기서 에이전트는 코드를 살펴보고 파일을 만드는 AI 도구를 말합니다. 일반 채팅창에 이름만 입력하는 방식과는 준비 과정이 다릅니다. [공식 시작 안내](https://archify.si/start)에서 사용하는 도구에 맞춰 준비할 수 있습니다.

작업은 두 부분으로 나뉩니다. AI가 코드나 설명에서 구성 요소와 관계를 정리하면, Archify가 그 내용을 받아 다이어그램을 그리고 검사합니다. 결과는 브라우저에서 여는 HTML 파일입니다. 받은 사람이 그림을 보기 위해 Archify를 설치할 필요는 없습니다.

설치는 사용하는 도구의 터미널에서 시작합니다. [공식 빠른 시작](https://github.com/tt-a1i/archify#quick-start)의 기본 명령은 다음과 같습니다.

```bash
npx skills add tt-a1i/archify -g
```

설치 과정에서는 실제로 사용하는 에이전트를 선택합니다. `-g`는 여러 프로젝트에서 쓸 수 있도록 전역에 설치하는 옵션입니다. 특정 프로젝트에서만 사용하려면 [설치 안내](https://archify.si/start)에서 해당 에이전트와 프로젝트 범위를 선택하면 됩니다.

### 처음엔 로그인 과정부터 그려 보기

설치 후에는 코드가 있는 작업 공간에서 AI에게 무엇을 보고 싶은지 말하면 됩니다. 다음은 요청 예시입니다.

> 이 프로젝트의 로그인 처리 흐름을 Archify로 그려 줘.

“전체 구조를 전부 그려 줘”보다 확인할 대상이 분명합니다. 로그인 화면, 요청을 받는 서버, 사용자 정보를 조회하는 부분처럼 한 기능에 필요한 요소부터 살펴볼 수 있습니다. 결과가 복잡하다면 “로그인에 직접 관계없는 부분은 빼 줘”처럼 이어서 수정합니다.

코드가 없어도 시작할 수 있습니다. 예를 들어 “주문 접수 → 결제 확인 → 배송 준비 과정을 그려 줘”라고 요청하면 됩니다. 이 경우에는 사용자가 알려 준 절차를 그림으로 정리합니다.

그림의 종류는 알고 싶은 내용에 맞추면 됩니다. [공식 시나리오 가이드](https://archify.si/guide)는 현재 10가지 종류를 안내하지만, 처음부터 이름을 모두 외울 필요는 없습니다.

| 알고 싶은 내용 | 어울리는 그림 | 읽는 방법 |
| --- | --- | --- |
| 어떤 서버와 저장소가 연결되어 있는지 | 구조도(Architecture) | 구성 요소와 연결 관계 확인 |
| 요청이 어떤 순서로 처리되는지 | 호출 순서도(Sequence) | 호출과 응답을 차례로 따라가기 |
| 승인·반려 뒤에 어떤 작업을 하는지 | 업무 흐름도(Workflow) | 분기 조건과 다음 단계 확인 |

### 그림만으로 설명이 부족할 때

그림만으로 설명하기 어려운 주제에는 한 페이지 답변 기능이 어울립니다. [v3.2.0에서 추가된 explainer](https://github.com/tt-a1i/archify/releases/tag/v3.2.0)는 결론을 먼저 보여 주고, 질문별로 설명과 표, 단계, 다이어그램을 묶어 줍니다. 그림의 일부와 옆 설명이 함께 강조되며, 노드를 누르면 상세 뷰로 이동할 수 있습니다.

{{media:archify-explainer}}

[HTTPS 첫 방문 공식 예제](https://archify.si/cases/explainer/tls-first-visit)는 브라우저가 사이트에 처음 연결할 때의 과정을 다룹니다. 위에서 답을 짧게 읽은 뒤, 아래에서 통신 순서와 사이트 확인 과정을 따로 살펴보도록 구성되어 있습니다. 같은 내용을 긴 채팅 답변으로 읽을 때보다 질문별로 찾아보기 좋은 형태입니다.

팀에 설명할 자료가 필요하다면 “이 로그인 구조를 새 팀원이 이해할 수 있게 Archify 한 페이지로 설명해 줘”라고 요청할 수 있습니다. 구조도 하나로 충분한지, 그림과 설명을 함께 전달해야 하는지에 따라 결과 형식을 고르면 됩니다.

### AI가 그린 구조, 그대로 믿어도 될까?

Archify의 검사는 그림을 구성한 데이터와 표현이 규칙에 맞는지 확인합니다. **AI가 코드를 정확히 이해했는지, 운영 중인 서비스가 실제로 그렇게 동작하는지는 별도로 확인해야 합니다.** [공식 가이드](https://archify.si/agent-diagrams)도 코드 근거와 실행 중인 시스템의 동작을 구분합니다. 실제 요청 경로를 확인하려면 코드 외에 설정이나 실행 기록이 필요할 수 있습니다. 공유할 때는 참조한 코드 버전을 남기고, 설명 카드와 포함된 코드에 내부 정보가 없는지도 살펴봐야 합니다.

Archify는 처음 보는 코드를 읽을 때 전체 흐름을 잡고, 이미 이해한 구조를 다른 사람에게 설명하는 데 유용합니다. 시작은 로그인이나 주문처럼 질문 하나로 충분합니다. 그 흐름을 코드와 대조해 확인한 뒤 공유하면, 긴 설명을 되풀이하는 대신 같은 그림을 보며 이야기할 수 있습니다.

복잡한 내용을 그림으로 정리하는 AI 스킬이 궁금하다면, 앞서 소개한 [diagram-design 사용법](https://dop3n.tistory.com/entry/설명을-그려주는-AI-스킬-diagram-design)도 함께 참고해 보세요.
