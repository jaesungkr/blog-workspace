REA란? 메모 앱으로 이해하는 소프트웨어 역공학

안녕하세요. dev.log입니다.

완성된 앱을 보고 “이 기능은 어떻게 만들었을까?” 궁금할 때가 있습니다. REA(Reverse Engineer Anything)는 앱의 파일을 분석해, AI가 그 기능의 작동 방식을 설명하도록 돕는 오픈소스 도구입니다.

처음 접한다면 공식 실습의 작은 메모 앱으로 시작해 보세요. 이번 실험에서는 이 앱의 파일을 REA로 분석해 ‘내보내기’ 기능을 처리하는 코드를 찾았습니다. 그 코드를 읽어 저장 방식을 알아내고, 일부는 직접 실행해 설명이 맞는지도 확인했습니다.

REA가 AI와 분석 도구를 연결하는 관계를 보여주는 공식 소개 카드입니다. · MIT, Copyright (c) 2026 morluto

REA는 앱에서 무엇을 찾아줄까?

보통 앱을 만들 때는 코드를 작성해 기능을 구현합니다. 역공학은 이미 만들어진 프로그램을 조사해 내부에서 어떤 처리를 하는지 알아내는 작업입니다. 예를 들어 메모 앱의 ‘내보내기’ 기능을 조사한다면, 버튼을 누른 뒤 메모가 어떤 형식으로 바뀌고 어느 파일에 저장되는지 찾습니다.

REA는 이런 조사에 필요한 분석 도구를 AI가 사용할 수 있게 연결합니다. AI는 REA가 찾은 코드와 위치를 참고해 작동 방식을 설명합니다. 공식 FAQ에 따르면 JavaScript·Electron 앱, 실행 파일, 웹페이지 등을 분석할 수 있으며 대상에 따라 필요한 도구가 달라집니다.

이번에 사용한 메모 앱은 소스 코드가 함께 제공되는 연습용 예제입니다. 실행 파일에서 원래 코드를 복원한 실험은 아닙니다.

메모 앱을 분석해 알아낸 것

이 앱에는 메모를 파일로 꺼내는 ‘Export notes’ 버튼이 있습니다. 여기서 ‘내보내기’란 앱 안의 데이터를 다른 프로그램에서도 열 수 있는 파일로 만드는 기능입니다. 조사할 질문은 하나였습니다.

이 버튼을 누르면 메모를 어디에, 어떤 형태로 저장할까?

실험에서는 여섯 파일로 된 예제 폴더를 REA에 전달했습니다. REA는 JavaScript 파일 네 개를 분석했고, 내보내기 요청을 보내는 코드와 그 요청을 받아 처리하는 코드를 연결했습니다. 그 연결을 따라 원본 코드도 읽어 저장 위치와 파일 내용을 확인했습니다.

아래는 REA의 분석 결과와 원본 코드를 함께 읽어 정리한 답입니다.

확인하려던 내용코드에서 찾은 내용
어디에 저장하나요?사용자의 다운로드 폴더에 저장하도록 되어 있습니다.
파일 이름은 무엇인가요?notes.csv입니다.
어떤 내용이 들어가나요?메모 번호와 제목이 들어갑니다. 열 이름은 id와 title입니다.
어떤 형식인가요?엑셀 같은 프로그램으로 열 수 있는 CSV입니다. 데이터를 행과 열로 나눈 텍스트 형식입니다.

화면의 버튼과 파일을 저장하는 코드는 서로 다른 파일에 들어 있습니다. 버튼은 저장을 요청하고, 앱 내부의 다른 코드가 메모를 파일로 바꿔 저장합니다. REA가 연결해 준 부분은 이 요청과 처리 코드입니다. 아래 그림은 해당 코드를 읽어 정리한 전체 순서입니다.

예제 코드를 따라 정리한 메모 내보내기 순서입니다.

실제 파일에서 확인할 때는 renderer.js의 버튼 처리부터 preload.js의 요청 전달, main.js의 저장 처리 순으로 읽으면 됩니다. 공식 예제의 main.js 8~12행에 다운로드 폴더와 notes.csv라는 파일 이름이 나옵니다. 메모를 CSV로 바꾸는 함수는 csv.js에 있습니다.

이렇게 얻은 결과는 ‘저장 기능을 구현한 코드가 어디에 있고, 무엇을 하도록 작성됐는가’에 대한 설명입니다. 앱을 실행해 다운로드 폴더에 실제 파일을 저장해 보지는 않았습니다. 폴더 권한이나 디스크 문제로 저장에 실패할 때의 동작은 별도로 확인해야 합니다.

찾아낸 코드도 실행해 확인하기

저장 코드를 찾은 뒤에는 그 안에서 쓰는 변환 함수가 설명대로 동작하는지 확인했습니다. 이 앱은 메모 번호와 제목을 CSV로 바꾼 다음 파일에 씁니다. CSV 변환을 확인한 이유는, 분석에서 찾은 코드의 동작을 실제 입력과 출력으로 대조하기 위해서입니다.

확인할 입력으로는 제목에 쉼표가 들어간 메모를 골랐습니다. CSV도 쉼표로 열을 나누기 때문에, 제목 속 쉼표를 잘못 처리하면 제목이 두 칸으로 나뉠 수 있습니다. 공식 실습에서도 Hello, "REA"라는 제목으로 이 부분을 확인합니다.

원본 csv.js를 수정하지 않고 변환 함수인 toCsv에 메모 번호 1과 제목 Hello, "REA"를 넣었습니다. 함수가 실제로 만든 CSV는 다음과 같습니다.

id,title
1,"Hello, ""REA"""

큰따옴표가 늘어난 것은 CSV에 제목을 기록하는 규칙 때문입니다. 제목 전체를 큰따옴표로 감싸고, 제목 안에 있던 큰따옴표는 두 번 적습니다. 이 CSV를 다시 읽으면 제목은 처음 넣은 Hello, "REA"로 돌아옵니다.

메모 제목이 CSV에 기록됐다가 원래 문자열로 읽히는 과정입니다. 가운데에는 CSV의 제목 칸만 표시했습니다.

같은 방식으로 일반 제목, 한국어가 들어간 제목, 줄바꿈이 있는 제목, 빈 메모 목록까지 총 다섯 경우를 확인했습니다. 예상 문자열을 먼저 정해 실제 출력과 비교하고, Python으로 CSV를 다시 읽었습니다. 다섯 경우 모두 예상한 문자열이 나왔고, 다시 읽은 데이터도 입력과 같았습니다.

여기서 REA는 조사할 코드의 연결을 찾는 데 쓰였고, Node.js와 Python은 찾은 변환 함수의 결과를 확인하는 데 쓰였습니다. 메모의 쉼표 처리는 REA의 기능이 아니라, 분석 대상인 메모 앱의 동작입니다.

같은 예제를 직접 분석하는 방법

위 과정이 궁금하다면 공식 예제 ZIP을 내려받아 압축을 풀어 보세요. notes-example 폴더가 나옵니다. 이 예제는 데스크톱 앱을 만드는 Electron으로 작성됐지만, 코드를 분석하고 변환 함수만 실행할 때는 Electron을 설치하지 않아도 됩니다.

JavaScript 실행 프로그램인 Node.js와 패키지 관리 도구인 npm은 필요합니다. 아래 명령은 REA 6.7.0을 사용하며, 지원하는 Node.js 버전은 다음과 같습니다.

  • 22 계열: 22.19 이상
  • 24 계열: 24.11 이상
  • 26 이상

실험 환경은 macOS arm64, Node.js 26.0.0, npm 11.12.1, REA 6.7.0이었습니다. 본문의 명령은 macOS·Linux의 Bash/Zsh 기준입니다. Windows PowerShell 명령은 공식 실습을 참고하세요.

앱을 분석하려면 터미널에서 notes-example 폴더가 들어 있는 상위 폴더로 이동해 아래 명령을 실행하세요. npm에 포함된 npx가 REA를 내려받아 실행합니다.

npx -y rea-agents@6.7.0 analyze-javascript-application \
  ./notes-example --format json --full-output

결과는 JSON 형식의 텍스트로 나옵니다. ok가 true인지, parse_failures가 0인지 확인하세요. 각각 분석 완료와 파일 해석 실패가 없음을 뜻합니다. 위에서 설명한 저장 위치는 분석 결과에 나온 관련 파일을 열어 확인하면 됩니다.

CSV 변환을 확인하려면 notes-example 폴더 안으로 이동해 아래 명령을 실행하세요. 앱 전체를 실행하는 대신, 메모를 CSV로 바꾸는 함수만 호출합니다.

node -e 'const {toCsv}=require("./csv.js"); process.stdout.write(toCsv([{id:1,title:"Hello, \"REA\""}]))'

AI와 대화하며 조사하는 방법은 공식 시작 안내에 나와 있습니다. AI가 REA 도구를 호출하도록 연결하는 MCP 설정을 안내합니다. 위 실험에서는 이 연결 설정 없이 REA를 터미널에서 실행했습니다.

파일이 여섯 개뿐인 이 예제는 개발용 AI에 폴더를 주고 직접 읽게 해도 됩니다. 이번 실험으로 두 방식의 속도나 정확도를 비교한 것은 아닙니다. REA를 함께 쓸 때는 “이 기능을 분석하고, 어떤 파일의 어느 코드에서 확인했는지 보여줘”처럼 조사 대상과 확인할 동작을 구체적으로 알려 주세요.

실행 파일의 내부를 자세히 분석하려면 Hopper·Ghidra·IDA 같은 별도 도구가 필요합니다. 웹페이지를 분석한다고 비공개 서버 코드까지 볼 수는 없고, 실행 파일에 원래 있던 주석이나 변수 이름을 모두 되찾을 수도 없습니다.

REA 자체는 MIT 라이선스로 공개되어 있으며, 함께 쓰는 AI 서비스나 일부 분석 도구에는 별도 비용이 들 수 있습니다. 회사나 고객의 앱을 분석한다면 모델 제공자의 데이터 정책도 먼저 확인하세요.

자신이 만들었거나 분석을 허가받은 앱에서도 처음에는 기능 하나만 골라 보세요. “어디에 저장하나요?”, “어떤 데이터를 보내나요?”처럼 답을 코드와 대조할 수 있는 질문부터 시작하면 됩니다.
