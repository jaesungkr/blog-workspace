# 기획: REA란? AI로 앱의 작동 원리를 알아내는 오픈소스 도구

## 사용자 피드백과 독자

사용자가 “조금 더 쉬운 예시로 이게 뭔지, 뭘 할 수 있는지 비개발자도 이해하는 글”을 요청했습니다. 기존 원고의 source pass는 revision-1 역사 기록으로 옮겼습니다. 현재 lifecycle은 reviewing입니다.

- 분류: Log > 개발 · 디지털. 설치 튜토리얼이 아니라 도구의 용도를 이해하는 입문 설명입니다.
- 한 독자: 코딩 경험이 없고 REA도 처음 접하는 사람입니다. 앱을 쓰거나 AI에 질문해 본 정도의 배경만 전제합니다.
- 익숙한 상황: 계산기의 % 버튼을 누르지만 내부에서 어떤 계산을 하는지 모릅니다.
- 독자가 모르는 것: 기존 앱을 조사해 규칙을 찾고, 그 규칙으로 새 기능을 만드는 작업입니다.
- 한 권고: REA 공식 페이지의 계산기·게임 예제를 먼저 눌러봅니다.
- 유용한 결과: 무엇을 AI에게 요청하고 어떤 설명·결과물을 받을 수 있는지 파악합니다.
- 보유 메시지: REA는 AI가 실제 프로그램을 조사해 기능의 규칙을 찾고, 그 규칙으로 작은 기능을 다시 만드는 데 쓰는 도구입니다.
- 가장 쉬운 시작: https://rea.tools/ 의 계산기 버튼과 게임 예제입니다. 설치는 독자가 직접 사용을 선택할 때 공식 안내로 이동합니다.

## 도입과 질문 지도

도입은 `계산기 % 버튼의 규칙에 대한 질문 → 화면만으로 내부 계산을 알기 어려운 점 → 앱 안의 실제 작업을 묻는 질문 → REA의 평이한 정체 → 공식 결과물을 눌러보기`로 이어집니다. 실제 사용 경험을 만들어 넣지 않습니다.

| 독자 질문 | 담당 절 | 새로 제공하는 정보 |
|---|---|---|
| 앱에서 뭘 알아낼 수 있나요? | 계산기에서 버튼의 규칙을 알아내기 | % 규칙을 조사하고 같은 계산을 하는 작은 프로그램을 만드는 과정을 보여줍니다. |
| 아는 데서 끝나나요? | 공룡 게임에 속도 조절 기능 더하기 | 속도 규칙을 재현한 뒤 사용자가 조절하는 기능을 더하는 결과입니다. |
| 게임이나 계산기 외에는요? | 메모가 어느 파일에 저장되는지 찾기 | 버튼→파일 저장 경로를 추적해 내보내기 동작을 이해합니다. |
| 보통의 AI와 무엇이 다른가요? | 평소 쓰는 AI와 무엇이 다를까? | 개념 설명과 특정 프로그램의 동작 확인을 구별하는 자체 판단 틀입니다. |
| 코딩을 몰라도 쓸 수 있나요? | 코드를 몰라도 써볼 수 있을까? | 예제 관람과 직접 분석의 준비 차이, 비용·권한·데이터 조건입니다. |

## 설명 사슬과 자체 기여

사용자의 한 질문 → REA로 실제 앱 조사 → 관련 코드와 규칙 → AI의 쉬운 설명 → 작은 기능 재현·변경 → 원래 결과와 비교합니다. 계산기·게임·메모 예제는 프로젝트가 공개한 사례로 명시합니다.

자체 기여는 “개념을 배우는 질문”과 “내가 가진 프로그램의 실제 동작을 확인하는 질문”의 구별 및 결과 확인 기준입니다. 사용자는 자신의 목적이 REA를 설치할 만큼 구체적인지 판단할 수 있습니다. 이전 초안의 앱 형식·준비물 표를 반복하지 않습니다.

## 범위와 근거 경계

- 프로필: standard-rich. 공식 사례에 기반하며 직접 REA를 설치·실행하거나 게임을 수정하지 않았습니다.
- 계산기: Windows Calculator 11.2508.4.0의 % 사례입니다. 다른 모든 계산기를 일반화하지 않습니다. REA 4.1.0이라는 도구 버전은 evidence에 보존하고 본문에 반복하지 않습니다.
- 공룡: Chrome 내장 오프라인 게임을 직접 분석했다고 쓰지 않습니다. 공식 사례는 wayou의 Chromium 기반 웹판을 REA 4.1.0으로 조사했습니다. 속도 규칙을 재현한 교육용 새 게임이며 점프·그림·충돌은 새 코드입니다.
- 메모: 공식 Notes 예제의 다운로드 폴더·notes.csv·id/title 필드이며 오류 자동 해결을 약속하지 않습니다.
- 일반 프로그램 활용 예시는 적용 가능성으로 쓰며 실행 성과로 쓰지 않습니다.
- 코드와 역공학은 예시 속 의미가 나온 뒤 평이하게 풉니다. MCP는 끝부분에서 한 번만 소개합니다. Electron·ASAR·CLI·IPC·native 분류는 본문에서 제외합니다.
- 이 글처럼 AI와 대화하며 사용할 때는 로컬 파일을 읽는 개발용 AI·REA 연결이 필요하며 결과 검증에 개발 지식이 필요할 수 있음을 설명합니다.
- 제외: 상용 앱 전체 복제, 보안 우회, 성능·성공률·star 수, 상세 설치 명령·Node 버전·doctor 절차, 전체 기능 목록입니다. 원본 서버 소스·원래 주석 복원 한계와 비용·권한·모델 데이터 조건은 유지합니다.
- 입력 Instagram은 접근 제한으로 읽지 못한 상태입니다. 해당 게시물 문구나 사례를 인용하지 않습니다.

## 미디어와 화면 판단

사용자가 그림이나 화면이 더 필요하다고 명시했습니다. 텍스트만으로 충분하다는 이전 판단을 철회하고, 기능을 이해하는 그림과 바뀐 결과물을 보여주는 그림을 하나씩 추가합니다.

- 기존 공식 소개 카드 lead는 유지합니다.
- `rea-calculator-flow`: 계산기 질문 → REA의 앱 내부 규칙 조사 → AI의 작은 새 계산기 제작입니다. 독자 질문은 “REA와 AI가 각각 무엇을 해서 어떤 결과를 만드는가?”입니다. 과정형 도식이며 계산기 코드와 새 계산기 설명 문단 바로 뒤에 놓습니다. 한국어 caption은 “계산 규칙이 궁금하다고 질문하면 REA로 앱을 조사하고, AI가 알아낸 규칙으로 새 계산기를 만듭니다. 실제 앱 화면을 그대로 옮긴 그림은 아닙니다.”입니다.
- `rea-game-change`: 기존 웹 게임의 자동 가속과 새 교육용 게임의 속도 조절을 비교합니다. 독자 질문은 “조사한 내용으로 무엇을 바꿔 만들 수 있는가?”입니다. 비교·변경형 도식이며 공룡 사례의 속도 조절과 새 코드 한계 문단 직후에 놓습니다. 한국어 caption은 “기존 웹 게임의 속도 규칙을 조사한 뒤, 그 규칙을 재현한 작은 게임에 속도 조절을 더하는 예시입니다. 게임 전체를 복원한 결과는 아닙니다.”입니다.
- 두 그림은 max-txt2img와 내장 image_gen으로 제작하고 독립 infographic validator가 검토합니다. 단순한 장식 카드 대신 질문·조사·새 결과의 차이가 그림만으로 보이게 합니다.
- 한국어 라벨을 짧게 유지하고 모바일 가독성 때문에 첫 그림은 세로형 2:3, 두 번째는 정사각형으로 설계합니다. 원래 16:9는 고정 요구가 아닌 기본값이므로 관계와 독자 화면에 맞게 조정합니다.
- 두 그림 모두 생성 설명 그림이며 실제 실행 화면·실험 증거로 쓰지 않습니다. 본문에서 공식 사례에 귀속한 사실만 표현합니다.
- 공식 정적 사례 모음 PNG는 DX-Ball·Notion·TH04를 보여주므로 현재 계산기·공룡 설명에 맞지 않아 제외합니다. Hopper 전체 화면도 작은 내부 코드가 독자의 질문을 해결하지 않아 제외합니다. 브라우저 보안 정책으로 차단된 화면을 우회 캡처하지 않습니다.
- 생성 hero·GIF·직접 캡처·복잡한 배치·390·768·두 번째 원격 fetch는 여전히 불필요합니다. 두 이미지의 원본·글 표시 폭·확대 crop 검토는 원문 source pass 뒤 별도 수행합니다.

브라우저 URL 정책에 따른 이전 local preflight 차단은 계속 유효합니다. 실제 페이지 화면을 보았다고 기록하지 않습니다. source pass·로컬 미디어 검토와 light/dark preview 갱신 뒤 reviewing을 유지합니다.

## 제목 선택

- 선택: REA란? AI로 앱의 작동 원리를 알아내는 오픈소스 도구. 분석을 알아내기로 풀고 용도를 먼저 드러냅니다.
- 제외: REA로 앱을 복제하는 법. 완전 복원과 권리 문제를 오해하게 만듭니다.
- 제외: MCP 역공학 도구 REA 사용법. 비개발자가 모르는 기술 용어와 설치 약속을 앞세웁니다.

검색량이나 트래픽을 측정하지 않았습니다. 이번 수정의 우선순위는 비개발자의 이해입니다.
