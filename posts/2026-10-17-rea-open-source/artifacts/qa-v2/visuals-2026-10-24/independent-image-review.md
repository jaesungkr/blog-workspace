## 원본 전체 관찰

저장 흐름: 네 단계가 버튼·전달 메시지·CSV 문서·폴더라는 그림으로 구별되고 세 하향 화살표가 하나의 읽기 축을 형성합니다. 화면·앱 내부·번호/제목·다운로드 폴더·notes.csv가 승인한 코드 관계와 같습니다. 큰 외곽 프레임이 없으며 헤드라인 영역은 캔버스의 18%보다 작습니다. 실제 저장 성공 체크를 추가하지 않았고 하단 ‘코드에서 확인한 경로’가 범위를 한정합니다. 전체 원본에서 한글 오자나 아이콘/화살표의 글자 침범은 발견하지 못했습니다. 생성 래스터의 소스 폰트 설정은 제공되지 않았으므로 크기를 꾸며 기록하지 않습니다.

CSV 변환: 입력·CSV title 필드·다시 읽은 제목의 3단계가 위에서 아래로 이어지고 가운데 변환 문자열이 파랑으로 강조되어 있습니다. 실제 문자에서 입력과 마지막 값은 Hello, "REA", 중앙 값은 "Hello, ""REA"""로 원출력과 맞습니다. 큰 외곽 카드는 없고 단계별 경계는 의미를 구분합니다. 라벨과 문자열은 전체 원본에서 선·테두리와 겹치지 않습니다. 결정적 소스 글자 크기는 heading34 / node label28 / value38 / support24(viewBox640×880)이며 실제 래스터는 2배입니다.

## 반환 사항

CSV 제목 바로 아래 ‘같은 제목이 기록되고 다시 읽히는 과정’ 부제는 입력한 제목 → CSV의 제목 칸 → 다시 읽은 제목이라는 세 노드와 화살표가 이미 전달하는 내용을 반복합니다. 이 부제를 지워도 변환 관계와 필요한 구별을 잃지 않습니다. infographic 기준의 ‘각 kicker/subhead는 실제 모호성을 해소해야 한다’는 조건에 따라 삭제를 권고합니다. ‘전체를 감싸기 · 안쪽은 두 번’은 따옴표 규칙을 구별하므로 유지할 가치가 있습니다.

## intended-size 검사 접근 상태

CUA getState 결과 제 독립 에이전트 환경의 browsers 목록은 비어 있었습니다. 문서화된 createBrowserTab('iab', inspection URL, {visible:false}) 호출은 ‘Browser is not available: iab’로 실패했습니다. 실제 540px·320px 표시나 확대 영역을 확인했다고 쓰지 않습니다. 부모 검토자에게 CUA로 원본을 실제 표시한 화면을 요청했으며, 뷰포트는 변경하지 않았으므로 복원이 필요하지 않습니다. 정확한 원본의 intended-size와 확대 영역을 관찰한 뒤 최종 판정을 갱신해야 합니다.

원본 전체 관찰만으로는 pass를 기록하지 않습니다. 이미지 제작·원고 수정·게시·Git 작업은 하지 않았습니다.


## CSV v2 수정 후 전체·확대·intended-size 재확인

최종 후보는 저장 흐름 v1 그대로와 CSV 변환 v2입니다. CSV v2는 assets/rea-csv-escaping-v2.jpg, 1280×1760, SHA-256 ffd6982ae5268692a58120e9e314a2603074a54280aaee75965b0c7b4f1e1016입니다. v1의 중복 부제가 제거되었고 세 노드의 라벨과 값 사이 여백이 넓어졌습니다. 해당 수정은 1회 수정 예산을 사용한 것으로 generation record에 남아 있습니다. 중앙 문자열과 세 단계 의미는 유지됩니다.

CUA가 제공되지 않는 독립 에이전트의 제약을 우회하지 않고, 부모 에이전트가 CUA로 정확한 원본 img를 실제 표시하여 얻은 inspection-540.jpg 및 inspection-320.jpg를 원본 해상도로 열어 독립적으로 판독했습니다. image-display-measurements.json도 대조했습니다. 540px 표시의 natural dimensions는 각각 1024×1536, 1280×1760이며 display width는 둘 다 540px입니다. 360px viewport에서 두 원본 display width는 320px이며 높이는 각각 480px·440px입니다. 관찰 src도 최종 자산과 일치합니다. 이 파일들은 원본을 별도로 축소 재인코딩한 QA 이미지가 아니라 실제 브라우저 표시 화면 캡처입니다. 해당 화면의 시각적 판단은 제가 직접 했으며 부모의 승인 문구를 인용해 통과시키지 않았습니다.

540px 화면에서 저장 흐름의 4단계와 아래로 내려가는 세 화살표, CSV의 입력/변환/다시 읽기와 정확한 따옴표 문자열이 쉽게 구별됩니다. 320px 화면에서도 각 단계명, 보조 라벨, notes.csv와 하단 범위 문구를 읽을 수 있습니다. CSV 변환은 원래 값과 파란 따옴표가 있는 중앙 값을 구별할 수 있으며 ‘전체를 감싸기 · 안쪽은 두 번’도 읽힙니다. 라벨이 시각화를 압도하거나 작은 도식이 큰 외곽 카드 안에 갇힌 구성이 아닙니다. 잠깐 시선을 뗐다 돌아와 보아도 버튼에서 파일로 이어지는 관계와 제목 문자열의 왕복 관계가 먼저 잡힙니다.

정확한 최종 후보의 원본 픽셀을 확대해 읽도록 independent-crops/에 9개 PNG 영역을 만들고 전부 열었습니다. 원본 publication 파일은 변경하지 않았고, 축소 QA 래스터를 만들지 않았습니다. 제목·각 단계·아이콘/라벨·각 화살표와 arrowhead·하단 caveat·CSV 결과를 모두 포함합니다. 최초 sips 좌표가 의도대로 적용되지 않은 일부 임시 crop은 동일 위치의 정확한 PIL crop으로 다시 생성했고, 잘못된 JPEG crop은 제거했습니다. 최종 crop은 원본 해상도를 그대로 보존한 영역 추출이며 가독성을 보정하지 않았습니다.

## 글자·간격·연결선 관찰

independent-painted-bounds.json은 최종 원본의 검정/파랑 픽셀 범위를 관심 영역 안에서 측정한 자료입니다. SVG의 DOM 글자 박스를 painted bound로 오인하지 않았습니다. 저장 흐름의 단계명과 보조 문구 사이 가시 여백은 원본 기준 약 22~27px이고 보조 글자의 가시 높이는 약 45~46px입니다. 마지막 다운로드 폴더와 notes.csv 사이 간격은 약21px입니다. 권장 여백 비율의 낮은 쪽이지만 두 실제 표시 폭에서 줄이 붙어 보이거나 글자가 충돌하지 않습니다. 생성 폰트 크기는 여전히 unavailable이며 관찰한 픽셀 범위만 기록합니다.

CSV v2의 라벨→값 painted gap은 입력 약72px, 중앙 약72px, 출력 약64px입니다. 중앙 값→설명 간격은 약69px입니다. 각각 글자와 테두리·화살표 사이에 명확한 여백이 있습니다. source font size는 heading34 / node label28 / value38 / support24이고 캡처가 2배임을 실제 1280×1760 후보와 맞춰 확인했습니다. 헤드라인의 painted height는 저장 흐름 약92px/1536, CSV 약62px/1760이며 헤드라인 영역도 각각 캔버스의 약10%·8% 이내입니다.

저장 흐름의 하향 화살표는 그림 영역 안에 있고 오른쪽 라벨의 clear zone에 들어오지 않습니다. 메시지→앱, 데이터→CSV의 짧은 가로 화살표는 각 단계의 변환을 가리켜 전체 하향 순서를 혼동시키지 않습니다. 마지막 폴더와 caveat 사이에는 약40px 이상의 여백이 보입니다. 설명용 구분선은 없습니다.

CSV의 두 세로 연결선과 arrowhead는 노드 경계에 닿아 관계를 연결하지만 글자 영역에는 들어오지 않습니다. 이는 의미 없는 section rule 접촉이 아니라 노드 연결입니다. markerUnits=userSpaceOnUse와 명시한 10×10 marker source를 확인했고 실제 래스터에서도 과대 화살표나 글자 침범이 없습니다. 세 노드는 입력·직렬화·재해석이라는 역할을 담으며 중앙에만 파랑을 써 변환의 차이를 드러냅니다.

모든 한글·문장부호·파일명·따옴표를 원본 확대 영역에서 다시 읽었습니다. 잘린 글자, 가짜 글자, orphan label, 겹침, 흐릿한 보조 레이어를 발견하지 못했습니다. 실제 GUI나 저장 성공을 그린 그림이 아니며 승인된 두 캡션의 경계와 충돌하지 않습니다.
