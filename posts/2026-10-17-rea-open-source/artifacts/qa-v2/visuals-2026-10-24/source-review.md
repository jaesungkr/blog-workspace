## C25: 내보내기 저장 흐름

버튼 클릭 → 요청 전달 → CSV 변환 → 파일 저장은 원본 renderer/preload/main/csv 코드가 보여 주는 기능 순서와 맞습니다. main handler는 toCsv(notes)로 문자열을 만든 뒤 writeFileSync에 전달하며 목적지는 app.getPath("downloads") 아래 notes.csv입니다. 그림은 실행 시 성공을 추가로 입증하는 자료가 아니라 해당 코드를 읽기 쉽게 표현하는 계획입니다.

## C26: CSV 제목 칸의 변환

comma-and-quotes의 원본 actual은 `id,title\n1,"Hello, ""REA"""\n`입니다. 가운데 제목 필드만 추출한 값은 `"Hello, ""REA"""`이며 계획 문자열과 정확히 일치합니다. 입력 및 재해석한 제목은 `Hello, "REA"`입니다. csv-roundtrip.json에서도 해당 입력의 roundtrip_pass가 true임을 이전 검토에서 확인했으며 현재 증거 범위를 넓히지 않았습니다.

외곽 큰따옴표와 내부 큰따옴표 두 번 표기를 구분하는 계획은 csv.js의 quote 함수와 같습니다. 전체 CSV 대신 title 필드만 보여 준다고 brief·evidence에서 명시했으므로 id 열이나 헤더를 누락한 출력으로 잘못 소개하지 않습니다. 실제 출력 코드 바로 뒤의 그림은 동일 결과를 독자가 해석하도록 돕는 역할입니다.

캡션 ‘CSV의 제목 칸에 기록되는 문자열과 다시 읽은 제목을 연결한 설명 그림입니다. 따옴표의 개수와 위치는 실제 변환 결과를 따릅니다.’는 실제 UI라는 오해를 만들지 않으며, 기존의 원본 함수 실험에 근거합니다. 향후 그림 바이트에서도 직선 큰따옴표의 개수·위치와 title 필드 범위를 그대로 보존해야 합니다.
