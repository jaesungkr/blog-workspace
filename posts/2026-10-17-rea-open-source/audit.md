## 현재 상태와 사용자 의도

사용자가 더 쉬운 예시를 통해 비개발자도 정체와 활용을 이해하는 글을 요청했습니다. 문체만 다듬는 것으로 부족하여 예시 우선 구조로 다시 작성했습니다. lifecycle은 reviewing이며 이전 source pass와 글은 artifacts/qa-v2/history/revision-1/에 보존했습니다. 현재 수정 원고의 독립 source review는 아직 전입니다.

기존 저장소 dirty 작업은 보존했습니다. origin은 https://github.com/jaesungkr/blog-workspace.git이며 수정 전 origin/master를 fetch했습니다. 다른 글과 스킬·템플릿은 변경하지 않았습니다.

## 비교 표본과 보존 사실

이전 단계에서 읽은 같은 개발 · 디지털 분류의 최근 완료 글 5개를 비교 기준으로 유지합니다. 2026-09-27-drifty-browser, 2026-09-20-archify-codebase-architecture, 2026-09-08-cursor-origin-vs-github, 2026-08-31-assembly-language-guide, 2026-08-27-sell-o-used-phone-sale은 모두 ready였습니다. 같은 하위 분류 표본이 충분해 대체하지 않았습니다. 이번 글은 도구 사용 경험을 차용하지 않고 일상 기능을 먼저 설명합니다.

보호한 사실은 % 계산 수치, 공식 계산기 대상 버전, 공룡 웹판·속도 규칙 재현·나머지 새 코드, Notes의 notes.csv·다운로드 폴더·번호와 제목, 분석 주체, 원본 복원 한계, 대상 권한·별도 비용·모델 데이터 전달입니다. 설치 버전과 명령은 사용법을 약속하지 않는 새 범위에 따라 본문에서 제외하되 evidence와 이전 글에 보존했습니다.

## v2 voice-and-density 검토

### 독자 이익과 도입

한 독자는 코딩 경험이 없는 사람입니다. “내가 가진 파일을 분석해 보라”는 개발 절차보다 공식 예제 결과물을 먼저 눌러보도록 권합니다. 독자는 어떤 질문을 하고 무엇을 받을 수 있는지 이해합니다. 첫 화면은 % 버튼의 계산 규칙 → 화면만으로 내부 계산을 알기 어려운 점 → REA의 정체와 재구현 용도 → 직접 볼 수 있는 공식 예제로 이어집니다.

초안 도입에는 200+10%=220을 설명하고 첫 절에서 같은 계산을 다시 설명했습니다. 도입은 질문만 남기고 수치·원리는 첫 절이 소유하도록 바꿨습니다. 추상적인 검색 결과 나열·일반 로드맵·결론부터 말하면 문구는 없습니다. 낯선 MCP나 엔진 이름을 첫 화면에 두지 않습니다.

### 문장 틀·중복·용어

- '한 걸음 더 나아가'는 사례가 한 일을 직접 쓰는 'REA 프로젝트는 찾아낸 속도 규칙에 사용자가 조절하는 기능을 더해 보여줍니다'로 바꿨습니다.
- '어려운 구조가 아니라'라는 대비를 제거하고 메모의 저장 위치라는 대상을 직접 썼습니다.
- 세 사례를 다시 나열한 요약 표는 새 정보가 없어 제거했습니다. 대신 개념 질문과 특정 프로그램의 동작 확인을 구별하는 판단을 남겼습니다.
- 코드란 프로그램이 할 일을 적어 둔 내용으로 설명합니다. CSV는 행·열과 엑셀로 설명하며, 슬라이더는 속도 조절 막대로 바꿨습니다.
- MCP는 직접 사용 준비를 묻는 끝 절에 한 번만 남깁니다. Electron·ASAR·IPC·CLI·native와 doctor는 본문에서 제외했습니다.
- 명령어가 사라져도 설치 선택 시 공식 시작 안내와 기본 준비 구분을 알 수 있습니다. 완결된 설치 튜토리얼인 것처럼 제목이나 문구를 쓰지 않습니다.

### 문단 역개요

- 도입: % 버튼의 궁금증, 정체, 쉬운 결과물 관람이라는 세 정보를 추가합니다.
- 계산기: 두 연산 규칙 → 실제로 보낼 요청 예시 → 프로그램 조사·재구현과 대상 버전 → 오래된 기능을 새 프로그램에 맞추는 적용 범위입니다.
- 게임: 느리게 연습하는 구체적 용도 → 속도 규칙 조사와 새 게임 → 요청 예시 → 실제 예제 진입과 속도 규칙/새 코드 경계입니다.
- 메모: 저장 위치를 묻는 가정 → 다운로드·파일명·열 → CSV 풀이 → 쓰기 실패 후속 조사와 자동 해결 한계입니다.
- AI 구별: 구체 사례를 역공학이라는 이름과 연결 → 개념 질문/실제 프로그램 질문 선택 → 파일·코드 위치와 같은 입력 대조 → 확보 자료의 범위입니다.
- 직접 사용: 관람과 분석 준비를 구분 → 공식 Notes 시작과 도구·비용 조건 → 대상 권한과 사내·고객 데이터 → 쉬운 설명을 받은 뒤 작은 예제로 요청을 확장하는 다음 행동입니다.

메모 절에서 실제 프로그램을 묻는 질문으로 넘어가고, 그 질문에서 일반 AI와의 차이를 설명합니다. 설명 대상이 익숙해진 뒤 사용 조건을 다룹니다. 기존 구현 구조부터 설치로 이어지는 설명 순서를 유지하지 않았습니다.

### 주장 소유와 경계

계산 수치는 계산기 절, 웹판·속도 규칙만 재현한 조건은 게임 절, 저장 경로와 실패 추적은 메모 절, REA 필요성·원본 복원 한계는 AI 구별 절, 비용·권한·데이터·개발 지식은 마지막 절이 소유합니다. 결말은 한 기능의 설명에서 작은 예제 제작으로 질문을 확장하는 행동만 제시합니다.

사용자 허위 경험을 추가하지 않았고, 공식 성과를 저자의 실험으로 쓰지 않았습니다. 실제 원본 전체 복제, 오류 자동 해결, 완전 오프라인을 약속하지 않습니다. 비개발자가 이해할 수 있다는 목표를 설치와 결과 검증이 항상 쉽다는 주장으로 넓히지 않았습니다.

## 미디어·화면·다음 단계

공식 카드 원본의 SHA와 파일 바이트는 이전 원본 검토 때와 같습니다. alt·caption을 쉬운 한국어로 수정했습니다. generated lead와 infographic은 not_applicable입니다. 텍스트 사례가 독자 질문과 결과를 연결해 별도 이미지 업로드를 추가하지 않습니다.

독립 source reviewer는 새 원고만 먼저 읽고 비개발자가 각 사례에서 요청과 결과를 구별할 수 있는지 확인해야 합니다. 이전 승인을 현재 승인으로 재사용하지 않습니다. 이후 새 source pass와 light/dark preview를 생성합니다. 브라우저 정책으로 기존 local 시각 검사는 차단되어 있으며 우회하지 않습니다. 실제 360px·1280px 검사를 완료했다고 기록하지 않습니다. ready·최종 TXT·Git 전달은 아직 남아 있습니다.

### 마지막 밀도 점검

인용 요청을 예고하기만 하는 '사용자 입장에서 요청은 이 정도로 표현할 수 있습니다' 문단을 삭제했습니다. 게임 결과 문단에서 속도 조절 기능을 다시 소개하는 첫 문장도 제거하고, 실제 Play 진입·조절 방법과 원본 전체 복원 한계만 남겼습니다. AI 구별 절은 세 사례를 다시 설명하는 문장을 지우고 역공학 정의와 REA의 도구 연결 역할 두 문장으로 줄였습니다. 독립 검토자에게 변경을 알리고 현재 파일의 재확인을 요청했습니다.

### 독립 검토 반환과 수정

독립 검토자는 '직접 분석하려면 개발용 AI에 연결해야 한다'가 CLI 단독 사용을 제외하는 표현이라고 지적했습니다. 본문을 'AI와 대화하며 직접 분석하려면'으로 한정했고 brief와 evidence C15도 같은 범위로 수정했습니다. 개발용 AI를 모든 사용의 필수 조건으로 쓰지 않습니다. CLI 설치 설명을 다시 늘리지 않고 본문이 소개하는 이용 방식만 정확히 표현했습니다. 수정 파일의 재검토를 요청했습니다.

## 수정 원고의 독립 검토 완료

독립 검토자 /root/nondeveloper_review가 원고를 먼저 읽고 사용자 요청인 비개발자 이해, 사례별 요청·조사·결과, 실제 성과의 귀속과 공식 근거를 확인했습니다. CLI 사용 범위를 바로잡은 현재 파일을 재검토한 뒤 source-level pass를 기록했습니다. source-review.md와 새 source-pass.json이 현재 원고를 설명합니다.

blog.py check는 오류 0개·경고 0개입니다. v2 기본 검사는 통과하고 실제 360px 표시가 미확인인 미디어 상태를 경고합니다. 밝은/어두운 미리보기를 같은 경로에 갱신했습니다. HTML 정적 확인에서 미리보기 H1은 1개이며 설치 명령 블록은 없습니다. local-preflight-status.json에 새 미리보기 해시와 시각 검사 미완료 상태를 기록했습니다. 원고·brief·evidence를 source pass 뒤에 변경하지 않았습니다.

이번 요청의 원고 수정과 미리보기 갱신은 완료했습니다. 전체 발행 절차의 화면·CDN·최종 TXT·Git 게이트는 이전과 같이 남아 있으며, reviewing을 유지합니다. 브라우저 정책을 우회하지 않았고 사용자에게 같은 차단을 해결하라는 확인을 반복 요청하지 않았습니다.

## revision 3: 그림을 통한 설명 보강

사용자가 스크린샷이나 그림이 더 필요하다고 요청했습니다. 텍스트만으로 충분하다는 이전 미디어 판단을 철회했습니다. 이전 원고·원고 승인·media/workflow는 history/revision-2/에 보존했고 reviewing을 유지합니다.

본문 주장은 바꾸지 않고 계산기 조사·재구현 문단 뒤와 공룡 속도 조절·원본 복원 경계 뒤에 figure 지시문을 추가했습니다. 첫 그림은 AI 질문→REA 조사→AI 제작의 역할 구분을, 두 번째는 자동으로 빨라지는 기존 웹 게임과 속도를 조절하는 새 교육용 게임의 차이를 설명합니다. 첫 그림은 2:3, 두 번째는 1:1로 설계해 모바일에서 가로 3열의 작은 글씨를 피합니다. 정확한 caption·alt·문자열과 claim ID는 brief와 infographic/copy-map.json에 고정했습니다.

공식 docs의 rea-showcases.png도 직접 열었으나 DX-Ball·Notion·TH04의 작은 그림 모음이라 현재 계산기·공룡 사례를 설명하는 자료로는 적절하지 않았습니다. 실제 UI 캡처를 확보했다고 쓰지 않습니다. 과거 로컬 브라우저 보안 정책 차단을 우회하지 않습니다.

원고의 도입·제목·절 구조와 사실은 revision 2에서 유지했습니다. analyzer는 prose-revision-3.txt입니다. 신규 인포그래픽은 max-txt2img로 생성하고 dev-log-infographic-validation으로 독립 검토합니다. source pass를 먼저 갱신한 뒤 최종 미디어를 제작합니다.
