# 기획: REA란? 메모 앱으로 이해하는 소프트웨어 역공학

## 현재 요청과 독자

사용자는 앞선 원고의 표현은 자연스러워졌지만, 무엇을 했는지와 CSV·내보내기 코드가 왜 나오는지 이해하기 어렵다고 했습니다. 이번 요청은 문장 교정보다 설명 구조의 개편에 해당합니다. 대상 독자는 REA가 프로그램 내부를 조사하는 도구라는 정도만 아는 비전문 독자입니다. 메모 앱의 내부 구조나 CSV 지식은 전제하지 않습니다.

- 익숙한 상황: 완성된 앱을 보고 그 기능을 어떻게 구현했는지 궁금합니다.
- 모르는 점: REA에 무엇을 주며, REA가 무엇을 찾아주고, 그 결과로 무엇을 알 수 있는지 모릅니다.
- 한 권고: 소스가 있는 공식 Notes 예제로 기능 하나를 조사하고 찾은 코드와 결과를 확인합니다.
- 유용한 결과: 앱 파일 → REA가 찾은 요청/처리 코드 연결 → 소스에서 확인한 저장 동작 → 함수 실행 확인을 구별할 수 있습니다.
- 보유 메시지: 이번에 한 일은 메모 앱의 내보내기 구현을 조사한 것이며 CSV 변환은 그중 한 코드의 동작을 확인한 보조 단계입니다.
- 의도적으로 제외할 것: 전체 도구 기능 목록, 바이너리 복원 실습, MCP 클라이언트별 설치법, IPC 내부 용어·상태 수치의 긴 해설, CSV 규격 튜토리얼, 통제하지 않은 AI 성능 우열입니다.

## 설명 순서와 질문 지도

도입은 완성된 앱의 구현이 궁금한 상황 → REA의 역할 → 공식 소형 예제를 권고 → 조사한 기능 하나를 밝히는 순서입니다. 설치보다 먼저 조사 목적과 결과를 설명합니다.

| 독자 질문 | 소유 절 | 제공하는 새 정보 |
|---|---|---|
| 무엇을 알아내는 도구인가요? | REA는 앱에서 무엇을 찾아줄까? | 역공학의 의미, REA와 AI의 역할, 이번 예제는 소스가 있다는 범위입니다. |
| 정확히 무엇을 했고 무엇을 알아냈나요? | 메모 앱을 분석해 알아낸 것 | 입력 폴더, 실제 연결 분석, 수동 원본 대조, 저장 위치·이름·열·형식입니다. |
| 갑자기 CSV는 왜 확인하나요? | 찾아낸 코드도 실행해 확인하기 | 저장 기능 안에 있는 변환 함수를 실행해 설명과 실제 출력을 대조한 목적입니다. |
| 같은 실험을 하려면 어떻게 하나요? | 같은 예제를 직접 분석하는 방법 | 버전·환경·명령 2개·출력 확인, AI 연결 경로, 대상별 준비물·자료·비용의 범위입니다. |

제목은 'REA란? 메모 앱으로 이해하는 소프트웨어 역공학'입니다. 설치 방법보다 개념과 실제 조사 과정을 먼저 이해하려는 이번 독자 요구를 반영합니다. 검색량이나 순위를 새로 측정하지 않았습니다.

## 실제 실험과 범위

실험은 기존 artifacts/qa-v2/revision-2026-10-24/의 원본을 그대로 사용합니다. 실행 주체는 내부 evidence에서 Codex로 기록합니다. 사용자 지시에 따라 본문에는 수행 주체를 별도로 표기하지 않으며 사용자 개인 경험으로 바꾸지 않습니다.

- macOS arm64 / Node.js 26.0.0 / npm 11.12.1 / REA 6.7.0입니다.
- 소스가 있는 6파일 예제를 CLI로 읽었습니다. JS 4개·해석 실패 0개·요청과 처리 코드 연결 1개입니다.
- REA의 연결 결과와 원본 renderer/preload/main/csv를 대조해 저장 경로와 형식을 확인했습니다. 한국어 결과 표는 REA 원출력이라고 제시하지 않습니다.
- 원본 toCsv의 5개 입력을 고정 예상 문자열 및 Python csv.reader 결과와 비교했습니다. 실제 결과는 유지하며 본문에는 대표 출력만 남깁니다.
- Electron 앱 실행·실제 다운로드 폴더 쓰기·실행 파일에서의 소스 복원·AI A/B 비교는 하지 않았습니다. 이 조건은 해당 주장 가까이에 구체적으로 둡니다.

## 미디어와 절차 화면 결정

기존 검증 이미지 3장의 바이트를 유지합니다. 공식 lead는 도구 관계를 보여 줍니다. 저장 흐름 그림은 이번 조사의 결과인 앱 내부 처리 순서를 보여 줍니다. CSV 그림은 조사 결과의 일부를 함수 실행으로 대조하는 절에서만 사용합니다. 그림이 REA의 분석 자체나 실제 앱 실행 화면으로 읽히지 않도록 주변 문장에서 구별합니다.

파일별 세부 표와 main.js 코드 블록, 5개 CSV 입력별 상세 표는 원본 evidence와 이전 원고에 보존하고 현재 공개 본문에서 덜어냈습니다. 사용자는 글 전체의 이해를 요청했으므로 근거 보존을 본문의 모든 기술 세부 유지로 해석하지 않습니다. 기존 명령 2개와 대표 CSV 실제 출력은 동일합니다.

터미널 실험의 입력·명령·출력이 본문에 있으므로 미실행 GUI 스크린샷은 만들지 않습니다. 명령은 설명을 이해한 뒤 선택적으로 따라 할 수 있도록 마지막 절로 옮깁니다. 신규 이미지나 공유 CSS·스킬 편집은 없습니다.

현재 수정 원고는 reviewing입니다. 현재 원고에 대한 발행 승인은 없으므로 공개 글과 티스토리 편집기는 수정하지 않습니다. 기존 URL·게시일·카테고리는 유지합니다.
