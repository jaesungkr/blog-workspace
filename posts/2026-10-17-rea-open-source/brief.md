# 기획: REA 사용법: 메모 앱 분석으로 확인한 기능과 한계

## 현재 요청과 독자

2026-10-24 사용자가 기존 공개 REA 글의 개선을 승인하고 dev-log-rich-post-workspace-v2를 명시했습니다. 본문에는 Codex 수행 표기를 넣지 않도록 요청했습니다. 중립적인 '실험에서는'으로 서술하며 사용자 경험을 만들지 않습니다. 내부 근거와 실행 로그의 actor는 Codex입니다.

독자는 AI에 질문해 본 적은 있으나 REA나 역공학은 처음 접하는 사람입니다. 앱의 버튼이 어떤 코드를 실행하는지 확인하고 싶은 상황을 출발점으로 삼습니다. 설치 전체를 따라가는 MCP 튜토리얼이나 범용 앱 복제 안내를 약속하지 않습니다.

- 익숙한 상황: 내보내기 버튼의 저장 위치와 파일 내용을 알고 싶습니다.
- 모르는 점: 화면의 요청과 실제 처리 코드를 연결해 확인하는 분석 도구의 쓰임새입니다.
- 한 권고: 공식 소형 Notes 예제로 기능 하나를 분석하고, 변환 함수에 작은 입력을 넣어 설명을 검증합니다.
- 유용한 결과: 근거 위치가 있는 설명과 실행 결과를 구별하고 자신의 앱에 물을 질문을 정할 수 있습니다.
- 보유 메시지: REA는 조사할 코드 관계를 정리하며, 설명이 맞는지는 실제 입력과 출력도 대조해야 합니다.

## 설명 순서와 질문 지도

도입은 내보내기 저장 위치 질문 → REA의 평이한 정체 → 작은 예제라는 첫 행동 → 실제 분석 및 출력 대조의 범위로 이어집니다.

| 독자 질문 | 소유 절 | 제공하는 새 정보 |
|---|---|---|
| 무엇부터 실행하나요? | 메모 앱 하나로 시작하기 | 예제 파일, 환경, 버전 고정 CLI 명령, 출력 성공 확인입니다. |
| 저장 위치는 어떻게 알았나요? | 내보내기 버튼에서 저장 코드까지 | 파일별 역할, 요청 연결, main.js 근거, 정적 분석 범위입니다. |
| 설명이 맞는지 어떻게 확인하나요? | 쉼표가 들어간 메모도 그대로 저장될까? | 5개 고정 입력의 문자열 및 CSV roundtrip 대조입니다. |
| 그냥 AI에 파일을 주면 안 되나요? | 일반 AI에게 파일을 읽히면 어떨까? | 작은 소스의 직접 읽기와 REA 관계 정리 역할, 통제 비교가 아님을 구분합니다. |
| 어떤 프로그램에 써볼까요? | 어떤 앱부터 맡기면 좋을까? | 관람/소스/실행 파일의 준비물 차이와 권한·비용·자료 범위입니다. |

## 직접 실험과 범위

- 프로필 evidence-rich, CLI 정적 분석 및 실제 함수 실행입니다. MCP 등록, 사용자 설정 변경, 전체 Electron GUI 실행, 상용 앱 복제는 하지 않았습니다.
- macOS arm64 / Node.js 26.0.0 / npm 11.12.1 / rea-agents 6.7.0입니다.
- 분석한 공식 예제는 6파일, JavaScript 4개, parse_failures 0, 요청/handler 연결 1개입니다. main.js와 csv.js는 원본을 읽어 저장 목적지·함수 내용을 확인했습니다.
- 공식 쉼표/따옴표 예제에 한국어·줄바꿈·빈 목록을 추가했습니다. 예상 문자열을 고정하고 원본 toCsv 함수의 결과와 비교했으며 Python csv.reader로 원래 값 복원을 확인했습니다.
- AI 모델 또는 REA의 우열 벤치마크, 처리 속도·정확도 상승, 파일 저장 성공은 주장하지 않습니다. 정적 코드가 경로를 지정한다는 것과 함수 문자열 결과만 검증합니다.
- 검증 주체는 내부 evidence에서 Codex로 기록하며, 본문은 사용자의 직접 경험으로 귀속하지 않습니다.

## 미디어 결정

공식 lead 한 장을 재사용합니다. 기존 계산기/게임 생성 그림은 현재 중심 사례와 맞지 않아 본문에서 제외하되 과거 파일은 보존합니다. 별도 infographic은 not_applicable입니다.

CLI 진입은 복사 가능한 명령과 작업 폴더로 식별되고, 선택할 GUI 필드가 없습니다. 성공 상태는 ok/parse_failures와 실제 텍스트 출력으로 설명하므로 터미널 캡처를 더하면 같은 내용을 중복합니다. Electron 창은 실행 범위가 아니므로 캡처하지 않습니다. 신규 업로드 없이 기존 lead의 정확한 native block을 재관찰·결합하는 방식을 우선 검토합니다. remote binding은 source pass와 구체 원고에 대한 author approval 이후 수행합니다.

## 제목과 제외 항목

선택 제목은 'REA 사용법: 메모 앱 분석으로 확인한 기능과 한계'입니다. '사용 후기'나 '앱 복제'는 실행 범위를 넓게 오해하게 하므로 제외합니다. 실제 검색량이나 순위를 측정하지 않았습니다.

계산기·공룡 공식 사례의 장문 재설명, 전체 도구 기능 목록, MCP 설치의 모든 클라이언트 분기, 바이너리 분석 실습, 서버 코드 복원, 보호 기능 우회는 제외합니다. 다음 행동은 같은 내보내기 코드의 실패 전달 경로를 묻는 질문 하나로 마칩니다.

현재는 수정 원고 reviewing이며 기존 공개 URL은 보존합니다. 변경 원고와 로컬 미리보기를 저자에게 보여준 뒤 특정 원고의 수정 발행 승인을 받아 기존 게시글을 갱신합니다.
