2026-10-24 prose-polish를 마쳤으며 현재 상태는 `reviewing`입니다. 일반 요약 1개와 같은 대화의 후속 답변 3개를 확보했습니다. 독립적인 article/source 검증과 최종 페이지 검증은 아직 남아 있습니다. 이 기록은 source pass, ready 또는 publication 승인을 뜻하지 않습니다.

이전 기록의 `researching / authentication_required`는 Claude Code 인증 오류로 실제 답변을 확보하지 못했던 당시 상태입니다. 그 실패는 성능 판정에서 제외했습니다. 이후 Claude 웹 실험을 완료했으므로 현재 차단 사유로 남기지 않습니다.

## 보존한 사실과 편집 범위

- 제목 `AI에게 PDF 요약을 맡겨도 될까?`와 게시 분류 `AI·개발 > AI 이해·활용`은 사용자 지정으로 유지했습니다. 도구 호환용 `Log > AI 개념 · 실전`도 유지했습니다.
- 실험 수행자는 Codex이며, Claude 웹의 새 대화에 원본 PDF 한 개를 첨부했습니다. 2026-10-24 화면 표시 모델은 `Sonnet 5.5 · 중간`이고 웹 검색은 껐습니다. 이를 사용자의 직접 체험으로 바꾸지 않았습니다.
- 183쪽짜리 2016년 공개 영문 설명서 한 개와, 요청 전에 작성한 정답 기준을 사용했습니다. 일반 요약 한 번 뒤에 같은 대화에서 질문 세 개를 순서대로 보냈으며 독립 시행 세 번으로 표현하지 않았습니다.
- q1의 숫자 8개는 모두 일치하지만 해상도까지 EB-1795F/1785W/1781W의 공통값으로 묶은 설명은 틀렸습니다. 부분 성공을 전면 성공이나 숫자 추출 실패로 바꾸지 않았습니다.
- q2는 다른 파일 제한을 충족하는 1920×1080 비인터레이스 PNG를 가정했습니다. PNG 각주를 사양표에 연결한 문서 해석이며 실제 기기 투사 실험은 아닙니다.
- q3는 정확한 dB(A) 수치를 추정하지 않은 답변입니다. PDF에서 확인하지 못했다는 판단과 제품 자료 어디에도 값이 없다는 주장을 구분했습니다.
- 숫자, 단위, 전압·동작 조건, 근삿값 표시, 원문 링크, 표의 값과 실제 답변 인용을 유지했습니다. `artifacts/experiment/*-web-answer.txt`를 읽었으며 원시 답변은 편집하지 않았습니다.
- 도구 기록의 텍스트 추출·검색을 PDF 전체 정독, OCR 정확도 또는 그림의 시각적 이해 성능으로 확대하지 않았습니다.
- 편집 파일은 `article.md`와 `audit.md`뿐입니다. Git 작업, source-pass 기록, 이미지 제작은 수행하지 않았습니다.

## 독자에게 약속한 내용과 범위

독자는 AI로 제품 설명서를 요약한 뒤 구매나 기능 사용 여부를 판단하려는 비전문 독자입니다. 표가 깔끔하다는 이유만으로 모델별 적용 조건까지 맞았다고 받아들이는 상황을 다룹니다. 먼저 요약을 받고 실제 선택에 필요한 숫자와 조건을 페이지 근거와 함께 다시 묻도록 권합니다. 마지막에는 원문 페이지에서 자신의 모델과 사용 조건을 직접 확인하도록 안내합니다.

독자가 PDF 내부 처리나 API를 안다고 가정하지 않았습니다. PC Free는 USB 이미지를 컴퓨터 없이 투사하는 기능으로, dB(A)는 소음 수준을 나타내는 단위로 설명했습니다. 비인터레이스 조건은 이번 질문에서 제외한 저장 방식을 명시하는 문장으로 풀었습니다. 모델 순위, 다른 제품 추천, OCR 제품 비교, API 구현과 가격 비교는 다루지 않습니다.

제목이 만든 질문과 본문의 담당 절은 다음과 같습니다.

| 독자 질문 | 담당 절 |
|---|---|
| 어떤 PDF를 어떻게 확인했는가? | 183쪽 설명서, 요약 한 번과 후속 질문 세 번 |
| 숫자를 맞혔으면 설명도 믿어도 되는가? | 숫자 표 아래에서 발견한 모델 혼동 |
| 작은 각주까지 적용할 수 있는가? | PNG 파일의 허용 크기를 바꾸는 각주 |
| 없는 수치를 만들어 내지는 않는가? | 팬 소음이 줄어든다는 설명에 없는 수치 |
| 내 PDF에는 어떻게 물어보면 되는가? | PDF 답변을 검증하는 후속 질문 |

글의 중심 문장은 다음과 같습니다. 제품 설명서 요약을 실제 선택에 쓰려는 상황에서 모델별 표기와 각주가 문제가 되었으므로, Codex가 같은 PDF의 답변을 원문과 대조했고 숫자 일치와 설명의 정확성이 서로 다를 수 있음을 관찰했습니다. 기존 절 순서는 이 경로에 맞아 유지했습니다.

중심 주장과 행동은 각 검증 절과 마지막 질문 절이 각각 소유합니다. 도입은 q1의 핵심 관찰만 짧게 예고하며 수치 표·원인·근거를 반복하지 않습니다. 일반 요약의 각주 누락을 채점하지 않은 규칙은 방법 절에서, 실제 후속 질문에서 각주를 찾은 관찰은 PNG 절에서 설명합니다. 별도의 포괄적인 주의사항 절은 만들지 않고 실제 투사 미실시와 자료 범위를 해당 결과 옆에 유지했습니다.

## 미디어 관련 전달 사항

기존 계획에서는 max-txt2img와 diagram-design을 검토한 뒤 원문 화면과 실제 답변을 우선하기로 했습니다. 생성 인포그래픽과 생성 hero는 추가하지 않았습니다. 원문 65·131·173쪽 화면을 확인했다는 기존 기록은 유지하되, 공개용 이미지의 독립 최종 검증으로 취급하지 않습니다.

오케스트레이터가 사양표 발췌를 lead로 사용하도록 요청했습니다. 이에 따라 `{{media:pdf-pc-free-lead}}`를 삭제하고 `hero_image`를 `assets/model-specifications-detail.png`로 바꿨습니다. 첫 검증 절의 `{{media:model-specifications}}`는 유지했습니다. 실제 파일과 manifest의 일치, 모바일 가로 스크롤 및 최종 페이지 읽기 검증은 오케스트레이터와 독립 페이지 검증 단계에서 확인해야 합니다.

## 재검증 결과와 남은 단계

- prose analyzer를 수정 전후에 실행했습니다. 일반 문장은 69개에서 62개로 줄었고, 관용적 발표 문구와 소제목 일반화 신호는 두 실행 모두 없었습니다. 추상 명사·대조 표현의 신호는 문맥으로 검토했으며 수치 자체를 통과 점수로 사용하지 않았습니다.
- 소제목만 읽기, 문단 경계 이어 읽기, 전체 원고를 소리 내어 읽는 방식의 점검을 마쳤습니다. 실제 인용과 제안 프롬프트를 본문의 서술과 구분했습니다.
- 실제 답변 인용 세 개가 대응하는 원시 답변의 연속된 발췌인지 재확인하고, q1 숫자 8개와 q2 조건·q3 미추정 결과를 유지했습니다.
- 독립 검증자는 이 감사 기록을 읽기 전에 `article.md`를 먼저 cold-read해야 합니다. 읽기 어려운 소제목, 반복된 결론, 부정확한 수치 부재 표현이 남았는지 확인해야 합니다.
- 현재 원고와 미디어가 맞는지 확인한 뒤 독립 source 검증, 최종 미디어·렌더링·반응형 검증을 진행해야 합니다. 마지막 문구가 반영된 산출물을 다시 생성해야 하며 이전 TXT를 전달해서는 안 됩니다.
- 작성자가 구체적인 원고를 승인하고 게시를 요청한 이후에 Tistory 게시 단계를 진행합니다. 이 prose-polish 단계에서는 상태를 `reviewing`으로 유지합니다.

## 오케스트레이터의 source freeze와 로컬 검토 인계

- 독립 검증자 /root/source_review가 원문·실제 답변·공식 PDF 재다운로드 해시를 대조하고 source pass를 반환했습니다. record_source_pass_v2.py로 이를 기록했습니다.
- 공개 미디어 4개를 원본과 대조하고 실제 로컬 페이지에서 확인해 validated로 기록했습니다. 생성 hero·생성 인포그래픽은 해당하지 않습니다.
- 로컬 밝은/어두운 1280·360·390·768px 화면 모두 페이지 가로 넘침 0px, 이미지 4개 로드, H1 1개입니다. 전체 360px 밝은 화면과 데스크톱·어두운 화면의 대표 영역을 읽었습니다. 지연 로딩 이미지는 실제 목차 이동과 스크롤로 불러온 뒤 캡처했습니다.
- 360px에서 ECO 이미지의 가로 스크롤을 실제로 움직여 문구 가독성을 확인했습니다. 스크린샷과 표만 개별 스크롤되며 본문은 화면 폭 안에 있습니다.
- 검토용 HTML에는 로컬 최종 이미지를 내장하고 요청한 게시 분류를 머리말에 표시합니다. 출판 본문 텍스트는 바꾸지 않습니다.
- 현재 인계는 작성자 검토용입니다. 작성자 승인·게시 요청, Tistory 원본 첨부 블록·원격 미디어, 독립 최종 페이지, 실제 게시 검증은 이후 단계이며 final-page 또는 ready 승인을 대신하지 않습니다.
