# 작성 계획

- 독자: 제품 설명서 PDF를 AI로 요약한 뒤 구매나 사용 가능 여부를 판단하려는 비전문 독자입니다.
- 검색 의도: AI가 긴 PDF의 표와 작은 예외까지 정확히 읽는지 확인하고 싶습니다.
- 유지할 메시지: 요약을 받은 뒤 모델명·숫자·적용 조건·문서에 없는 항목을 페이지 근거와 함께 따로 확인합니다.
- 시작: PDF와 질문을 함께 주고 답마다 근거 페이지와 원문 구절을 요청합니다.
- 실험: 공개 제품 설명서 한 개를 Claude 웹 새 대화에 첨부하고 일반 요약을 받은 뒤, 같은 대화에서 검증 질문 세 종류를 순서대로 묻습니다. 정답 기준을 먼저 기록하며 웹 검색은 끕니다. 최초 요약에 요청하지 않은 항목이 빠진 것은 오답으로 계산하지 않습니다.
- 실제 수행자: Codex가 Claude 웹에서 PDF를 첨부하고 답변을 검증합니다. 사용자의 체험으로 서술하지 않습니다.
- 범위: 한 문서와 한 모델의 관찰입니다. 모든 PDF 또는 다른 모델 성능을 일반화하지 않습니다. 같은 대화의 후속 질문이므로 독립 시행 간 비교가 아닙니다.
- 첫 화면: 긴 PDF를 요약한 답변을 실제 제품 선택이나 기능 사용 판단에 쓰려는 상황을 제시합니다. Epson이나 실험 결과를 먼저 꺼내지 않고, 요약 이후 원문 대조가 필요한 이유를 설명한 뒤 제품 설명서를 선택한 이유로 이어갑니다.
- 시각화: max-txt2img와 diagram-design을 검토했습니다. 이 글의 독자 질문은 생성된 구조 그림보다 원문 캡처와 실제 답변의 직접 비교로 더 잘 해결됩니다. 각 시험 절에 원문 화면 → AI 답변 → 대조 판정을 배치합니다. 데스크톱은 나란히, 좁은 화면은 읽는 순서대로 배치합니다. 추가 인포그래픽은 생략합니다.
- 생성 hero: 공식 PDF 일부를 lead로 사용하므로 생략합니다.
- 제외: 모델 순위, OCR 제품 비교, API 구축, 가격·구매 추천을 다루지 않습니다.
- 분류: 사용자가 지정한 게시 카테고리 AI·개발 → AI 이해·활용을 우선합니다. 저장소 도구용 메타데이터는 기존 Log → AI 개념 · 실전입니다.

## 작성자 피드백에 따른 두 번째 구성

사용자가 Epson의 등장 이유, 실험의 목적, 어색한 말투와 설명 없이 바뀌는 화제를 지적했습니다. 독자는 PDF 요약의 활용법을 보러 온 사람이므로 첫 화면에서는 제품명을 소개하지 않고 요약을 실제 선택에 쓰기 전에 확인할 내용을 설명합니다. 이어 제품 설명서가 정답 대조에 적합한 이유와 이 PDF를 고른 이유를 밝힙니다. 두 비교 모델의 짧은 이름을 미리 정의하고, q1에서 다른 두 모델이 등장하는 것은 실제 AI가 추가 설명을 붙였기 때문임을 인용 전에 설명합니다. q2는 숫자 찾기에서 사용 조건 적용으로 이어지는 질문으로 소개하고, q3는 문서 안에 답이 있는 질문에서 없는 질문으로 넘어가는 이유를 먼저 설명합니다. Codex와 Claude의 역할도 구분합니다. 사실·실험·미디어 바이트는 그대로 유지합니다.

## 세 번째 수정: 실험 결과로 마무리

작성자가 후속 질문 예시 절을 빼고 제목의 질문에 답하는 결과 정리를 요청했습니다. 마지막 절을 세 시험의 관찰과 판정을 함께 보여 주는 표로 바꿉니다. 숫자 추출 성공과 설명 오류를 구분하고, 각주 적용·수치 미추정을 해당 질문의 성공으로 한정합니다. 한 문서·한 Claude 대화의 결과라는 범위와 스캔/실기 미시험은 유지합니다. 원고의 나머지 절과 실제 인용·미디어는 수정하지 않습니다. 게시 직전 원고 변경 요청이므로 공개 게시를 수행하지 않고 갱신된 검토본을 먼저 제공합니다.
