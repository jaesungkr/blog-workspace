현재 후보는 reviewing이다. 사용자가 딱딱한 표현과 의미 없는 정리 문장, 제목·소제목, 이미지의 불필요한 해명을 지적했다. 2차 검수 기록은 이전 원고에 대한 것이며, 이번 편집의 승인으로 취급하지 않는다. 직전 원고와 source-pass를 revision-polish-3에 보존했다.

- 똑같은 권고를 반복하던 도입의 마지막 문단과 ‘함께 비교할 이유입니다’ 등을 삭제했다. 모델별 장점은 인물 외형과 동작을 나눠 지정하는 상황, 제품 사진과 문서를 함께 넣는 상황으로 풀었다. 개인 체험·대화·성공률은 만들지 않았다.

- 보호: 버전·날짜·길이·해상도·API 요율·순위·공식 링크·제공사 제약. 의미 없는 요약 삭제와 자연스러운 호흡을 우선하며, 모든 절에 정리 문장을 새로 붙이지 않는다.
- 최근 동일 하위 범주 완성글 네 편의 비교 기록과 human-prose-benchmarks를 적용했다. 인물의 말투를 흉내 내거나 가상의 사용 경험을 더하지 않았다.

## 이해와 구성 점검

독자는 사진이나 설명으로 첫 숏폼을 만들고 싶지만 생성 모델과 사이트 이름이 섞여 선택하기 어렵다. 모델과 이용 공간을 구분하고, 독립 평가의 선두와 기능별 선택을 분리해 실제 이용 사이트를 고르게 한다. 제공사 기능 소개·독립 평가 관측·편집 판단을 구분했다. 실제 생성 시험은 수행하지 않아 성공률·한국어 대사·대기 시간은 단정하지 않는다. 비용 계산은 공식 요율에 가정한 재시도 횟수를 곱하는 산술 예시로 명시했다.

제목 질문의 소유: 모델/사이트(첫 절), 선두(평가 절), 장단점(세 모델 절), 주요 사이트(서비스 절), 용도/비용(마지막 절). 인접 주제인 API 구축·모델 설치·촬영 강좌·시장 점유율은 제외했다. 각 실용 권고는 영상 입력·수정·장면 연결·아바타·생성 비용에 연결되어 일반 생산성 조언으로 확장하지 않는다.

## v2 voice-and-density / prose polish

- 독자 계약: 첫 영상 제작 도구를 찾는 개인 한 명. Higgsfield는 다수 모델을 살펴볼 출발점이라는 권고이며, 월 구독이나 품질 우승을 권하지 않는다.
- 첫 화면: 사진→제품 영상/촬영 어려운 장면이라는 대상 고유 상황에서 시작하고 생성 AI의 정체와 비교 출발점을 제시했다. 조사 과정·방법론의 방어 문구·목차 안내를 넣지 않았다.
- 제목/소제목: ‘핵심 메시지’ 템플릿을 삭제하고 모델/사이트 구분→평가 선두→세 모델 장단점→서비스→비용과 첫 선택으로 작성했다. 최근 글의 ‘A vs B - 모델 비교’ 틀은 복제하지 않았다.
- 검토한 동일 하위 범주 완성글: 2026-10-25-kimi-k3-1-pro-strengths-vs-opus-5-5(published), 2026-10-25-gemini-4-argon-vs-gpt-6-astra(published), 2026-09-30-gpt-6-1-sol-vs-opus-5-5(ready), 2026-09-29-opus-5-5-vs-gpt-6-astra(ready). fallback 없음.
- 비교적 긴 문단은 실제 기능 설명·근거·제약을 소유한다. 공식 수치 전체와 API 명령·실험 없는 성공률은 evidence로 제한했다.
- 수정: ‘구독 서비스는 ... 차감하고’라는 전체 일반화→‘크레딧을 차감하는 경우가 많고’로 범위를 좁혔다. 무제한 경계는 공식 대기열 문서 링크와 구체적 조건으로 보강했다.
- 수정: 일반적인 ‘원하는 모델을 고르라’는 세 문장 맺음→공개 평가를 보는 상황과 원본 수정이 필요한 상황의 판단을 간단히 종합했다. 앞의 작업 절차를 다시 나열하지 않았다.
- 링크 보강: Seedance 제공 경로와 Hailuo의 H3 설명은 각각 공식 모델 목록과 발표에 연결했다.
- 보호한 내용: 2026-10-26 확인일과 Arena 9/21 갱신일, Kling4 미등재, 점수구간 겹침, API/구독 구분, Wan 문자·음질 제약, Sora 종료일, 산술 예시의 비실험성.
- 분석기: artifacts/prose-before.json, prose-after.json을 문구 목록으로 보존했다. 신호 개수는 통과 기준으로 사용하지 않았다.
- 문단 연결: 혼동→정의→평가 기준→모델별 기능→이용 서비스→상황별 선택→재생성 비용 순서가 유지된다. 원본 수정·한국어 글자·대사·권리는 구체적 결과물을 점검하는 범위에서만 남겼다.
- 수사 반전(A가 아니라 B), 방어형 종합 부정, 명사형 판단 라벨을 사용하지 않았다.

## 로컬 렌더에서 발견한 수정

360px에서 3열 표의 마지막 열은 표 안의 가로 스크롤로 읽을 수 있었다. 페이지 자체의 가로 넘침은 없었으나 처음 읽는 사람이 마지막 열을 놓칠 수 있어 첫 표 앞에 표를 좌우로 미는 안내를 한 번 추가했다. 일반 본문과 hero를 가로 스크롤시키지 않는다. 이 문구 변경 후 자연스러운 문단 연결을 읽고 prose 분석기를 갱신했으며 독립 source 재검수를 요청했다. 원고 승인 전의 실제 수정이므로 기존 source-pass를 새 통과 기록으로 갱신한다.

## 로컬 사전 점검과 검토본 전달

최신 원고의 source-pass를 /root/source_review 이름으로 기록했다. hero는 독립 pass를 받은 validated 미디어이며 v2 검사와 blog.py 검사를 통과했다. light/dark 각각 1280·360에서 실제 브라우저 캡처 후 전체 구도·본문·표의 마지막 열·목록을 확인했다. 표는 컨테이너 내부에서 좌우로 이동하며 본문 가로 넘침은 없다. 상세 관측은 artifacts/qa-v2/local-preflight-review.md와 local-preflight-measurements.json에 기록했다. 최종 렌더 문장의 연결과 맺음을 다시 읽었으며 추가 원고 수정이 필요한 결함을 발견하지 못했다.

사용자에게는 이미지 바이트를 포함한 독립 HTML 검토본을 제공한다. 공개 원고 승인과 게시 지시를 아직 받지 않았으므로 status reviewing을 유지하고 원격 첨부나 게시를 실행하지 않았다. 이번 Git 저장은 검토 후보의 보관이며 ready/published 판정을 뜻하지 않는다.

## 사용자 최종 폴리싱 요청 반영(2차)

기존 검수는 이전 후보에 관한 기록이다. 사용자에게서 서론의 급한 전환과 문단 연결 부족을 지적받아 원고를 재검수한다. reviewing을 유지하고 이전 source-pass와 article을 artifacts/qa-v2/revision-polish-2/에 보존했다.

- 도구 이름 나열 직후 추천이 나오는 문제를 보완했다. 만들고 싶은 영상, 도구 선택의 어려움, 모델과 사이트의 혼동, 한곳에서 비교할 이점을 차례로 연결한 뒤 기존 추천 문장을 유지했다.
- 평가가 보는 생성 품질과 실제 제작에서 필요한 원본 활용을 연결하고, 사진에 움직임을 더하는 작업과 기존 배경을 수정하는 작업의 차이를 설명했다.
- Wan의 중복 순위는 평가 절, API 요율은 비용 절에서 설명하도록 정리했다. 다양한 자료 입력, 제품 소개, 정확한 글자와 음질의 제약이 이어지도록 수정했다.
- 사이트 목록 뒤의 설명에는 복수 모델 선택, 카메라 연출과 원본 수정, 현재 이용 가능성이라는 각각의 읽을 이유를 제시했다.
- 선택표 뒤에 생성·채택·편집 과정을 보완했다. 재생성 횟수, 채택한 클립 비용, 실제 사용 장면의 품질 요구가 이어지도록 수정했다.
- 모든 공식 버전·수치·날짜·URL과 표 값, 평가 조건, Kling 4 미등재, API와 구독료 구분, Wan 문자·음질 제약, Sora 종료일, 비실험 산술 예시를 보호했다. 실제 저자의 사용 경험은 추가하지 않았다.
- 동일 하위 범주의 완성글 네 편은 1차 검수 목록과 같으며 이번에도 제목과 소제목을 다시 확인했다. 대상 글의 제목과 소제목은 바꾸지 않았다.
- 기존 hero는 보존하고 자료가 클립과 완성 영상으로 바뀌는 과정을 설명하는 그림을 추가한다. 생성 자료와 독립 그림 검수는 artifacts/qa-v2/infographic/에 기록한다.

## 2차 후보의 원고·그림·실제 화면 재검수

원고 독립 검수자 /root/source_review가 article.md를 새로 읽고 pass를 반환했다. 사용자가 호평한 추천 문장, 모든 공개 링크와 표 값이 유지됨을 대조했다. C19의 주장 표 등록과 그림 캡션도 추가 확인한 뒤 최신 source-pass를 기록했다. 원고의 첫 세 문장 안에 추천을 압축하는 일반 지침보다 사용자가 요구한 충분한 서론을 우선했다.

추가 그림은 max-txt2img 경로와 내장 image_gen으로 생성했다. v1은 320px에서 한글이 약 8px로 보여 독립 검수자 /root/hero_review가 revision_required로 반환했다. 한 번의 수정 생성으로 세 라벨을 확대하고 화살표 위치를 조정했다. 기존 대표 이미지는 변경하지 않았다.

최종 후보는 assets/ai-video-workflow-v2.png, 1448×1086, SHA-256 dd38baef647a28f70504a2549aed6e28751603ded5e5100f073f80ffa7acdc9e이다. 독립 검수에서 원본·320px 표시·라벨과 연결부 확대를 확인하고 pass를 반환했다. 생성 래스터이므로 원본 폰트 설정은 알 수 없으며 관측된 글자 높이는 56/58/58px, 320px 표시 높이는 약 12.4~12.8px이다. 문자가 그림을 압도하지 않고, 화살표와 글자가 닿지 않으며, 같은 제품과 3단계의 관계가 유지된다. 원본과 수정 프롬프트, 생성 기록, v1 실패와 v2 검수는 artifacts/qa-v2/infographic/에 보존했다.

최신 원고와 v2 그림을 넣어 light/dark 각각 1280×900·360×800에서 다시 렌더하고 캡처했다. 본문 가로 넘침은 없고, 두 이미지가 로드되며, H1과 목차 연결이 정상이다. 실제 도입·그림과 캡션·비용 문단·표 오른쪽 끝·맺음과 참고 자료를 열어 확인했다. 원본 래스터의 실제 게시 폭은 데스크톱 916px, 모바일 320px이다. 검토본 HTML은 같은 이미지 바이트 두 개를 내장해 다시 만들었다. 이 검수는 로컬 검토 후보에 대한 것이며 게시 상태는 reviewing으로 유지한다.
