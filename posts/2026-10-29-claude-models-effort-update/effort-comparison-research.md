# 동일 모델 Effort 비교 보강 근거

확인: 2026-10-29. 유료 테스트 미실행. 새 수치/결과를 생성한 것이 아니라 공개된 공식 실험을 검증함.

## 1순위: 결과물 차이가 보이는 Opus 5.5 운동 기록 앱

출처: https://claude.dev/blog/spending-your-effort/
제목: Using Claude Code: Spending your effort
작성자: Thariq Shihipar / Engineering
발표: 2026-09-25
공식 Claude Code 문서 https://code.claude.com/docs/en/model-config#choose-an-effort-level 에서도 이 글로 연결한다.

### 정확히 확인된 실험 범위
- 글은 같은 작업을 Opus 5.5에서 여러 Effort로 실행했다고 명시한다 (Building with effort).
- 첫 예시 ‘Underspecified build task’: 요구사항을 자세히 정하지 않은 앱 제작.
- 요청: “build a personal fitness and workout tracker app” (9 words; 직접 인용 허용범위 내).
- 비교 결과는 Low / Medium / High / Max 4개. 이 예시에는 xhigh 수치가 없으므로 보충·추정하지 않는다.
- 원문 공개 소요 시간: Low 1.5분 / Medium 4분 / High 11분 / Max 67분.
- Low 결과: 기록(log)과 간단한 그래프.
- 높은 단계에서 앱이 복잡하고 상세해지고 AI가 스스로 결정하는 사항도 많아진다.
- Max 결과에 heat chart(운동 기록을 색으로 보여주는 히트맵)가 추가됐다고 원문 명시.
- Medium/High 개별 기능은 원문 서술에 정확히 나뉘어 있지 않다. 스크린샷에서 보이지 않은 기능을 상상해 채워넣지 말 것.
- 이 수치는 해당 시연의 소요시간이며 평균 벤치마크, 동일하드웨어 반복실험, 일반적인 속도배율로 보고하지 않는다. 원문이 이 앱 예시의 반복횟수/정확한 프롬프트 전체/Code버전/환경을 제공하지 않으므로 ‘엄격하게 통제된 성능시험’이라고 부르지 않는다.
- ‘Max가 항상 45배 느리다’, ‘성능이 N배 오른다’ 식 계산/일반화 금지.

### 권장 삽입
제목: 같은 일을 맡기면 실제로 얼마나 달라질까?
공식 작성자가 같은 Opus5.5에 운동기록앱을 요청해 단계별 결과를 공개했다는 짧은 배경.
표는 Effort / 공개된 소요시간 두 열만 (Low1분30초·Medium4분·High11분·Max67분).
옆 또는 밑 실제결과물 캡처.
Low는 간단기록과그래프, Max는히트맵까지추가해상세해졌다는설명. ‘더오래생각해답이길어진것보다, 어디까지알아서만들고확인하느냐가달라졌다’는 해석 가능.
결론: 초안을빨리받고함께다듬고싶으면Low도유효; 한번에더완성된결과물을원하면높은단계를고려. 다만더높을수록자기판단이추가되므로원치않는범위확대도가능.
원문 공개 시연의 시간이며 작업마다 달라진다는 짧은 한 문장이면 충분; 면책문구장황하게추가하지않기.

## 보조 후보 A: 실제 성공률 비교 (같은 Opus5.5)

동일 위 출처, Terminal-Bench3.0 내부실행, 과제마다5회시도.
`mvcc-lsm-compaction`: 크래시보고서를바탕으로저장엔진버그고치기,기존압축기능을깨뜨리지않아야함.
- Low: 0/5 통과, 시도당약1분. 빌드/문제재현전에수정,추가한테스트가원래버그를잡는지검증하지않음.
- xhigh: 4/5 통과, 약11분. 먼저크래시재현,기준구현과비교하는랜덤테스트,불완전수정에서테스트가실패하는지확인.
조건: 글의figA는70과제(4GPU제외),Opus5.5는약3주뒤실행,응답128kcap,GitHub/PyPI접근없음. 저자는내부실행과공개leaderboard조건이달라수치가같지않을수있다고설명. Fable안전개입off특례는Fable한정;Opus작업으로혼동금지.
주의: 특정과제5회사례라전체성공률0%→80%라고일반화불가. 필요하면이예시하나만두행표로구체검증차이를보여줄수있으나운동앱보다낯설다.
