# 복사해서 시작하는 네 가지 지시

아래는 실제 서비스에 실행하지 않은 지시문 초안입니다. 먼저 프로젝트 폴더와 파일 쓰기 권한을 확인합니다. 예시 파일명·화면 요구사항·대화 이름은 자신의 작업에 맞게 바꿉니다. 파일 저장에 필요한 승인이 나타나면 범위를 확인하고 처리합니다. 권한을 우회하거나 보안 설정을 낮추지 않습니다.

## 1. 처음 한 번: 폴더와 운영 규칙 준비

```text
이 로컬 프로젝트에서 AI 작업과 내 판단 대기를 분리하려고 합니다.
현재 프로젝트의 실제 절대 경로와 적용되는 프로젝트 지침을 먼저 확인해 주세요.
기존 파일을 덮어쓰지 말고 ai-work/README.md, ai-work/tasks/,
ai-work/inbox.md를 준비해 주세요. 이미 있으면 내용을 읽고 충돌부터 알려 주세요.
README에는 아래 규칙을 저장하고, 실제 저장한 파일 경로를 알려 주세요.
이번 요청에서는 작업 카드 양식과 빈 대기함까지만 만들고 제품 코드는 바꾸지 마세요.

작업마다 카드 하나를 둡니다. 처음에는 코드 수정 범위가 겹치지 않는 두 작업만 시작합니다.
작업 대화는 자기 카드만 갱신하고, 검토 대화는 카드를 읽어 inbox.md만 다시 만듭니다.
모든 대화는 같은 실제 로컬 폴더를 사용해야 합니다. 다른 worktree나 복제본은 제외합니다.
카드에는 ID, 목표, 상태, 돌아갈 대화 이름, 허용 범위, 멈춘 지점, 검증 상태,
질문, 선택지, 추천과 근거, 확인할 자료 위치, 다음 행동, 완료 조건, 갱신 시각을 씁니다.
판단이 필요하면 대기 시작 시각, 마감, 다른 작업을 막는지도 적습니다.
상태는 AI 작업 중 / 내 판단 대기 / 외부 요인 대기 / 완료로 나눕니다.
이미 허용된 조사는 AI 작업 중에 둡니다. 사람의 판단이 필요하면 질문을 저장하고
해당 작업을 멈춘 뒤 카드 경로를 알려 주세요. 답 없이 같은 시도를 반복하지 마세요.
대기함에는 내 판단 대기만 모으고, 다른 작업을 막는 항목, 가까운 마감,
오래 기다린 순서로 정렬합니다. 같은 조건이면 ID 순서로 정렬합니다.
대기함에는 갱신 시각과 ID·질문·카드/근거 위치·돌아갈 대화 이름만 적습니다.
나는 한 카드의 근거를 읽고 결정한 뒤 그 작업 대화에 결정과 재개 지시를 전달합니다.
작업 AI가 결정·상태·다음 행동을 저장하면 검토 대화에 대기함 재생성을 요청합니다.
같은 카드나 코드 파일을 여러 대화에서 동시에 수정하지 않습니다.
자동 갱신·공유 기억·자동 재개를 가정하지 마세요. README는 자동으로 읽힌다고
가정하지 않고 각 대화 시작에 읽도록 지정합니다. 기존 권한을 확대하지 마세요.
배포나 외부 전송은 하지 말고, 비밀값과 개인정보를 카드·로그에 적지 마세요.
```

## 2. 작업 시작: 로그인 대화에 붙여넣기

```text
이 대화의 작업 이름은 '로그인 수정'입니다.
현재 프로젝트의 실제 경로를 확인하고 ai-work/README.md를 먼저 읽어 주세요.
ai-work/tasks/T01-login.md가 있으면 읽고, 없으면 이 작업의 카드로 만들어 주세요.
이 카드의 작성자는 이 대화 하나입니다. 다른 카드와 inbox.md는 수정하지 마세요.

목표는 만료된 로그인 링크에서 흰 화면 대신 안내가 보이도록 하는 것입니다.
로그인 화면의 기존 만료 처리와 관련 로컬 테스트를 조사하고 최소 수정안을 준비해 주세요.
로그인 방식·권한·서버 API는 바꾸지 말고, 새 UI 선택이 필요하면 실행 전에 물어보세요.
카드에 실제로 확인한 파일, 멈춘 지점, 실행한 검증과 결과 위치, 미확인 항목,
다음 행동을 기록해 주세요. 완료 조건에는 정상 링크 로그인 유지도 넣어 주세요.
기존 지침이나 다른 작업과 수정 범위가 겹치면 수정하기 전에 알려 주세요.
내 판단이 필요하면 질문·선택지·추천 이유·근거 자료를 카드에 남기고
상태를 '내 판단 대기'로 바꾼 뒤 해당 작업을 멈추고 카드 경로를 알려 주세요.
저장되지 않았으면 저장됐다고 말하지 마세요. 이번 작업에서는 배포하지 마세요.
```

두 번째 작업 대화에서는 ID·대화 이름·목표·허용 범위를 검색 작업에 맞게 바꿉니다. 테스트 조사 T03은 세 번째 작업을 시작하는 지시가 아니라, 이미 승인한 조사라면 다시 사람의 답을 기다릴 필요가 없다는 예제입니다.

## 3. 대기함 갱신: 검토 전용 대화에 붙여넣기

```text
이 대화는 판단 대기함 검토용입니다. 작업 대화들과 같은 실제 로컬 프로젝트인지
절대 경로를 확인하고 ai-work/README.md와 ai-work/tasks/*.md를 다시 읽어 주세요.
상태가 '내 판단 대기'인 카드만 ai-work/inbox.md에 모아 주세요.
다른 작업을 막는 항목을 먼저, 그 안에서는 마감이 가까운 순서,
같은 조건이면 오래 기다린 순서로 정렬해 주세요. 마감 없음은 뒤로 두고,
그래도 같으면 ID 순서로 정렬해 주세요.
마지막 갱신 시각과 각 ID·질문·카드/근거 위치·돌아갈 대화 이름만 짧게 적어 주세요.
선택지·추천·검증 로그 등 상세 내용은 카드에서 읽도록 하고 전체를 복제하지 마세요.
질문이나 자료가 빠졌으면 지어내지 말고 누락을 알려 주세요.
카드·코드·권한을 바꾸거나 작업을 재개하지 마세요. 저장한 대기함의 경로를 알려 주세요.
```

## 4. 한 건 판단 후: 원래 로그인 대화에 붙여넣기

```text
ai-work/README.md와 ai-work/tasks/T01-login.md를 먼저 다시 읽어 주세요.
T01의 '만료 안내 아래에 링크 다시 받기 버튼을 추가해도 될까요?'에 대한 결정입니다.
버튼을 만료 안내 바로 아래에 추가해 주세요. 로그인 방식과 서버 API는 그대로 유지하세요.
현재 카드가 여전히 이 결정을 기다리는지 확인하고, 다른 질문으로 바뀌었으면 멈춰 알려 주세요.
추가로 필요한 승인이 없다면 카드에 이 결정과 다음 행동을 남기고
상태를 'AI 작업 중'으로 바꾼 뒤 허용된 범위에서 작업을 재개해 주세요.
만료된 링크와 정상 링크를 각각 확인하고 실제 실행한 검증과 결과 위치를 카드에 남겨 주세요.
미실행·실패는 그대로 적고 배포하지 마세요. 카드 저장 경로와 현재 상태를 알려 주세요.
```

이 문구를 대기함에 적어 두는 대신 **원래 작업 대화로 보내야 합니다**. 저장 확인을 받은 다음 검토 대화에 3번을 다시 보내면, 로그인 질문이 빠지고 검색 질문이 남아야 합니다.

원래 대화 대신 새 대화에서 재개하려면 기존 작업 대화가 더는 수정하지 않음을 먼저 확인합니다. 위 지시에 `이 대화가 T01의 새 단독 작성자입니다. 카드의 돌아갈 대화 이름을 [새 대화 이름]으로 바꿔 주세요.`를 덧붙입니다. 이전 대화의 기억이 자동 전달된다고 가정하지 않습니다.
