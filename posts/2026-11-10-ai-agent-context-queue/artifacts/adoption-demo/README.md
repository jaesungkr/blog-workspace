# 판단 대기함 도입 예제와 검증

이 폴더는 dev.log 글을 위해 Codex가 작성한 **가상 작업 카드와 Python 표준 라이브러리 검증**입니다. 실제 로그인·검색 앱을 개발하거나 Codex CLI·Claude Code CLI에 아래 프롬프트를 넣어 실행한 기록이 아닙니다. 사용자의 프로젝트에 이 운영 방식을 설치하지 않았습니다.

## 처음 해 볼 일

1. 파일을 읽고 쓸 수 있는 Codex 또는 Claude Code에서 **같은 실제 로컬 프로젝트 폴더**를 엽니다. 별도 worktree, 복제본, 원격 작업 공간은 같은 폴더가 아닙니다.
2. `PROMPTS.md`의 초기 지시로 `ai-work/README.md`, 작업 카드, `inbox.md`를 준비합니다. 처음에는 코드 수정 범위가 겹치지 않는 작업 두 개만 시작합니다.
3. 작업 대화마다 카드 하나를 맡깁니다. 답이 필요한 지점에서 해당 작업을 멈추고, 카드에 질문·선택지·추천·근거·다음 행동을 저장하도록 합니다.
4. 검토용 대화에 대기함 갱신을 요청합니다. 사용자는 대기함 첫 카드만 열어 맥락을 읽고 한 건을 판단합니다.
5. 결정과 재개 지시를 **그 작업을 맡긴 원래 대화에 실제로 전달**합니다. 작업 AI가 카드를 읽고 결정·상태·다음 행동을 저장했는지 확인합니다.
6. 검토 대화에 대기함 갱신을 다시 요청합니다. 방금 답한 질문이 빠진 것을 확인한 다음 다른 카드를 봅니다.

도입 완료 기준은 문서 개수가 아니라 **질문 한 건이 카드 → 대기함 → 사람 판단 → 원래 작업 대화 → 카드 갱신 → 대기함에서 제외되는 흐름을 끝까지 통과했는지**입니다. 이 예제의 T03 테스트 조사는 이미 허용된 조사를 다시 승인받지 않는 분류 대조용입니다. 처음부터 세 작업을 동시에 시작하라는 뜻이 아닙니다.

## 파일

- `PROMPTS.md`: 초기 설정, 작업 시작, 대기함 갱신, 결정 반환의 복사 가능한 지시문입니다.
- `ai-work/README.md`: 이 예제의 운영 규칙입니다. 실제 도입 때 읽히는 규칙의 본문입니다.
- `ai-work/tasks/T01-login.md`, `T02-search.md`, `T03-test.md`: 가상 입력 세 개입니다.
- `ai-work/inbox.md`: 입력 카드에서 생성한 결정 전 대기함입니다.
- `queue_demo.py`: 상태 필터와 정렬을 기계적으로 재현하고 스냅샷을 만드는 **검증용** 프로그램입니다. 독자가 설치해야 하는 제품이나 필수 자동화가 아닙니다.
- `test_queue_demo.py`: 필터·정렬·반환 조건·잘못된 입력·비변경 조건을 검사합니다.
- `snapshots/before/`, `snapshots/after/`: 결정 반환 전후 가상 스냅샷입니다.
- `decision-input.json`: 테스트에만 사용한 가상 사람 결정입니다.
- `verification.log`, `results.json`: 실제 프로그램 실행 결과입니다.
- `source-check.md`: 공식 문서로 확인한 기능, 전제, 검증하지 않은 범위입니다.

## 재현

이 폴더에서 다음 명령을 실행합니다. Python 3.9 이상, 추가 패키지와 네트워크가 필요 없습니다.

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_queue_demo
PYTHONDONTWRITEBYTECODE=1 python3 queue_demo.py
```

두 번째 명령은 이 폴더의 `ai-work/inbox.md`, `snapshots/`, `results.json`만 다시 씁니다. 실제 도구 세션을 실행하거나 채팅에 메시지를 보내거나 프로젝트 코드를 바꾸지 않습니다. 데모의 고정 시각은 재현용 가상 시각이며, 실제 실행 시각은 `verification.log`에 따로 기록합니다.

## 결과 해석

정답은 결정 전 `[T01, T02]`, T01의 결정이 작업 대화에 돌아갔다고 가정한 카드 갱신 후 `[T02]`입니다. T03은 계속 `AI 작업 중`이며 처음부터 대기함에 들어오지 않습니다. 결정이 대화에 전달되지 않았거나 다른 대화로 전달됐다는 입력은 거절해야 합니다.

이는 **명시한 운영 규칙을 코드로 옮긴 결과의 일관성**을 검증합니다. AI가 실제 세션에서 매번 지시를 따르는지, 실시간으로 파일을 공유하는지, 테스트 결과가 옳은지, 생산성이나 피로가 개선되는지는 검증하지 않습니다. 카드가 저장되지 않거나 최신이 아니면 대기함도 틀립니다.
