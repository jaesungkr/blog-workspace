# AI 작업과 판단 대기함 운영 규칙

## 범위와 역할

이 규칙은 도구의 보안 설정이 아니라 작업 중 지킬 약속입니다. 기존 프로젝트 지침, 파일 접근 권한, 사용자가 정한 작업 범위를 우선합니다. 이 파일을 만들었다고 권한이 늘어나거나 자동 실행이 설정되지 않습니다.

- 작업 대화와 검토 대화는 같은 실제 로컬 프로젝트 폴더의 `ai-work/`를 읽습니다. 같은 저장소 이름의 다른 복제본이나 worktree는 이 최소 구성의 범위 밖입니다.
- 작업 대화는 맡은 작업 카드 하나만 갱신합니다. 카드는 그 대화가 단독 작성합니다. 코드 수정은 카드에 기록된 허용 범위 안에서만 합니다.
- 검토 대화는 카드를 읽고 요청받을 때 `ai-work/inbox.md`만 다시 만듭니다. 카드·코드·권한을 바꾸거나 다른 작업 대화에 명령하지 않습니다.
- 사람은 카드의 근거를 읽고 판단한 뒤 결정과 재개 지시를 원래 작업 대화에 전달합니다. 카드와 대기함에 직접 답을 적는 것만으로 전달을 대신하지 않습니다.
- 같은 코드 파일을 두 작업에서 동시에 바꾸지 않습니다. 범위가 겹치면 먼저 한 작업을 멈추고 작성자를 정합니다. Markdown 운영 규칙은 파일 잠금이나 충돌 감지 기능이 아닙니다.

## 카드에 남길 내용

ID, 목표, 상태, 돌아갈 대화 이름, 허용 범위, 멈춘 지점, 검증 상태, 판단 질문, 선택지와 추천 이유, 근거 자료 위치, 다음 행동, 완료 조건, 마지막 갱신 시각을 적습니다. 실제 실행하지 않은 테스트나 없는 파일을 근거로 적지 않습니다. 결정이 필요해지면 대기 시작 시각, 마감(없으면 없음), 다른 작업을 막는지도 남깁니다.

## 상태

- `AI 작업 중`: 이미 허용된 범위 안에서 AI가 진행할 수 있습니다. 사용자의 답을 기다리는 목록에서 제외합니다.
- `내 판단 대기`: 사용자가 선택하거나 확인해야 다음 단계로 갈 수 있습니다. 필요한 질문을 저장한 뒤 해당 작업을 멈추고 카드 경로를 알립니다. 사람의 답 없이 같은 시도를 반복하지 않습니다.
- `외부 요인 대기`: 서비스 복구나 다른 산출물처럼 현재 사용자의 판단으로 풀 수 없는 일을 기다립니다. 판단 대기함에서 제외하고 카드에 막힌 원인과 재확인 조건을 남깁니다. 사용자 조치가 필요해지면 구체적 질문을 써서 `내 판단 대기`로 바꿉니다.
- `완료`: 완료 조건을 확인한 근거가 있습니다. 대기함에서 제외합니다. 미실행 검증을 완료로 표시하지 않습니다.

## 대기함 만들기

요청받은 시점에 모든 작업 카드를 다시 읽고 `내 판단 대기`만 모읍니다. 다른 작업을 막는 항목 먼저, 이어서 마감이 가까운 순서, 같은 조건이면 오래 기다린 순서로 정렬합니다. 마감 없는 항목은 마감 있는 항목 뒤에 둡니다. 마지막으로 ID 순서를 사용해 순서를 고정합니다. 이 순서는 이 예제의 시작 규칙이며 보편적인 최적 순서가 아닙니다.

대기함에는 마지막 갱신 시각과 각 항목의 ID·질문·카드/근거 위치·돌아갈 대화 이름만 짧게 씁니다. 카드 전체를 복제하지 않습니다. 판단에 필요한 상세 자료는 카드에서 읽습니다. 갱신 뒤 카드가 바뀔 수 있으므로 결정을 내리기 직전에 해당 카드의 상태와 갱신 시각을 다시 확인합니다.

## 한 건을 닫는 절차

1. 사용자가 대기함 첫 항목의 카드를 열고 맥락과 자료를 읽습니다.
2. 한 건을 결정하거나 필요한 추가 조사를 정합니다.
3. 결정과 재개 지시를 카드에 적힌 작업 대화에 전달합니다. 새 대화를 써야 한다면 기존 작성자가 더는 수정하지 않음을 확인하고, 새 대화에 이 규칙과 해당 카드를 먼저 읽으라고 명시합니다.
4. 작업 AI가 최신 카드를 읽고 같은 질문에 대한 결정인지 확인합니다. 더 필요한 확인이 없다면 결정·다음 행동·갱신 시각을 저장하고 `AI 작업 중`으로 바꾼 뒤 허용된 범위에서 재개합니다. 새 문제가 생겼다면 새 질문을 써서 다시 기다립니다.
5. 작업 AI의 저장 확인 뒤 검토 대화에 대기함 재생성을 요청합니다. 답한 질문이 빠지면 다음 항목으로 넘어갑니다.

이 최소 방식은 자동 갱신, 세션 간 공유 기억, 대기함 편집에 따른 자동 재개, 다른 대화로의 자동 메시지 전송을 제공하지 않습니다. 사람의 실제 전달과 파일 재읽기가 연결 단계입니다. 배포, 외부 전송, 권한 확대는 별도 승인이 필요한 작업으로 취급합니다. 카드와 로그에 비밀번호·API 키·고객 개인정보를 적지 않습니다.
