# 기획: AI 코딩 질문이 쌓일 때, ‘판단 대기함’부터 만드세요

## 요청과 중심 문장
- 사용자는 기록 권유나 아이디어 소개에 그치지 않고, 독자가 무엇을 어떻게 도입할지 명확히 제안하는 글을 요청했다. 게시를 중지했으므로 검토본만 전달한다.
- 여러 AI의 판단 요청을 한곳에 모아 한 건씩 결정하고 원래 작업으로 반환한다. 파일은 그 처리를 가능하게 하는 수단이다.
- 이전 제목 ‘AI에게 코딩을 맡겼는데, 왜 더 피곤할까?’는 원인 설명을 기대하게 했다. 새 제목은 질문 누적 상황과 첫 행동을 직접 이름 붙인다. 대체 후보는 ‘Claude Code·Codex 질문을 한곳에 모아 처리하는 법’, ‘AI는 일하게 두고, 답할 질문만 한 건씩’이었다.

## 독자와 권고
- 대상은 같은 실제 로컬 프로젝트를 읽고 쓸 수 있는 AI 코딩 대화 둘 이상을 사용하는 개발자다. 제품 설치와 가입은 이미 끝나 있다.
- 불편은 질문이 도착할 때마다 대화를 바꾸고 아직 내리지 않은 결정을 계속 기억하는 것이다.
- 권고는 기존 프로젝트에 ai-work 규칙, 작업 카드, 판단 대기함을 만들고 작업별 지시와 검토용 지시를 분리하는 것이다. 문서 작성과 질문 취합은 AI가 맡는다.
- 각 작업 대화는 동일한 폴더의 자기 카드만 쓴다. 대기함은 검토 대화 하나만 쓴다. 예상 변경 파일이 겹치는 코드 작업은 순서대로 진행한다.
- 사람은 목록 갱신, 결정 전달, 재개를 요청한다. 자동 감시, 세션 간 공유 기억, 무인 재개를 주장하지 않는다. 질문이 드물거나 작업이 하나뿐이면 기존 대화를 유지해도 된다.

## 독자의 질문과 절 역할
1. 무엇이 달라지나: 여러 알림에 반응하는 전과 로그인 결정·반환 후 검색을 보는 후를 비교한다. 원문의 큐, owner inbox, 한 건의 맥락을 닫는 설명과 기존 흐름도를 배치한다.
2. 무엇을 어디에 만드나: 같은 로컬 프로젝트와 검토 대화에서 첫 설정 지시를 실행한다. 실제 생성 경로와 빈 대기함을 확인한다.
3. AI에게 어떻게 일을 주나: 예상 변경 파일을 먼저 확인한 뒤 규칙과 작업 카드 경로를 지정한다. 질문을 저장하면 해당 작업을 멈추게 한다.
4. 어떤 질문만 보나: 로그인·검색 판단은 대기함에 넣고 이미 허용한 테스트 조사는 작업 중에 둔다. 목록 갱신 지시와 가상 질문 목록을 제공한다.
5. 답한 다음 어떻게 하나: 원래 대화로 결정 전달, 작업 AI의 카드 갱신과 재개, 목록 재갱신, 다음 질문 순으로 처리한다. 문서 편집만으로 대화가 재개되지 않음을 명시한다.
6. 언제 도입됐다고 보나: 방금 답한 질문이 해소되고 원래 작업이 재개됐는지 확인한다. 새 질문, 오래된 목록, 전달 누락은 각각 구별한다.

## 근거와 기여
- 원문 실제 구현은 Git, 스크립트, Claude artifact를 사용한다. 수동 갱신 시작안과 한국어 지시문, 파일 구성은 dev.log가 제안한다.
- Codex·Claude Code의 로컬 파일 접근과 권한 전제는 공식 문서로 확인한다. 실제 동시 CLI 사용이나 성능 개선을 검증했다고 쓰지 않는다.
- artifacts/adoption-demo의 가상 카드 세 개와 결정 반환 전후 스냅샷으로 상태별 목록 포함·제외를 검사했다. 18개 표준 라이브러리 검사와 실제 로그를 보존한다. 실제 메시지 전달, 로그인 구현, 사용자의 경험으로 표현하지 않는다.
- 재개 연구와 Kanban 일반론은 도입 절차를 직접 해결하지 않아 본문에서 제외하고 과거 기록에 보존한다.

## 매체와 화면 판단
- 기존 대표 이미지는 여러 AI 작업에서 한 건을 선택하는 의미가 동일하므로 재사용한다.
- 기존 diagram-design 흐름도는 한 건을 판단해 반환하는 관계를 설명한다. 전후 비교 직후로 이동하며 픽셀과 라벨은 바꾸지 않는다.
- 화면 진입은 이미 쓰는 프로젝트 대화이고 특정 메뉴를 찾을 필요가 없다. 선택할 경로와 상태는 복사 요청에 명시하고, 확인할 결과는 빈 대기함과 질문 목록으로 본문에 제공한다. 가짜 UI나 반복적인 파일 탐색기 화면은 추가하지 않는다.
- 모바일에서는 긴 지시문의 문단 간격, 인용 상자, 파일 경로 줄바꿈, 목록과 흐름도를 360/1280px light/dark에서 확인한다.

## 유지할 한계
- 원문은 개인 실험이며 사례는 가상이다. 미확인 테스트, 실제 자료 위치, 배포 제한, 비밀 정보 제외, 권한·오류의 별도 막힘, 긴급 운영 예외를 보존한다.
- 새 관리 서비스 설치, 사용자의 실제 작업 방식 변경, 자동 게시·배포, 생산성·건강 효과, 최적 동시 작업 수는 범위에 포함하지 않는다.
