<h2 id="fable-51에서-달라진-점" data-ke-size="size26">Fable 5.1에서 달라진 점</h2>
<p data-ke-size="size16">Fable은 여러 시간 동안 도구를 사용하며 코드를 고치거나, 자료 조사부터 문서&middot;스프레드시트 완성까지 이어 가는 상위 모델입니다. Opus 5.5도 문서&middot;코드&middot;도구 작업을 맡길 수 있는 범용 상위 모델입니다. 여기서 에이전트 작업은 AI가 도구를 실행하고 결과를 확인하며 다음 행동을 이어 가는 방식을 말합니다. <a style="color: #1a73e8; text-decoration: none;" href="https://platform.claude.com/docs/en/models/fable-5-2/overview" target="_blank" rel="noopener">Fable의 용도</a></p>
<p data-ke-size="size16">5.1에서 5.2로 바뀌며 개선된 부분은 <b>복잡한 과제를 해결하는 성능과 처리 효율</b>입니다. 추론 강도는 답을 내기 전에 얼마나 많은 계산을 할지 정하는 옵션이며, medium은 중간 강도입니다. 공식 발표에 따르면 기본 출력 생성 속도는 최대 30% 빨라졌고, 같은 medium 설정에서 어려운 작업을 더 적은 토큰으로 처리했습니다. 토큰은 글과 자료를 잘게 나눈 처리 단위입니다.</p>
<p data-ke-size="size16">텍스트&middot;이미지를 받아 텍스트를 출력하는 방식, 한 번에 다루는 문맥 100만 토큰, 최대 출력 12만 8천 토큰은 그대로입니다. 지식 기준일도 두 모델 모두 2026년 6월입니다. 문맥 크기는 한 요청에 함께 참고할 수 있는 자료의 양을 뜻합니다. <a style="color: #1a73e8; text-decoration: none;" href="https://platform.claude.com/docs/en/models/fable-5-1/overview" target="_blank" rel="noopener">5.1&middot;5.2 사양 비교</a></p>
<p data-ke-size="size16">함께 발표된 <b>Mythos 5.2</b>는 Fable과 같은 기반 모델을 사용합니다. Fable에는 사이버보안과 생물학 분야의 악용을 막는 안전장치가 적용돼 있고, Mythos는 검증 프로그램을 통과한 조직에 제공됩니다. 공식 성능표의 취약점 탐지&middot;단백질 설계 행은 Mythos 결과이므로, 아래에서는 Fable로 공개된 평가를 비교했습니다. <a style="color: #1a73e8; text-decoration: none;" href="https://platform.claude.com/docs/en/models/fable-5-2/overview" target="_blank" rel="noopener">모델과 접근 조건</a></p>
</section>

<h2 id="fable-51-api에서-옮길-때-확인할-것" data-ke-size="size26">Fable 5.1 API에서 옮길 때 확인할 것</h2>
<p data-ke-size="size16">Claude 앱이나 Claude Code에서 모델을 선택하는 사용자와, 직접 API 요청을 만드는 개발자는 이전 과정이 다릅니다. 5.2에서는 모델이 이미 만든 추론 내용 앞의 system&middot;tools&middot;과거 메시지를 바꿨는지 검사하는 규칙이 모든 계정에 적용됩니다. 예전 메시지를 편집한 뒤 그 추론 내용을 다시 보내면 기본 동작에서 400 오류가 날 수 있습니다. 5.1에서 오래된 계정으로 동작하던 코드도 여기에 걸릴 수 있습니다. <a style="color: #1a73e8; text-decoration: none;" href="https://platform.claude.com/docs/en/models/fable-5-2/whats-new-fable-5-2" target="_blank" rel="noopener">5.1에서 바뀐 API 검사</a></p>
<p data-ke-size="size16">직접 연동한 코드는 대화 앞부분을 수정하지 않고 새 메시지만 덧붙이는지 확인해야 합니다. 반면 Claude 앱&middot;Claude Code&middot;Claude Agent SDK가 요청을 만들어 주는 경우에는 이 검사 변경에 따로 대응할 필요가 없습니다. 또한 5.2에서 Opus 5.5나 Fable 5.1로 대화 중 전환하면 5.2의 내부 추론 내용은 이어받지 못합니다. 대화 기록을 가공하거나 모델을 번갈아 쓰는 서비스라면 <a style="color: #1a73e8; text-decoration: none;" href="https://platform.claude.com/docs/en/models/fable-5-2/migration-guide" target="_blank" rel="noopener">공식 이전 가이드</a>를 먼저 확인하는 편이 좋습니다.</p>
</section>

<h2 id="fable-52와-opus-55의-쓰임새" data-ke-size="size26">Fable 5.2와 Opus 5.5의 쓰임새</h2>
<p data-ke-size="size16"><b>기존 Fable 5.1로 긴 작업을 맡기고 있었다면 5.2로 옮길 이유가 분명해졌습니다.</b> 문맥 크기와 입출력 형식은 유지하면서 공식 코딩 점수는 올랐고 단가는 내려갔습니다. 독립 평가에서도 5.2 high가 5.1 max보다 높은 지수를 더 적은 비용과 시간으로 얻었습니다. 직접 만든 API 연동은 앞서 설명한 호환성 조건도 확인해야 합니다.</p>
<p data-ke-size="size16">Opus 5.5를 쓰고 있다면 작업의 난도가 선택을 가릅니다. 짧은 문서 정리나 평소 코드 수정은 기본 단가와 낮은 추론 설정의 비용이 작은 Opus에서 시작할 만합니다. 여러 파일을 바꾸는 대규모 수정, 긴 조사와 계산을 거쳐 결과물을 완성하는 일처럼 Opus의 추론 강도를 높여도 해결이 어려운 과제에는 Fable 5.2가 더 설득력 있습니다. 공개된 코딩&middot;에이전트 평가가 이 선택을 뒷받침합니다.</p>
