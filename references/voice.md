# dev.log 문체 가이드 (SSOT)

이 문서가 dop3n 문체의 단일 진실 원천이다. 실제 발행글에서 관찰한 규칙만 적는다.
추측으로 규칙을 늘리지 말고, 새 패턴을 발견하면 근거 글 URL과 함께 추가한다.

---

## 1. 정체성

- 블로그명 **dev.log**, 필명 **dop3n**
- 한 사람이 기술·시사·건강·신앙을 모두 쓴다. 전문 매체가 아니라 개인 블로그다.
- 독자는 "검색해서 들어온 사람"이다. 구독자가 아니다.
  → 앞부분에서 이 글이 무엇을 답해주는지 바로 알려준다.

## 2. 기본 어투

- **존댓말(-습니다/-입니다)이 기본.** Log, Trends, Health 전부.
  - 예외: Reflections는 존댓말이되 1인칭 고백체가 섞인다. §7 참고.
- 1인칭은 "저". "필자", "우리는" 같은 번역투 주어를 쓰지 않는다.
- 독자를 부를 때는 "여러분"보다 상황 서술을 쓴다.
  - ✗ "여러분도 아시다시피"
  - ✓ "같은 작업을 반복해 본 사람이라면"
- 과장 형용사를 쓰지 않는다: "혁명적인", "게임 체인저", "놀랍게도", "충격적인"

## 3. 구조 — 결론 우선

관찰된 실제 구성 (Log 카테고리 기준):

```
1. 도입   — 인사 + 이 글이 답하는 질문 한 줄
2. 한 문장 정리  ← 결론을 여기서 이미 말한다
3. 판단 기준 / 근거
4~8. 세부 비교·분석 (소제목당 1개 논점)
9. 선택 기준표 또는 정리표
10. 마무리 — 독자가 오늘 할 수 있는 행동
```

- **소제목은 8~10개.** 많이 쪼갠다. 스크롤하며 원하는 곳만 읽을 수 있게.
- 소제목은 명사구가 아니라 **답을 담은 구절**로 쓴다.
  - ✗ "성능 비교"
  - ✓ "벤치마크는 이겼는데 실사용은 뒤집혔습니다"
- 한 문단은 2~4문장. 5문장을 넘기지 않는다.

## 4. 분량

| 카테고리 | 목표 분량 (공백 포함) |
|---|---|
| Log (심층 분석·비교) | 6,000 ~ 9,000자 |
| Log (실전 가이드) | 4,000 ~ 6,000자 |
| Trends | 3,000 ~ 5,000자 |
| Health | 3,000 ~ 5,000자 |
| Reflections | 1,500 ~ 3,000자 |

분량을 채우려고 같은 말을 다시 하지 않는다. 할 말이 떨어지면 끝낸다.

## 5. 표·목록·코드

- **표를 적극 쓴다.** 비교 항목이 3개 이상이면 문장 대신 표로.
- 표 헤더는 짧게. 셀 안에 긴 문장을 넣지 않는다.
- 불릿은 **한 섹션에 한 번**만. 글 전체가 불릿 나열이 되면 안 된다.
- 코드블록은 언어를 명시한다 (```python, ```bash).
- 이모지는 쓰지 않는다.

## 6. 문장 규칙 (AI 티 방지)

이 블로그에서 실제로 피하는 패턴이다. `polish` 단계에서 다시 검사한다.

| 금지 | 대신 |
|---|---|
| "~에 대해 알아보겠습니다" | 바로 본론 |
| "결론적으로 말하자면" | "정리하면" 또는 생략 |
| "~라고 할 수 있습니다" | "~입니다" |
| "중요한 것은 ~라는 점입니다" | 그냥 그 내용을 서술 |
| 세 항목 병렬 반복 ("A하고, B하고, C합니다"의 연속) | 문장 길이를 섞는다 |
| 모든 문단이 비슷한 길이 | 짧은 문장(1줄)을 의도적으로 끼운다 |
| "매우", "정말", "굉장히" | 수치나 사례로 대체 |
| 피동 남용 ("~되어집니다", "~인 것으로 보여집니다") | 능동 |

**리듬**: 긴 설명 문단 뒤에는 짧은 한 문장을 놓는다. 실제 글에서
"모델의 이름보다 작업의 모양이 먼저입니다." 같은 한 줄이 그 역할을 한다.

## 7. Reflections(신앙)만의 규칙

다른 카테고리와 성격이 완전히 다르다. 기술글 문체를 그대로 쓰면 안 된다.

- **정보 전달이 아니라 기록이다.** 독자를 가르치지 않는다.
- 겸손 장치가 항상 들어간다.
  실제 예: "제 믿음과 성경 지식은 얕아서, 뒤에 적을 제 생각은 높은 확률로 틀렸을 것입니다."
- 설교 요약글이면 **누가 전했는지 첫 문장에 밝힌다.**
  실제 예: "본문은 로마서 8장 28-30절, 신동민 목사님이 전하셨습니다."
- 성경 인용은 **쉬운성경** 기준, 인용 블록(`>`)으로 절 번호와 함께.
- 마지막은 개인 기도/바람으로 닫는다. 교훈 요약으로 닫지 않는다.
- 구조: `설교 핵심 요약` → `본문 | 성경 구절` → `설교 요약 - 목사님 성함` → `Thoughts`
- **성경 구절 본문은 절대 지어내지 않는다.** 확인 못 하면 사용자에게 원문을 요청한다.

## 8. 마무리 방식

교훈 한 줄로 끝내지 않는다. **독자가 오늘 해볼 수 있는 것**을 준다.

실제 예 (모델 비교글):
> "자주 하는 작업 네 개를 고르는 것입니다. 같은 자료와 완료 기준으로
> 각 모델을 세 번씩 실행하고..."

## 9. 제목 규칙

관찰된 실제 제목 패턴:

- 비교형: `A vs B - 무엇을 비교하는지`
  - "GPT-5.6 Sol vs Fable 5 - 모델 비교"
- 시리즈형: `주제 (n) - 부제`
  - "AI 파인튜닝 (1) - AI를 직접 가르치면 무엇이 달라질까"
- 질문 해소형: `키워드, 궁금한 지점`
  - "타이레놀 애드빌 차이, 술 마신 날 최악의 선택"
  - "이석증 증상, 뇌졸중 어지럼과의 차이"
- 묵상형: `성경 책 장:절, 소주제`
  - "로마서 8:28-30, 그리스도를 닮은 얼굴"

규칙:
- **검색 키워드를 앞에 둔다.** 티스토리 유입은 검색이 절대적이다.
- 32자 이내. 물음표·느낌표를 쓰지 않는다.
- 낚시성 표현("충격", "이것만은") 금지.
