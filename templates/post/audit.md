## 구조와 독자

- [ ] 제목 앞부분이 실제 검색 의도에서 시작합니다.
- [ ] 제목과 모든 소제목이 `~다`로 끝나지 않습니다.
- [ ] 표준 인사 뒤 2-4문장 안에 익숙한 문제와 글의 필요성이 나옵니다.
- [ ] 첫 5-6문장 안에 기억할 결론 또는 질문이 있습니다.
- [ ] 낯선 용어와 방법을 결과표보다 먼저 설명합니다.
- [ ] 중앙 방법의 `입력 -> 처리/표현 -> 비교/판단 -> 출력` 사슬이 보입니다.
- [ ] 시나리오 결과, 전체 벤치마크, 실용 추천의 범위를 구분했습니다.
- [ ] 선택이 목적인 독자에게 기본 선택과 예외를 직접 제시합니다.
- [ ] 비개발자가 코드 없이도 핵심 결론을 이해할 수 있습니다.

## 근거와 독창성

- [ ] 모든 수치와 강한 주장에 출처·측정 기준·한계가 붙습니다.
- [ ] 벤더 주장, 독립 검증, 추정, 구조 예시를 구분했습니다.
- [ ] 테스트 입력·환경·판정 규칙·원시 결과·실패 사례를 보존했습니다.
- [ ] Codex가 실행한 작업을 사용자의 개인 경험으로 쓰지 않았습니다.
- [ ] 미확인 사실과 해결되지 않은 TODO가 본문에 없습니다.
- [ ] 반론과 일반화할 수 없는 범위가 보입니다.
- [ ] 출처 요약을 넘어선 first-party contribution이 있습니다.
- [ ] 다른 블로그 이름으로 바꾸면 약해지는 dev.log만의 이유가 있습니다.

## 문장과 형식

- [ ] 인사부터 마무리까지 존대어가 일관됩니다.
- [ ] 번역투, 이중 피동, 명사화, 상투적인 요약 표현을 걷어냈습니다.
- [ ] 과장, 감정 부사, 기계적인 병렬, 불필요한 1인칭이 없습니다.
- [ ] 문단은 주제에 따라 자연스럽게 나뉘고 문장 리듬이 기계적이지 않습니다.
- [ ] 굵은 강조가 문단마다 반복되지 않습니다.
- [ ] em dash(`—`), 분리된 참고문헌 부록, 관성적인 면책 문구가 없습니다.
- [ ] 카테고리별 마무리 기준을 따릅니다.
